# 데이터 소유권과 테이블 계약

| 데이터 | 편집 원본 | 런타임 사용 |
|---|---|---|
| 적·패턴·수치·가격·보상 | Excel 등 기획자가 정한 단일 원본 | 검증된 SO/JSON |
| 문자열 | 안정적인 키, 한국어·지원 언어, format 인자 계약 | 키 조회 테이블 |
| Prefab·Sprite·AudioClip 참조 | Unity의 수동 Catalog SO | 의미 ID→직렬화 Unity Object |
| 계층·위치·색·연출 곡선 | Unity 씬·프리팹·에셋 | 저장된 자산의 인스턴스 |
| 전투 HP·쿨타임·런 내 선택 | 세션/전투 상태 | 해당 런의 메모리 |
| 해금·설정·진행 | versioned save | 로딩·마이그레이션 결과 |
| 구매 권리 | 검증된 플랫폼 거래/서버 기록 | 검증 후 entitlement |

원본 프로젝트들이 사용한 4행 메타 형식은 재사용 가능한 선택지다.

```text
1행: EnemyId     Hp       TelegraphMs    PortraitId
2행: string      int      int            string
3행: Client      Client   Client         Client
4행: 고유 ID     HP, >0   예고 시간 ms   수동 카탈로그 ID
5행: gate_guard  120      700            guard_01
```

실제 importer가 처리하는 타입·추출 메타만 사용한다. 원본 프로젝트의 `ExportType`이나 Client/Server 필터는 프로젝트마다 지원 범위가 다르다. 메타행을 작성했다는 이유로 기능이 구현됐다고 간주하지 않는다.

- 실행 테이블에 수식/병합 셀을 넣지 않는 것을 기본으로 삼는다. 계산 보고서는 별도로 두고 확정값을 내보낸다.
- ID·타입·단위·빈값 의미·중복·외래키·지원 언어 placeholder를 검증한다. 삭제된 ID와 저장되는 enum 숫자를 재사용하지 않는다.
- 같은 입력→같은 출력 순서와 인코딩을 유지한다. 임의 생성 시각으로 diff를 오염시키지 않는다.
- 파싱과 검증을 끝내기 전 기존 결과를 쓰지 않는다. 다중 파일 교체가 실패하면 복구 또는 불완전 상태 표시를 제공한다. 전원 장애까지 원자성을 보장한다고 주장하려면 그 수준의 구현과 검증이 필요하다.
- 생성물과 수동 Catalog는 별도 폴더/소유권으로 보존한다. manifest가 둘을 연결한다.
- 예산이 작은 게임은 단일 workbook으로 시작해도 된다. 반복 편집과 담당 경계 때문에 필요해질 때 책임별 workbook으로 분리한다.
