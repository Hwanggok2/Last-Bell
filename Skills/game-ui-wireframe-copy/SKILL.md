# 게임 UI 배치와 짧은 문구

플레이어가 지금 봐야 할 것과 눌러야 할 것을 먼저 정한다. 기획서의 설명을 게임 화면에 그대로 붙이지 않는다.

## 와이어프레임부터 배치까지

1. 해당 화면의 주 행동, 필요한 상태, 진입·이탈 경로를 확인한다. 기존 화면이면 실제 프리팹/렌더부터 보고 문제를 특정한다.
2. 기준 해상도, 화면 방향, 안전 영역, 입력 방법을 명시한다. 좌표는 기준 해상도와 anchor 기준을 함께 남긴다.
3. 장식 전 흑백 와이어프레임을 만든다. 전투 영역·상태 HUD·엄지 입력 영역·모달·스크롤 영역을 분리한다. 핵심 공격 예고와 조작 버튼이 손가락에 가려지지 않게 한다.
4. 주요 화면뿐 아니라 잠금·실패·일시정지·긴 문구·광고 불가·구매 대기 등 실제 필요한 상태를 표시한다.
5. 와이어프레임을 시각 검토한 뒤 색·도트 자산·타이포를 적용한다. 별도 검토 요구가 없으면 작업자가 직접 검토한다. 사용자가 담당 세션 검토를 요청하면 그 담당자의 피드백과 반영 사항을 기록한다. 사소한 수정마다 새 승인 절차를 만들지 않는다.
6. 확정한 구조를 저장 프리팹으로 구현한다. 레이아웃 조정은 지정한 소유자 한 곳에서 수행하고, 여러 스크립트가 매 프레임 RectTransform을 덮어쓰지 않게 한다.
7. 실제 화면을 기준 시안과 비교한다. 실제 대상의 가장 짧은 화면·가장 좁은 화면·Safe Area·한국어 및 지원 언어의 긴 문구를 확인한다.

와이어프레임에는 **프레임 크기, 각 영역의 bounds/anchor, 버튼 hit area, 정보 우선순위, 상태 변화**가 있어야 한다. 단순한 분위기 이미지를 배치 명세로 대신하지 않는다.

## 공간과 시각 규칙

- 주 행동은 화면에서 즉시 구분되게 한다. 보조 기능이 전투·진입·재도전을 밀어내지 않게 한다.
- 작은 아이콘의 보이는 크기와 터치 영역은 다르게 잡을 수 있다. 모바일에서는 약 48dp 이상을 출발점으로 삼고 실제 밀도·기기·접근성 설정에서 확인한다. 두 hit area가 겹치지 않아야 한다.
- 도트 월드는 정수 배율/Point filtering을 고려하되, UI 문자는 가독성을 우선한다. 도트 분위기 때문에 작은 한글을 흐리거나 뭉개지게 만들지 않는다.
- 예고·성공·실패를 색만으로 전달하지 않는다. 방향, 모양, 동작, 짧은 음향/진동을 함께 고려한다.
- 작은 화면에서는 중요 요소를 유지하고 보조 영역을 접거나 재배치한다. 모든 요소를 일괄 축소하는 것으로 해결하지 않는다.
- 타이머·HP·구매 상태는 실제 소유 상태를 표시한다. 예고용 애니메이션이나 UI 자체 타이머가 게임 판정을 바꾸면 안 된다.
- 소리 끄기·진동 끄기·화면 흔들림 감소에서도 핵심 패턴을 이해할 수 있어야 한다.

## 텍스트 편집 기준

각 문구에 다음 중 하나의 역할을 붙인다.

| 남길 역할 | 예 |
|---|---|
| 행동 | 시작, 피하기, 공격, 다시 도전 |
| 즉시 판단에 필요한 상태 | 3/10, 연결 중, 구매 확인 중 |
| 실패 원인·복구 | 저장 실패 · 다시 시도 |
| 짧은 서사 | “마지막 종이 울리기 전에.” |
| 구매 조건·필수 고지 | 가격, 제공 내용, 광고 시청 조건, 복원 |
| 접근성 정보 | 아이콘의 읽기 라벨 |

어느 역할도 없으면 삭제 후보로 본다. 게임 화면에서 “이 화면에서는…”, “플레이어에게 몰입감을 제공합니다”, “전략적인 선택을 통해…” 같은 기획 해설이나 개발 설명을 지운다. 문구를 줄여 가격·확률·보상 조건·실패 복구까지 감추지 않는다.

- 버튼은 행동 동사 중심으로 쓴다. 같은 화면에서 제목·본문·버튼이 같은 뜻을 세 번 반복하지 않게 한다.
- 튜토리얼은 필요한 순간 한 행동씩 보여주고 플레이로 확인한다. 긴 설명 팝업으로 모든 규칙을 선행 학습시키지 않는다.
- 서사는 한 화면에서 읽을 수 있는 짧은 장면으로 나누고, 최초 표시/다시 보기/건너뛰기 동작을 정의한다.
- 수치가 판단에 중요하면 모호한 수사 대신 값과 단위를 쓴다. “더 강력한 공격”보다 “반격 피해 +20%”가 필요할 수 있다.
- 개발자 진단·네트워크 상세·밸런스 가정·AI 제작 설명은 개발 문서/진단 화면에 둔다.
- 문구 ID와 실제 문자열, 표시 조건, 최대 공간을 묶어 관리한다. 강제 줄바꿈과 말줄임은 실제 렌더로 확인한다.

## 전달과 완료 기준

화면 그림 + 배치 명세 + 최소 문구 목록 + 상태별 동작을 남긴다. 설명용 번호와 주석은 시안 바깥에 둔다. 게임 화면 안에는 실제 출시할 문구만 보이게 한다.

완료 여부는 핵심 정보 가림, 겹치는 입력 영역, 글자 잘림, 읽히지 않는 한글, 중복 안내, 실패 시 막힌 동선으로 판단한다. 화면 이미지 검토는 문서 검토이며 기기 터치 검증을 했다는 뜻은 아니다.
