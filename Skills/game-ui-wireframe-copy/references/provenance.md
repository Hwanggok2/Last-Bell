# UI·문구 규칙의 근거 — 2026-10-20

원본 자료가 없더라도 스킬 본문은 독립적으로 사용할 수 있다.

| 근거 | 관찰 | 적용 |
|---|---|---|
| 현재 사용자 요청 | 와이어프레임으로 초안을 만들고 이에 따라 배치. 필요 없는 AI 설명식 텍스트를 게임에 첨부하지 않음 | 이 스킬의 직접 요구사항 |
| StageGame `Docs/Design/lobby-redesign-20261018/design-spec.md` | 보이는 배경을 제거한 아이콘도 110×110 입력 영역 유지. 목록/상단/하단 높이 함께 계산. 실제 프리팹 저장 | 시각 크기와 hit area 분리, 영역 간 제약 명시 |
| StageGame `Docs/Design/TYPOGRAPHY.md` | 도트 그래픽과 별개로 한글 가독성 높은 Pretendard 적용, 문자 지원·한국어/영어·작은 화면 확인 | 스타일과 가독성 분리. 특정 폰트는 강제하지 않음 |
| StageGame `클라이언트` 세션 | 반복되거나 보이지 않는 설명 삭제, 첫 실행 규칙과 도움말에서 다시 열기 | 필요한 시점의 짧은 안내, 재열기 경로 |
| StageGame `총괄 · 일정 및 출시` 세션 | 다른 씬과 일관되게 상세 패널을 중앙 배치하라는 사용자 수정 | 기준선·정렬 일관성과 실제 렌더 비교 |
| SimpleGame `Planning/UIExperience_20260920.md` | HTML 시안 검토 단계와 Unity 미적용 상태를 분리. 정보 계층·실제 상태 표시·캐릭터 프리뷰 수명 정의 | 시안→구현 구분, UI가 게임 상태를 추정하지 않기 |

신규 권고로 추가한 사항: 모바일 hit area 약 48dp를 출발점으로 사용, 색 외의 패턴 신호, 행동/상태/서사/조건/접근성 기준의 문구 분류. 이 수치와 분류가 원본 게임의 모든 화면에 이미 적용됐다는 의미는 아니다.

과거의 특정 버튼 크기·2열 목록·세로/가로 병행 지원·글꼴과 승인 순서는 새 게임에 자동 적용하지 않는다.
