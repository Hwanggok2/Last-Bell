# Dragon v6 / 0.9.5 스킬 파티클 인계

2026-10-25. 소스 구현 완료. 이 담당은 Unity 임포트·프리팹 적용·컴파일·실행·빌드·시각 QA를 수행하지 않았다. 총괄의 통합 적용과 최종 QA가 남아 있다.

## 변경 범위

- `Client/Assets/Game/Runtime/Presentation/SkillPixelEffects.cs`: 기존 실제 ParticleSystem 4개와 투명 Point RenderTexture 합성을 유지하고 독립 스킬 이벤트 및 5종 동료 전용 스킬을 표시한다.
- `Client/Assets/Game/Editor/DragonV6SkillEffectsMigration.cs`: 기존 v5 전용 프리팹의 접촉 입자 용량과 정렬 설정만 부분 이전한다.
- `CompanionBattleView`, `BattlePresentation`, `MvpPresenter`, 피해·기절·회복 수치, 공격 모션 및 오디오 소스는 이 담당이 수정하지 않았다.
- 규칙 원본은 `dragon-v095-client-contract.md` 및 Client Core다. 연출 코드에서 확률·공격력·회복량·쿨다운을 재계산하지 않는다.

## 이벤트 계약

| 확정 이벤트 | 표시 | 금지한 중복 |
|---|---|---|
| `PlayerSkillStarted` | 플레이어 몸 주변 8개 준비 입자, 180ms | `ActorMotion` 변경, 일반 공격 예약/회피 취소 없음 |
| `PlayerSkillContact` + 실제 `DamageMilli > 0` | 해당 플레이어 전용 접촉 이펙트 | `EnemyDamaged`에서 같은 스킬을 또 재생하지 않음 |
| `CompanionAttackStarted` | 일반 원거리 투사체 또는 전용 준비/투사체. `SkillId`가 비었는지로 구분 | 추가 자동 공격 타이머/확률 추첨 없음 |
| `CompanionDamaged` + 실제 피해 | 일반 접촉 십자 또는 5종 전용 접촉 | 쌍화살도 실제 피해는 기존 이벤트 1회 |
| `PlayerRecovered` + 실제 `RecoveryMilli > 0` | 총괄이 기존 `PlaySupportWorld(Recovery, ...)` 호출 | 모모 파티클에서 자체 회복/추가 회복 표시 호출 없음 |
| `SkillShieldAbsorbed` | 실제 흡수 파편 | 보호막 수치/시간 변경 없음 |

시작→접촉 시간은 Core가 플레이어 200ms, 동료 180ms를 소유한다. 동료 투사체 비행 길이는 카탈로그의 `companionWindupMs`를 읽는다. 시각 효과의 수명만 표시 담당이 갖고, 실제 접촉을 예약하지 않는다. 저장된 진행 중 스킬을 복원할 때 이미 지난 준비 효과는 재생하지 않고 이후 실제 접촉 이벤트만 표시한다.

## 최종 시각 형태

| 대상 | 접촉 시 형태 | 색 / 수명 |
|---|---|---|
| 루카 | 플레이어의 원래 전투 자리에서 적까지 긴 이중 사선. 전달받은 0~5 사선 방향을 그대로 사용 | 금색·크림·황토, 160~280ms |
| 다렌 | 적 몸 중심 충격 고리와 십자. 실제 활성 보호막은 플레이어를 따라 기존 고리 유지 | 청색·크림·남색, 접촉 240~280ms / 보호막은 실제 남은 시간 |
| 미엘 | 상단 HUD 아래 상공부터 적 몸까지 6번 꺾이는 굵은 계단형 벼락 + 접촉 파편 | 보라·짙은 보라·크림, 본줄기 200ms / 잔여 300ms |
| 토리 | 준비 중 두 화살, 실제 접촉에서 두 줄이 모이는 쌍쏘기 | 금색·크림·황토, 230~280ms |
| 바룬 | 내려찍는 수직 줄기 + 지면 양쪽 충격 + 위로 솟는 조각 | 흙색·갈색·크림, 180~300ms |
| 도토 | 망치의 수직 충격 + 주황색 불꽃 조각이 높이 솟는 지면 충격 | 주황·금색·크림, 180~300ms |
| 리나 | 미엘보다 짧은 5굽이 하늘 번개 줄기 | 청색·남색·크림, 200~300ms |
| 모모 | 큰 씨앗 투사체 후 원형 씨앗 폭발, 회복은 실제 회복 이벤트에서 별도 표시 | 초록·살구·크림, 240~320ms |

일반 동료 공격은 원거리 4~5점 투사체와 접촉 십자 6점+파편 8점으로 강화했다. 주 투사체/벼락 줄기는 기본 출력 설정에서 정수 2~3texel, 물리 화면 4~6px 블록이다. 전용 접촉 중심은 짧게 더 큰 블록을 사용한다. 블룸·부드러운 원·전체 화면 번쩍임은 없다.

벼락은 적의 실제 몸 좌표에서 끝나며 위쪽 116 UI 단위 HUD 영역을 비운다. 위쪽 공간이 48 단위보다 작으면 접촉만 표시한다. 지면 충격은 적의 실제 발 좌표를 사용한다. 조작 버튼으로 이어지는 선이나 전체 전투 면적을 덮는 면은 만들지 않는다.

## 실제 기절 / 보호막

- 모든 캐릭터의 실제 `IsEnemyStunned` 기간에만 크림 중심·금색 가지·짙은 테두리의 별 3개를 적 얼굴 주변에 표시한다. 별마다 7개, 합계 **21/24입자**다.
- 이전의 작은 1~2texel 민트 점 대신 최대 7texel 테두리를 사용한다. 궤도는 Core `ClockMs`를 읽어 일시정지 때 멈춘다. HUD 공간 확보를 위해 중심 높이를 제한한다.
- 기절 종료·적 사망 때 즉시 제거한다. `IsStaggerImmune`만 있는 구간에는 별이 없다. 미엘의 실제 누적/ready 표식은 기존대로 별도 표시한다. 총괄의 기존 `View.StunStars` 중복 숨김을 유지한다.
- 보호막 고리는 실제 `SkillShieldMilli`와 `SkillShieldRemainingMs`를 읽으며, 스킬 이펙트에서 가짜 지속 시간이나 감속 디버프를 만들지 않는다.

## 저장 에셋 부분 이전

통합 Apply에서 기존 화면·아트 조립 후 다음을 호출하고, 총괄이 전체 씬을 저장한다.

```csharp
DragonV6SkillEffectsMigration.Configure(presenter);
DragonV6SkillEffectsMigration.Validate(presenter);
```

기존 `Assets/Game/Art/Effects/Dragon-v5/SkillPixelEffects.prefab` GUID·4개 PS 계층·재질·Point 텍스처·RawImage·카메라를 보존한다. 새 프리팹을 통째로 재작성하지 않는다. 실제 변경은 다음 두 가지다.

1. `AttackParticles.main.maxParticles`: 96 → 256. 플레이어 독립 스킬과 3동료 접촉이 겹칠 때의 예산.
2. 4개 `ParticleSystemRenderer.sortMode`: `Distance`. 짙은 테두리를 뒤쪽, 크림 핵심을 앞쪽 깊이에 두어 배열 정리 후에도 강조점이 가려지지 않게 한다.

전용 프리팹만 `LoadPrefabContents`로 열어 필요한 필드가 바뀐 경우 저장한다. 씬 참조는 기존 v5 Configure로 연결하고 장면 인스턴스의 해당 필드만 같은 값으로 맞춘다. 씬 저장·전체 AssetDatabase 저장·빌드는 호출하지 않는다. 실행 중이거나 필수 참조가 없으면 명확히 오류를 낸다.

## 예산과 정지

- 고정 최대: 접촉 256 + 보호막 32 + 기절/누적 24 + 서비스/회복 64 = **376입자**, ParticleSystem은 **4개**.
- pending 표시 이벤트 배열 16, 투사체 배열 6, 플레이어/적 1쌍에만 연결된다. 새 GameObject를 전투 중 만들지 않는다.
- 새 효과를 넣기 전에 만료된 칸을 회수한다. 배열 한도를 넘으면 표시 입자를 더 넣지 않으며 게임 판정에는 영향이 없다.
- 가장 큰 단일 접촉은 미엘의 상한 90입자. 미엘+리나+토리+도토의 한 번 동시 접촉 상한은 246입자이며, 준비 효과는 해당 접촉 전에 끝난다. 실제 플레이의 빈도·프레임 시간은 아직 측정하지 않았다.
- 기존 전투 시계 정지, UI 시간 분리, 일시정지, 단계 준비 초기화, 사망 Clear, RT 해상도 변경 시 재생성 및 OnDisable 해제 계약을 유지한다. 확정 막타의 표시 잔여 시간만 최대 340ms다.

## 총괄 최종 확인 항목

1. 640×360 및 1280×720에서 미엘 벼락·루카 이중 사선·다렌 충격이 구별되고, 공격 중 스킬을 눌러도 기존 공격 동작이 끊기지 않는가.
2. 3동료와 플레이어 스킬 동시 접촉에서 최대치/PS 개수 초과나 도형 소실이 없는가. 실제 피해 숫자와 흰 피격 플래시는 Core contact당 한 번인가.
3. 토리 쌍쏘기는 두 화살·피해 한 번, 리나 청색 번개와 미엘 보라 벼락 구분, 모모는 실제 회복량이 있을 때만 회복 입자인가.
4. 실제 기절/면역만 있는 상태/적 사망/일시정지에서 큰 별이 올바르게 켜지고 꺼지는가. 보스 상단 HP와 공격 예고, 조작 UI를 가리지 않는가.
5. 원래 RT 투명 알파·Point 필터·정수 격자·비차단 RawImage와 기존 저장 GUID가 유지되는가.

정적 검토로 신규 이벤트/필드가 현재 Core 소스에 존재함을 확인했다. Unity 컴파일 통과나 실제 렌더 품질을 확인했다고 주장하지 않는다.
