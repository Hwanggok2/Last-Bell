## 총괄에 전달할 실행 도구 (아직 실행하지 않음)

- `execute_menu_item(menu_path=...)`: 실제 등록 확인한 메뉴는 `Last Bell/Presentation/Apply Approved MVP`, `Last Bell/Presentation/Validate Saved MVP`. 저장/마이그레이션은 총괄의 다음 실행 단계에서만 진행한다.
- `execute_code(action="execute", code="...", compiler="auto", safety_checks=true)`: Editor 안에서 C# 메서드 본문을 실행하는 도구가 노출돼 있다. 이번 작업에서는 실행하지 않았다.
- `execute_custom_tool(tool_name="...", parameters={...})`: 프로젝트에 등록된 custom tool을 호출한다. 마이그레이션 helper에는 위 메뉴 도구가 바로 사용 가능하다.
- `refresh_unity(mode="if_dirty", scope="scripts", compile="request", wait_for_ready=true)`: 필요한 시점의 스크립트 임포트/컴파일 요청용. 반환 직후 도메인 재로드가 이어질 수 있어 Editor 상태를 확인해야 한다.

후속 실행이 결정되면 아래 형태로 호출할 수 있다. 이 명령은 본 구축 과정에서 실행하지 않았다.

## 프로젝트 격리

서버는 루프백 8093에만 바인딩한다. `LastBellRegistry`는 Unity의 등록 경로, 프로젝트 이름, 경로 해시를 검사하여 Last Bell 외 등록을 거부한다. 실행 파일은 고정한 upstream 서버를 재사용하며 설치 패키지나 SimpleGame 파일은 수정하지 않는다.

호출 스크립트는 매 세션에서 Last Bell 인스턴스를 선택한 뒤 Unity가 반환하는 `projectRoot`를 대조한다. 이후 각 도구 호출에도 인스턴스를 명시한다. 경로 확인에 실패하면 요청 도구를 호출하지 않는다. Codex 네이티브 MCP 세션에서도 최초에 `set_active_instance(instance="Client@65e60f79bc76ded9")`와 프로젝트 리소스 확인을 수행한다.

등록 검증의 소규모 테스트 2개(정상 등록, 다른/누락 경로 및 잘못된 해시 거부)를 통과했다. 이 검사는 메모리상의 레지스트리만 사용하며 Unity에 접근하지 않는다. 사용자 지시에 따라 전체 Unity QA는 수행하지 않았다.

## 실행 중 발견한 사항과 처리

- 실제 점유 확인 시 8093은 비어 있어 후보 포트를 그대로 사용했다.
- 확인 시점에 Unity Hub만 있고 Unity Editor 프로세스는 없었다. 해당 버전 Editor에서 `C:/Github/Test2/Client`만 일반 모드로 열었다. 기존 Unity를 종료하거나 사용자 저장을 초기화하지 않았다.
- 패키지 import 시 전역 EditorPrefs에 남은 8091 주소와 자동 시작 옵션 때문에 **Last Bell이 새로 생성한** 8091 서버가 나타났다. 해당 프로세스의 명령줄에 `C:/Github/Test2/Client/Library/MCPForUnity/RunState/mcp_http_8091.pid`가 있음을 검증한 뒤 이번 작업이 생성한 서버만 정리했다. 기존 다른 프로젝트 서버는 중지하지 않았다.
- 재발 방지를 위해 Last Bell 연결 helper는 패키지의 자동 서버 시작을 **현재 Editor SessionState에서만** 억제한다. 전역 자동 시작 설정과 SimpleGame 원본 설정은 유지했다. 최종 서버는 시작 스크립트가 관리한다.
- 연결 helper의 최종 수정은 현재 Editor에서 스크립트 임포트/컴파일로 반영했다. 마지막 읽기 smoke는 도메인 재로드 후 수행했다.
- Unity 패키지의 공개 연결 API는 전역 EditorPrefs에 연결 URL을 저장하는 구조다. 다른 프로젝트는 자신의 helper로 자신의 URL을 적용해야 한다. 8093 서버 등록 검사는 다른 프로젝트의 잘못된 접속을 차단한다.
- Git 기반 Python 서버 설치 시도가 실패하여 같은 버전의 PyPI 배포판 10.1.0을 고정 사용했다. Unity 패키지 자체의 Git 커밋 고정 및 Package Manager resolve는 성공했다.
