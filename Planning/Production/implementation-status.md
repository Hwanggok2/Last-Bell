## 이번 구현

첫 실행은 Stage1에서 보호된 회피·공격 튜토리얼로 시작한다. 이후 네 방향 회피, 일반/완벽 판정, 적의 기절, 공격/치명타, 사각 파편과 큰 도트 피해 숫자로 전투한다. 5층·10층 처치 보상은 유물3개 중 하나를 선택하며 종 파편1개·3개를 각각 받는다. 재획득한 유물은 성장하고 신규 유물은 로비에서 장착한다.

10층 유물 선택 뒤 확인 화면 없이11층으로 이어진다. 사망하면 로비에서 캐릭터별 스탯을 강화하고 유물을 장착한 뒤 보스 체크포인트 다음 층에서 재출전한다. 골드 부족 시 필요한 종 파편 교환 견적을 확인하며, 교환과 강화는 별도 명령이다. 캐릭터와 일반 적 HP는 발밑, 중간 보스와 보스HP는 상단이다. 로비 왼쪽1/4는 캐릭터 목록, 유물 화면 왼쪽1/3은 장착·보유 목록이다.

실행 콘텐츠는 **온1명, 적5종, 성문 배경1장,1~10층과11층 경계 표본**이다. 일반 적3종을 여러 층에서 재사용한다. 11층 완료는 MVP 범위 안내로 끝나며 최종50층 엔딩을 대신하지 않는다. 담·린은 미구현 선택 불가 상태다.

실제 사용자 저장은 쓰지 않았고 Evidence/Unity/smoke-profile-*에 테스트 저장을 분리했다. 체크섬은 손상 검출용이며 유료 재화의 서버 검증을 대신하지 않는다.

## 아트와50종 제작 범위

레퍼런스의 남색 배경·황금 실루엣 방향으로 온8개, 적5종×3개 대표 자세와 성문 배경을 생성·임포트했다. 원본은 유지하고 Unity 스프라이트 메타데이터로 셀/발 기준점을 지정했다.

|층|구역|현재 상태|
|---|---|---|
|1~10|성문|배경1장·MVP 적5종 초안 적용|
|11~20|사슬회랑|배경 구조·적10종 명단 설계.11층은 재사용 적으로 연결 확인|
|21~30|멈춘시계|배경 구조·적10종 명단 설계|
|31~40|잿빛첨탑|배경 구조·적10종 명단 설계|
|41~50|새벽종루|배경 구조·적10종 명단 설계|

온의 상·하·뒤·앞은 측면 점프/숙이기/후퇴/돌진이다. 적에게 같은 네 회피 세트를 만들지는 않는다. 적은 대기·공격 예고·공격·피격·기절·사망을 중심으로10개의 동작 원형을 공유하는 제작 계획이다. 몸 실루엣·무기·공격 준비가 구분돼야 새 종으로 센다. 지금 확보한 키 포즈와 절차 연출을 완성 프레임 애니메이션이나50종 완성 자산으로 표시하지 않는다.

## 역할과 스킬

- 총괄: 실제 Unity 환경·프로젝트·이미지 생성·아트 임포트·저장·통합·빌드·실행 검증.
- 전투 담당: 순수 C# 상태/판정/진행/저장 DTO와 단위 검증. [검토](combat-implementation-review.md)
- UI 담당: 저장 프리팹·화면 바인딩·입력·효과·시각 검토. [검토](ui-implementation-review.md)
- 데이터/경제 담당: 원본·내보내기·성장/유물/보상과 독립 교차 검토. [검토](data-implementation-review.md)
- 기획/아트 담당: 구역·50종 명단·공유 모션 설계와 이미지 초안 독립 검토. [검토](art-draft-review.md)

unity-project-foundation과 game-ui-wireframe-copy를 적용했다. 설정·진행 상태·표시를 분리하고, 생성 데이터 검증, 저장 프리팹, 명시적 Create Missing/Validate/이관, 필요한 게임 문구만 유지하는 규칙을 반영했다. 원본 편집은 GameData JSON, 런타임 UI 생성 대신 저장된 GameView/Actor/Mvp 에셋을 사용한다.
