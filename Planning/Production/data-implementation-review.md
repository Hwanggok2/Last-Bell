# Unity MVP 데이터 구현 검토

작성일: **2026-10-21 KST**  
상태: **데이터 구현·내보내기·독립 검증 완료 / Unity 실제 로드·플레이 검증은 총괄 통합 범위**

## 산출물과 소유권

- `GameData/mvp-catalog.json`: 사용자 편집 원본. planning-v4 초기 수치를 옮겼으며 Excel은 이번 요청 범위에서 제외했다.
- `GameData/export_catalog.py`: 표준 라이브러리만 사용하는 전체 검증·결정적 JSON 내보내기. 실패 시 정상 생성물 보존, 성공 시 원자적 교체, `--check`/`--validate-only` 지원.
- `Client/Assets/Game/Runtime/Data/GameCatalog.cs`: namespace LastBell, JsonUtility용 직렬화 필드·ID 조회·강화/보상 조회·검증. Unity API·실행 상태 의존 없음.
- `Client/Assets/Game/Data/Generated/mvp-catalog.json`: 생성 파일. 원본 SHA256·schema/data 버전·수동 편집 금지 문구 포함. 수동 편집하지 않았다.
- `GameData/README.md`, `GameData/tests`: 편집·단위·패턴 계약과 검증 도구. 전투/UI 사용을 위해 요청받은 공유 계약 `Planning/mvp-implementation-contract.md`에 데이터 API를 추가했다.

그 외 담당의 런타임·UI·Bootstrap·씬·아트·기획 JSON은 수정하지 않았다.

## 반영 범위

스테이지1~10과10보상 이후11 자동 진입의 경계 표본이 있다. 적ID 순서는 `gate_sentinel / chain_thrall / ash_wisp / gate_sentinel / gate_warden / chain_thrall / ash_wisp / gate_sentinel / chain_thrall / bell_knight / chain_thrall`이다. 적의 안정적ID와 아트ID를 분리했다.

온의 고정별3/3/3/3을 기본으로 하고 담2/5/2/3·린4/2/4/2도 데이터에 포함했다. MVP 선택 가능은 온만 켰다. 유물10종의 Lv.1~5 총효과·최종 상한, 전체10종3택1·MAX 포함·구역별20/40/60/80/100 G 전환을 반영했다. 무료 파편 중간1/보스3, 슬롯4/8,교환100 G,별도4스탯Lv.0~50 비용을 유지했다.

전투 기본 수치·성장 계수·행운0.0018·최종 상한·0.001HP 정밀도를 v4에서 옮겼다.1~10층 기본 보상640 G/4파편,50층 경제표 기본8,000 G/20파편,스탯당 총1,780 G/4종7,120 G가 유지된다.10층 적HP706/피해16,11층 표본HP1,050/피해40이다.50층/NG+ 적 데이터나 외부 구매·광고·서버를 구현한 것으로 표시하지 않는다.

## 패턴 데이터 판단

모든 층에 배열 순서가 있는 `patternSteps`를 넣었다. 첫1~4층은 위/뒤/아래/앞을 각각 첫 타격으로 소개한다. 단발650ms,연타 전체 예고900ms,후속250ms,타격 간격 최소450ms를 검증한다. 배열 반복 경계의 `intervalMs`도 직전 타격 기준으로 해석한다.

5층은 위→아래2연타와 단발을 섞고,10층은 위→아래→앞3연타와 뒤 단발을 섞었다. 한 패턴 주기의 평균 타격 간격은1~4·6~9층1,800ms,5층1,600ms,10층1,500ms,11층1,650ms로 기존 구역별 평균 입력과 맞췄다. **구체 순서는 MVP 구현용 초기 편성**이며 실제 재미·생존 시간 검증 결과가 아니다. 기절에 의한 취소·복귀·앱 재개는 GameSession 책임이다.

## 실행한 검증

| `dotnet run --project GameData/tests/CatalogSmoke.csproj --no-restore --no-launch-profile` | C#7.3 컴파일·public field 역직렬화·ID 조회·강화비/보상/경계·잘못된 DTO 거부 통과 |

독립 C# 검사는 설치된.NET10의 필드 역직렬화로 실행했다. Unity JsonUtility를 실제 호출했다는 증거와 구분한다. 카탈로그 코드는 Unity에 외부.NET10 라이브러리를 요구하지 않는다.

## 통합에 남긴 확인

총괄의 Unity6000.3.15f1에서 실제 TextAsset을 `JsonUtility.FromJson<GameCatalog>`로 읽고 `ValidateOrThrow()`를 실행하는 확인, 전투/UI 편집기 컴파일·플레이·빌드는 별도다. 실제 첫 회피/공격 및2~4층 방향 안내,5/10층 보상,10선택 후11진입,패턴 예고와450ms 연타의 조작성은 통합 테스트가 필요하다.

설정 필드는 Unity 직렬화 때문에 public이지만 읽기 전용 계약이다. 데이터 원본을 수정한 뒤에는 exporter를 다시 실행하며 실행 중 설정을 바꿔 저장된 전투 상태와 혼합하지 않는다. 세션 저장 버전·이전 저장 마이그레이션·보상 중복 처리는 전투 담당이 소유한다. 이 문서는 실제 게임 전체 완성이나 플레이 검증 완료를 주장하지 않는다.

## 세션 경제·진행 독립 검토 추가 — 2026-10-21

**결론: 검토한 로컬 MVP 범위에서 진행을 막는 문제를 발견하지 않았다.** `GameSession.Economy.cs`, `GameSession.Progression.cs`, `GameSession.State.cs`를 카탈로그와 대조하고, 전투 처치·보상 선택·저장 복구의 호출 흐름을 함께 확인했다. 다른 담당의 런타임 코드는 수정하지 않았다.

독립 실행 도구는 `GameData/tests/SessionContractReview/`에 두었다. 실제 생성 카탈로그와 현재 Core 소스를 연결해 다음 명령을 실행했으며 **880개 단언이 통과**했다. 이는 880개의 개별 테스트를 뜻하지 않는다.

```powershell
dotnet run --project GameData/tests/SessionContractReview/SessionContractReview.csproj --no-launch-profile
```

빠르게 각 경계에 도달하기 위해 일부 검증은 높은 스탯이나 유물 상태를 가진 개발용 저장 데이터를 사용했다. 처치·선택 자체는 공개 세션 API로 실행했으며, 이 결과는 실제 플레이 난이도나 UI 조작성을 검증한 것이 아니다. 독립 실행의 직렬화는 .NET의 필드 직렬화이며 Unity JsonUtility·실제 디스크 저장의 원자성 검증과 구분한다. 총괄이 Unity Prepare 성공을 공유했으며, Unity 테스트·플레이 검증은 총괄의 통합 결과를 따른다. 실제 결제·서버 검증은 이번 MVP 범위 밖이다.
