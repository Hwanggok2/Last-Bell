## 1. 결론과 근거의 구분

**세로 2버튼, 상단의 공격 예고, 하단의 큰 입력 영역을 권고한다. 영구 능력치 성장은 빼고 외형 전용 ‘수집’으로 바꾸는 총괄 조정안에 동의한다.** 결과 화면은 승리·패배 모두 `다시 도전`을 1차 행동으로 유지한다. 선택형 광고는 외형 재화만 추가하고 재도전을 막지 않는다.

‘마지막 종지기’는 종·불씨·그림자의 큰 형태로 목표를 보여 줄 수 있어 작은 화면과 어울린다. 다만 종이라는 소재만으로 전투 차별점이 입증되지는 않는다. 1회 충전 울림은 읽기 쉬워지는 대신, 축적/소비 선택의 폭은 줄어든다. 회피와 반격의 손맛·실패 원인·재도전 의향은 실제 플레이로 검증해야 한다.

| 구분 | 내용 |
|---|---|
| 전달받은 요구사항 | 원스토어 선출시, 저해상도 도트, 단순 회피·공격, 짧은 시작 서사, 도전욕구, 과금·MVP 검토. 작업 범위는 기획이며 원본 StageGame/SimpleGame은 수정하지 않음 |
| 최종 기획 기준 | 정밀회피로 울림 1회 충전, 패턴 무피격 유지, 연속타 종료 후 800ms 안의 다음 공격 적중에 소비. 피격 시 해당 패턴 재충전 금지. 길게 누르기·제3버튼 없음. 기본 회피+일반 공격으로 완주 가능 |
| 총괄 조정안에 대한 동의 | 영구 공격력/HP 성장 제외, ‘성장’을 외형 해금용 ‘수집’으로 변경, 광고·과금 보상은 외형 전용, 결과의 재도전 우선 |
| 직접 확인한 자료 | 지정된 두 스킬, 총괄 메시지, `decisions.json`·통합 `index.html`의 관련 항목, 전투/시장 검토의 관련 계약, 컨셉 v2와 총괄 제공 와이어프레임 캡처, 생성한 좌표 데이터 |
| UI 담당 제안 | 아래 배치·문구·우선순위·입력 처리·울림 표시·오류 동선. HP100·12전·장식 조각 보상/비용은 최종 기획 기준을 표시하며 실측값이 아님. 상품 이름·표본 잔액은 시안 예시 |
| 미검증 | 실제 손가락 가림, 터치 정확도, 한국어 폰트 렌더, 800ms 인지·입력 가능성, 작은 외형의 구매 가치, FPS·지연·접근성, SDK 및 저장 구현 |

적용 문서: [Unity 프로젝트 기반](../../Skills/unity-project-foundation/SKILL.md), [게임 UI 배치와 짧은 문구](../../Skills/game-ui-wireframe-copy/SKILL.md). HTML 소스 작성에는 `andrej-karpathy-guidelines`의 최소 구현·검증 기준도 적용했다.

초기 와이어프레임의 능력치 강화·상품 가격 예시·1장 오프닝안은 후속 결정으로 교체했다. 최종 반영은 HP100, 구역당4전·총12전, 1회 울림, 장식 조각, 첫 시작 3컷9초다. 다른 담당의 오래된 3칸 축적·별도 울림 게이지 좌표를 사용하지 않는다. UI 담당의 최종 판정은 11절에 기록한다.

## 2. 산출물과 사용 방법

- [wireframes.svg](../Visuals/wireframes.svg): 장식 없는 기본 4화면. 로비·전투·결과·수집을 나란히 배치했다. 각 화면 밖에 주요 bounds/anchor/hit area/우선순위를 기록했다.
- [wireframes.html](../Visuals/wireframes.html): 외부 의존성 없이 열 수 있는 4화면 비교 뷰어. 기본 2×2, 1584px 이상 4열, 799px 이하 1열. 각 카드의 화면·상태와 전체 비율·안전 영역·한글 120% 크기·입력 가이드를 바꿀 수 있다.
- [build-wireframes.mjs](../Visuals/build-wireframes.mjs): SVG와 HTML의 공통 생성 원본. `node Planning/Visuals/build-wireframes.mjs`로 재생성한다. `--check`는 아래 좌표 불변 조건만 검사한다.
- [concept-simple-v2.png](../Visuals/concept-simple-v2.png): 총괄이 생성한 방향 참고 이미지. UI 담당은 수정하거나 재생성하지 않았다.

뷰어의 `기본 4화면`, `서사·설정·상점·구매 대기`, `오류 상태 비교`로 주요 조합을 바로 볼 수 있다. 화면 안 SVG 버튼은 실제 전투·거래를 실행하지 않는 배치 시안이다. 외부 선택 컨트롤만 동작한다. 상점의 `표시 가격`은 총괄 요청에 따른 기획용 자리표시자이며 출시 문자열이 아니다.

HTML/SVG 문자열은 이번 시안의 원본이다. 제품 구현 시 문구 원본은 게임 데이터의 단일 편집 원본으로 옮기고, View나 생성 SO에 서로 다른 문구를 중복 편집하지 않는다.

## 3. 조작과 정보 우선순위

### 2버튼 독립 검토

`피하기`는 방향 선택 없는 회피 1회, `공격`은 현재 적에게 공격 1회로 제안한다. 자유 이동·타깃 선택·길게 누르기·제3버튼은 없다. 예고를 읽는 시간을 버튼을 찾는 시간으로 소모하지 않게 두 버튼을 계속 같은 자리에 둔다.

| 선택 | 장점 | 반론과 검증 |
|---|---|---|
| 피하기/공격 2개 | 각 버튼을 크게 만들고 예고·연속타 끝·반격 순간에 집중시킬 수 있음 | 항상 같은 대응만 반복되면 단조로울 수 있음. 적의 지연·연속타와 회피 후 공격 판단이 실제로 다른 행동을 만드는지 검사 |
| 좌/우 회피+공격 3개 | 방향 판단의 여지가 추가됨 | 현재 범위에서는 방향 예고·좌우 애니메이션·입력 오해·QA가 함께 늘어남. 단순히 버튼 하나 추가하는 변경이 아님 |
| 한 버튼 문맥 전환 | 화면은 단순해짐 | 누른 순간 공격인지 회피인지 예측하기 어려워질 수 있어 권고하지 않음 |

‘두 버튼이므로 한 손에 편하다’고 주장하지 않는다. 기본 시안은 양손 엄지 파지를 출발점으로 하며 작은 기기에서 한 손·양손을 각각 확인한다.

### 전투 표시 우선순위

1. **P1 즉시 행동:** 적의 공격 예고, 연속타 종료/반격 기회, 피하기/공격 버튼, 울림이 준비된 공격 버튼.
2. **P2 상태:** 플레이어 HP, 적 HP, 현재 구역/전투 순서, 직전 행동의 짧은 결과.
3. **P3 보조:** 일시정지. 재화·상점·기록 상세·서사 문단은 전투 HUD에 넣지 않는다.

전투 예고는 상단 중앙의 고정 구역과 적의 실제 자세를 함께 사용한다. `!`는 다가오는 위험, `틈!`은 연속타 종료 뒤 반격 기회다. 버튼 테두리만 보고 연속타 중에 공격하게 만들지 않는다. 색만으로 이 두 상태를 구분하지 않는다.

### 울림 표시 — 최종 기획 기준 반영

| 전투 상태 | 공격 버튼 표시 | 그 밖의 표시·동작 |
|---|---|---|
| 울림 없음 | 기본 공격 버튼 | 일반 공격 가능. ‘잠김’ 표시를 하지 않음 |
| 정밀회피로 1회 충전, 적 연속타 진행 중 | 종 아이콘 + 고정 테두리 | 중앙은 계속 위험 예고. 반격을 재촉하는 깜박임·`지금 공격!` 없음 |
| 마지막 타격 회피 후 800ms의 소비 기회 | 종 아이콘 + 강조 테두리. 구현에서는 남은 기회를 테두리 감소로 표시하는 안 | 중앙 `틈!`, 첫 안내 때만 `지금 공격!`. 전투 세션의 기회 종료 시각을 읽음 |
| 조건을 만족한 다음 공격 적중 | 종 아이콘/테두리 해제, 짧은 종 파문 | 버튼을 누른 순간이 아닌 적중 결과로 소비 표시 |
| 기회 만료·피격·적 격파·다음 패턴·런 이탈 | 기본 상태로 복귀 | 패턴 중 피격하면 같은 패턴 재충전 금지. 공격 준비 중 회피 취소는 울림을 소비하지 않으며 만료 시각도 늘리지 않음 |

패턴 도중 일반 공격도 피해 10을 준다. ‘반격 기회 밖 공격은 헛공격’이라는 규칙이 아니다. 800ms를 넘어 적중하면 일반 피해만 적용한다. 연속타의 남은 점을 예고 위에 두고 타격마다 소등해, 충전과 마지막 타격 종료를 구분한다. 점은 적 패턴 정보이며 별도 울림 게이지가 아니다.

상단에 별도 울림 게이지·칸·숫자를 추가하지 않는다. 800ms를 소수점 타이머로 읽게 하지 않는다. 예고/연속타 구분과 충전 아이콘의 의미를 먼저 이해시키며, 기본 회피와 일반 공격만으로 완주할 수 있다는 규칙을 UI에서 유료 잠금처럼 보이게 하지 않는다.

HTML의 강조 테두리는 정지 상태 시안이며 실제 800ms 애니메이션·입력 창을 재현하지 않는다. ‘충전됨’과 ‘지금 소비 가능’의 혼동이 계속되면 아이콘/테두리 역할을 줄여 다시 검토한다.

### 입력 처리 계약 제안

- 전투 버튼은 터치 시작 시각을 세션에 전달하는 1회 입력이다. 손을 뗄 때까지 기다리는 일반 메뉴 클릭과 구분한다. 이동·유지 중 반복 호출하지 않는다.
- 회피 회복 중에도 `피하기`라는 이름과 위치는 유지하고 비활성 명도·짧은 바만 바꾼다.
- 같은 프레임의 양버튼 입력은 전투 시스템이 명시적으로 판정한다. 초안 권고는 회피 우선이며, UI 이벤트 호출 순서에 맡기지 않는다.
- 앱 이탈·포커스 상실·일시정지 때 누른 손가락 상태를 해제한다. 복귀 시 정지 상태로 시작하고 `계속`을 눌러 재개한다.
- 버튼 교환은 설정에서 두 버튼의 위치 전체를 교환한다. 라벨·쿨다운·종 아이콘·접근성 읽기 이름도 함께 이동한다.
- 판정 시간·HP·울림의 소유자는 전투 세션이다. UI의 테두리 애니메이션이나 타이머가 적중/실패를 별도로 판정하지 않는다.

## 4. 화면 흐름

```text
최초 진입 → 시작 서사(건너뛰기 가능) → 로비 → 전투
                                       │       ↕ 일시정지 / 앱 복귀 확인
                                       │       ↓ 승리·패배·중단
                                       │      결과 → 다시 도전 → 전투
                                       │       ├→ 선택형 광고 → 결과
                                       │       └→ 로비
                                       ├↔ 수집
                                       ├↔ 설정 → 이야기 다시 보기 / 복원 / 문의
                                       └↔ 상점 → 스토어 구매 → 확인 대기 / 성공 / 실패
```

| 화면 | 주 행동 | 필요한 상태 | 진입·이탈 |
|---|---|---|---|
| 로비 | 도전 | 진행 가능한 구역, 최고 기록, 외형 재화 | 첫 서사·결과에서 진입. 도전/수집/설정/상점 |
| 전투 | 피하기·공격 | HP, 구역, 적 예고, 빈틈, 공격 버튼 울림 | 로비·재도전에서 진입. 결과/일시정지 |
| 결과 | 다시 도전 | 승패, 확실한 실패 원인 한 줄, 기본 보상/저장 상태 | 전투 종료. 재도전/로비/선택형 광고 |
| 수집 | 해금 또는 적용 | 외형 미리보기, 보유 여부, 비용·잔액 | 로비와 왕복. 전투 능력치 변화 없음 |
| 설정 | 해당 옵션 전환 | 소리/진동/흔들림/버튼 위치 | 로비와 왕복. 이야기·복원·문의 |
| 상점 | 확인된 가격으로 구매 | 제공 내용, 외형 전용 조건, 실제 스토어 가격, 소유·거래 상태 | 로비와 왕복. 스토어 UI·확인 대기 |
| 시작 서사 | 종탑으로 | 목표를 설명하는 짧은 문장 | 최초 1회. 건너뛰기/설정에서 다시 보기 |

한 런 중 다음 구역으로 넘어갈 때 매번 결과·상점 화면을 끼우지 않는다. 전체 런 종료 결과에서 `다시 도전`을 최상위로 유지한다. 승리의 보상 연출과 패배 원인 설명이 재도전 버튼을 움직이지 않게 한다.

최종 서사는 최초 9초·3컷, 엔딩 6초·2컷이다. 엔딩은 **첫 완주 때 런 기록을 확정한 뒤 한 번만 재생**하며 건너뛸 수 있다. 엔딩 6초는 런 기록과 반복 런 시간에서 제외하고, 이후 설정에서 무료로 다시 볼 수 있다. 시안은 각 오프닝 컷을 선택해 볼 수 있고 자동 9초 재생은 하지 않는다. 오프닝도 처음부터 건너뛰기가 가능하며 설정에서 무료로 다시 볼 수 있다. 재도전 때 서사를 자동 재생하지 않는다.

## 5. 기준 크기·bounds·anchor·hit area

### 좌표 계약

- 세로 논리 너비 `W=360`. 긴 기준 화면 `H=800`은 **20:9**, 최소 기준 `H=640`은 **9:16**이다.
- 원점은 전체 논리 화면 좌상단. `S`는 실제 safe top, `B=H-safe bottom`. 안전 영역 높이는 `B-S`.
- 기본 그림은 `S=24`, 하단 24를 가정한다. 실제 노치 크기를 조사했다는 뜻이 아니다.
- HTML은 안전 영역 `(0,0)`, `(24,24)`, `(44,34)`를 바꿀 수 있다. 너비 좌우 안전 영역은 세로 기준 0을 가정했다. 가로 화면 지원은 이번 범위 밖이다.
- UI는 너비 기준 크기를 유지한다. 640에서 전체를 0.8배로 축소하지 않는다. 상단 HUD와 하단 입력 영역 사이의 장식 공간을 먼저 줄인다.
- `TL/TR/T`: 안전 영역 상단 왼쪽/오른쪽/중앙. `BL/BR/B`: 안전 영역 하단 왼쪽/오른쪽/중앙. `C`: 안전 영역 중앙.
- Unity 구현은 SafeArea root 안에 저장된 RectTransform을 두고 해당 anchor와 고정 크기/오프셋을 적용한다. UI 스크립트 여럿이 매 프레임 좌표를 덮어쓰지 않는다.

### 주요 실제 배치

모든 값은 논리 단위이며 `x,y,w,h`다. 각 항목의 전체 좌표는 HTML의 펼침 표와 SVG의 `data-bounds`, `data-anchor`, `data-hit`에서 확인할 수 있다.

| 화면/항목 | bounds 공식 | 360×800, S=24/B=776 | 360×640, S=24/B=616 | anchor / 입력 |
|---|---|---|---|---|
| 전투 HP | `16,S+12,120,40` | 16,36,120,40 | 동일 | TL / 없음 |
| 일시정지 | `296,S+8,48,48` | 296,32,48,48 | 동일 | TR / 48×48 |
| 적 HP | `72,S+104,216,8` | 72,128,216,8 | 동일 | T / 없음 |
| 핵심 예고 | `48,S+224,264,68` | 48,248,264,68 | 동일 | T / 없음, P1 |
| 피하기 | `16,B-104,156,88` | 16,672,156,88 | 16,512,156,88 | BL / 전체 bounds |
| 공격 | `188,B-104,156,88` | 188,672,156,88 | 188,512,156,88 | BR / 전체 bounds |
| 버튼 사이 | 너비 16 | 172~188 | 동일 | 입력 없음 |
| 로비 도전 | `16,B-184,328,64` | 16,592,328,64 | 16,432,328,64 | B / 전체 bounds |
| 로비 수집/상점 | `16 또는 188,B-88,156,64` | y=688 | y=528 | BL/BR / 전체 bounds |

모든 활성 입력 bounds는 최소 48×48 논리 단위다. 이 수치만으로 실제 48dp가 보장되는 것은 아니다. Canvas scale·기기 밀도·접근성 설정을 포함해 실제 크기를 확인한다.

### 손가락 가림과 작은 화면

검토용 위험 구역은 `[x=0,y=B-208,w=360,h=208]`로 가정했다. 실제 손가락 크기나 측정 결과가 아니다. 최악의 시안 조합 `H=640,S=44,bottom=34`에서 핵심 예고는 y=268~336, 가림 가정 구역은 y=398부터다. 수치상 62 단위 간격이 있다.

주인공 일부나 하단 피드백이 손에 가릴 가능성은 남는다. 따라서 `틈!`·피격 위험·연속타 종료를 하단 문구만으로 전달하지 않는다. 실제 적의 무기 끝·파문도 이 상단 예고 영역과 충돌하거나 손가락 아래로만 이동하면 안 된다.

최소 화면에서는 장식/배경의 상하 여백을 줄인다. HUD·예고·버튼·가격·복구 행동의 글자를 일괄 축소하거나 잘라서 맞추지 않는다. 추가 상품이 생기면 상품 영역만 스크롤하고 구매·닫기 행동은 안전 영역 안에 유지한다.

## 6. 시각 방향과 concept-simple-v2 검토

**v2를 방향 참고로 사용하는 데 동의한다.** 직접 확인한 이미지는 세 장면이 나란히 놓인 콘셉트이며, 실제 360×800 UI 화면이나 저장 프리팹이 아니다. 세 장면 모두 작은 종지기, 큰 상대, 어두운 종탑, 아래의 넓은 어두운 여백을 가진다.

| 관찰 | UI 관점 판단·수정 방향 |
|---|---|
| 주인공은 왼쪽 아래, 상대는 오른쪽의 큰 실루엣 | 위치 관계를 빠르게 읽기 좋음. 와이어프레임의 인물 표식도 좌/우 관계로 맞춤. 자유 이동 표시를 추가할 이유는 없음 |
| 아래에 넓은 어두운 여백 | 조작 영역을 따로 확보하기 좋음. 그러나 원본 비율을 통째로 늘리면 640 화면에서 전장이 압축되므로 실제 전투 viewport에 다시 구성해야 함 |
| 주인공·적·큰 종이 비슷한 밝은 크림색 | 큰 종이 공격 예고보다 먼저 보일 위험. 상단 장식 종은 어둡게, 적의 예고 순간은 가장 높은 명도·명확한 형태로 구분 |
| 주황색 빛/달/등불이 강조됨 | 울림 준비와 위험 예고에 같은 주황색만 쓰면 의미가 겹침. 울림은 종 모양+버튼 테두리, 위험은 적의 자세+예고 형태로 구분 |
| 주인공이 상대보다 매우 작음 | 외형 상품의 차이가 전투 중 보이지 않을 수 있음. 수집·상점에는 확대 미리보기가 필요하며, 실제 원래 크기에서도 무엇이 바뀌는지 별도 확인 |
| 사슬·종·큰 적의 거친 픽셀형 윤곽 | 방향은 단순해졌지만 사슬과 작은 부품은 실제 저해상도 스프라이트에서 다시 정리해야 함 |
| 배경 색의 완만한 변화·경계의 다양한 단계 | 생성 이미지 자체가 정확한 4색 팔레트·동일 픽셀 격자·정수 배율을 보장하지 않음. production 스프라이트시트로 간주할 수 없음 |

후속 색상 제안은 배경 짙은 남색, 보조 청색, 인물 크림색, 주황 강조의 네 역할이다. 정확한 팔레트 값·색 수는 원본 도트 자산 제작 단계에서 정한다. 밝은 효과가 겹칠 때도 적의 위험 범위와 버튼의 종 아이콘이 구분돼야 한다.

도트 월드는 Point filtering·정수 배율을 출발점으로 하고, UI 문자와 분리해 렌더한다. 360 논리 너비에서 2배 표시를 쓴다면 전장 폭 328은 원본 164픽셀에 대응한다. 이는 제작 후보이며 Unity 카메라/실기기에서 확정한 사양이 아니다. 640 화면을 위해 중요한 인물·무기·예고는 짧은 전장 안에 배치하고 긴 화면의 여백에 장식을 더한다.

최종 기준의 주인공 16×24px, 일반 적24~32px, 보스48~64px, 4색 기반 방향에 동의한다. 실제 이미지의 색 개수/격자 보장과는 구분한다.

한글은 작은 도트 폰트 강제 사용을 피한다. 시안은 설치된 한글 고딕을 사용하며 본문·버튼 16, 상태 16~18, 제목 22~26 논리 단위를 출발점으로 삼았다. 출시 폰트의 라이선스·glyph coverage·TextMeshPro 자산·실제 읽힘은 미확정이다. 한국어 본문을 이미지에 구워 넣지 않는다.

소리·진동을 꺼도 예고·정밀회피·울림 소비가 보여야 한다. 화면 흔들림 감소에서도 위험 형태와 `틈!`을 유지한다. 흔들림·번쩍임·큰 파문은 예고보다 우선하지 않는다.

## 8. 오류·광고·구매·저장 상태와 복구

UI는 외부 서비스의 실제 상태를 읽는다. 타이머가 길어졌다고 성공/실패를 추정하거나, 창을 닫았다고 거래를 취소하지 않는다.

| 상태 | 표시·허용 행동 | 상태 전이·중복 방지 계약 |
|---|---|---|
| 기본 결과 저장 성공 | 기본 보상 표시, 재도전 1차, 광고 보조 | run/result ID로 기본 보상 1회 처리. 결과 재개방으로 재지급 금지 |
| 기본 결과 저장 실패 | 비차단 안내·저장 재시도. 재도전/로비 가능. 광고 자리에는 저장 재시도 | 미확정 보상을 ‘이미 받음’으로 표시하지 않음. 실행 중 pending 결과를 유지하되 영속 저장 실패 상태에서 앱 종료 후 보존을 약속하지 않음 |
| 광고 요청/준비 | 광고 버튼만 비활성, 재도전·로비 유지 | 화면 이탈 시 늦은 준비 콜백으로 광고를 강제 시작하지 않음 |
| 광고 없음(unavailable/no fill) | 광고가 없어요. 기본 보상 상태 표시. 재도전/로비 | 유저의 재도전을 광고 재요청에 묶지 않음. 같은 결과에서 요청 반복 횟수는 구현 계약으로 제한 |
| 광고 취소/오류 | 추가 보상 없음, 기본 보상 보존, 재도전/로비 | 닫힘 콜백만으로 광고 완주 보상 지급하지 않음 |
| 광고 완료·보상 확인 대기 | 확인 상태, 다시 볼 필요 없음, 로비 가능 | 검증 가능한 완료 증거와 event ID가 존재할 때만 이 문구 사용. 원래 결과 ID에 지급, 다음 결과에 섞지 않음 |
| 광고 보상 지급됨 | `장식 조각 +5 받음`, 비활성 | 결과당 최대1회. callback 재전달·화면 재개방에도 같은 보상 1회 |
| 일일 광고 보상 소진 | `오늘 보상 완료`, 광고 버튼 비활성. 재도전 유지 | 일 최대3회. 완료 확인·지급 거래와 횟수를 함께 처리. 실패 요청만으로 횟수 차감하지 않음 |
| 무료 수집 완료 | 재화 광고 영역 숨김. 재도전/로비 위치 유지 | 해금할 무료 외형이 없으면 광고를 제시하지 않음. 새 유료 상품이 있다는 이유로 재화 광고를 다시 켜지 않음 |
| 가격 조회 중/실패 | 가격 확인 중, 구매 불가, 재시도/닫기 | 임의 고정 가격이나 빈 가격으로 구매를 열지 않음 |
| 구매 시작 | 스토어의 실제 결제 UI | 누른 즉시 상품 소유 처리 금지 |
| 구매 pending | `구매 확인 중`, 닫기 가능. 닫은 상품에도 확인 중 유지 | 동일 상품 재구매 잠금. 앱 복귀 때 원래 transaction ID 조회. 긴 대기를 실패로 임의 전환하지 않음 |
| 구매 성공 | 보유 중/적용 | 검증·지급·저장 후 성공 표시. 거래 ID별 1회 권한 지급 |
| 구매 실패/불명 | 내역 확인·닫기 | 명확한 실패와 확인 중을 구별. 결제 여부 불명일 때 ‘다시 구매’로 유도하지 않음 |
| 사용자 취소 확인 | 취소 안내·닫기 | SDK에서 취소가 확인된 경우만 사용. 지급 없음 |
| 구매 복원 | 복원 중→복원 완료/대상 없음/조회 실패 | ‘대상 없음’과 네트워크 실패를 구분. 복원 권한은 기존 거래와 멱등 처리 |
| 외형 해금 저장 실패 | 장식 조각 미사용 안내, 재시도/닫기 | 잔액 차감과 보유 외형 추가를 함께 확정하거나 둘 다 원복. 일부만 저장되면 이 문구를 사용하면 안 됨 |
| 잠금·재화 부족 | 해금 조건/부족분을 표시, 뒤로 가능 | 부족한 재화를 광고·결제 강제 팝업으로 자동 연결하지 않음 |
| 일시정지·앱 복귀 | 게임 시계 정지. 계속/중단 확인 | UI 모달 시계와 전투 시계 분리. 돌아온 순간 이미 피격되는 상태를 만들지 않음 |

원스토어 SDK의 구체적 상태 이름·복원 API·영수증 검증 경로는 이 문서에서 조사/확정하지 않았다. 위 표는 필요한 제품 동작 계약이다. 플랫폼 담당이 SDK 동작과 매핑해야 하며, ‘보상은 반드시 보존된다’는 문구는 그 계약이 실제 구현된 상태에서만 쓴다.

## 9. 수집 전환에 동의하는 이유와 남은 위험

영구 능력치 성장은 패배 원인을 `타이밍 실패`와 `수치 부족` 사이에 흐리게 만들 수 있다. 기본 회피+일반 공격으로 완주 가능한 목표라면 수집으로 분리하는 편이 전투 학습과 맞는다. UI도 `공격력/HP`, 레벨, 강화 전후 화살표를 제거하고 외형·보유·비용만 보여 줄 수 있다.

대신 짧은 런과 작은 캐릭터에서 외형 구매 욕구가 약할 수 있다. 확대 미리보기만 좋고 실제 플레이에서는 구별되지 않는 상품은 권고하지 않는다. 최종 범위인 5팔레트 안에서 망토·등불의 큰 면의 색 차이가 원래 크기에도 보이는지 시험한다. 별도 의상 실루엣·전용 애니메이션을 이 범위에 추가하지 않는다. 외형이 적 예고·피격·울림의 의미를 바꾸면 안 된다.

재화는 **장식 조각**으로 통일한다. 일반전 완료 +1, 보스 완료 +3, 전체 완주 추가 +6으로 12전 완주 총24다. 실패/중단은 이미 완료한 전투 보상만 받고 죽음 자체에는 보상이 없다. 시안 기본 패배는 일반3전 완료 후 첫 보스에서 실패한 상황이라 +3, 완주는 +24다.

최종 외형 범위는 기본1+무료해금2+유료2의 총5팔레트와 썸네일이다. 무료 비용80/160, 광고 보너스+5·결과당1회·하루3회이며 무료 수집 완료 시 광고를 숨긴다. 표본 잔액120 또는20은 표시 예시다. 수집에서는 짧은 `외형` 분류만 남기고, 실제 구매 판단에 필요한 `능력치 변화 없음`은 상점에 유지한다. 광고 부활·강제 재시도 대기는 없다.

일일 횟수는 서비스를 소유한 상태를 표시한다. 출시 구현 시 일자 기준·오프라인/시간 변경 처리 계약을 정해야 하며 UI의 로컬 자정 타이머가 임의로 횟수를 되돌리지 않는다.

## 10. 검사 결과와 실제 기기 검증 계획

### 수행한 검사

2026-10-20 최종 수정 후 공통 렌더러의 **38개 화면·상태 × 2개 높이 × 3개 안전 영역 = 228개 조합**을 검사했다. 활성 입력 항목은 조합 합계 540개이며 실패0이다. 비활성 버튼과 모달 뒤 배경 입력은 활성 개수에서 제외했다.

- 모든 정의된 bounds가 해당 안전 영역 안에 있음.
- 활성 입력 영역은 최소 48×48 논리 단위이며 서로 겹치지 않음.
- 모달이 열리면 배경 입력은 비활성으로 표시됨.
- 전투 예고 bounds가 가정한 하단 208 단위 가림 구역에 들어가지 않음.
- SVG/HTML은 같은 렌더 함수에서 생성한다. 문구·좌표를 두 파일에서 따로 편집하지 않는다.

이는 **좌표 검사**다. 폰트 glyph의 실제 너비, 글자 잘림, 그림의 가림, 이미지 정수 배율, 터치 정확도 검증은 포함하지 않는다. HTML은 120% 글자 크기 상태를 제공하지만 그 상태의 실제 렌더 통과를 주장하지 않는다.

이 세션의 브라우저 렌더 시도에서 로컬 Chrome/Edge headless 프로세스는 스크린샷을 만들지 못했고, in-app 브라우저는 `file:` URL을 정책상 허용하지 않았다. 이후 총괄이 별도 환경에서 생성한 [wireframes-preview.png](../Visuals/wireframes-preview.png)를 이미지 뷰어로 확인했다. 그 캡처는 **수정 전** 1440px 창에서 4번째 화면이 잘리는 문제를 보여 주었다. 이를 받아 HTML을 2×2/4열/1열 반응형으로 수정했다. 최종 수정본의 새 브라우저 캡처는 이 세션에서 확인하지 않았으며, 총괄의 후속 렌더 대상이다.

컨셉 v2 이미지와 위 수정 전 캡처는 직접 시각 검토했다. 모든 상태·글자 확대의 실제 렌더 통과를 주장하지 않는다. Unity 실행·빌드·실기기 플레이는 이번 작업에 없다.

## 11. 최종 기준안 교차 검토 판정

**판정: UI 담당은 `decisions.json` planning-v1과 통합 `index.html`의 최종 관련 계약에 동의한다. 기획 확정을 막는 미해결 UI 필수 수정은 없다.** 아래 사항을 문서와 SVG/HTML에 반영했다. 이는 기획 계약에 대한 동의이며 실제 기기 사용성·사업성 검증의 동의가 아니다.

| 최종 검토 항목 | 판정·반영 |

| HP100, 구역당4전·총12전 | 표본 `체력 100/100`, `1구역 · 2/4`로 수정. 기존 3HP·2/5 제거 |
