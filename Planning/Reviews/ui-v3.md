# 마지막 종지기 v3 — 4방향·인물 중심 전투·캐릭터 로비

작성일: 2026-10-21 KST  
상태: **최종 동의. 6개 담당 산출물 완료, v3 통합 계약·시각 배치·상호작용 시안 검토 통과. 실제 게임·기기·결제 검증은 별개.**

## 1. 먼저 정한 배치와 충돌

사용자 요청에 따라 회피는 `▲ ◀ ▼ ▶` 네 방향, 공격은 검 아이콘으로 바꾼다. 전투 상단의 공격 설명과 기절 글자/숫자는 제거한다. 위험은 종지기의 위·아래·뒤·앞에 위치하는 형상으로 보여 주고, 기절은 종 아이콘·긴 막대·별/자세/파편으로 표현한다.

| 충돌 가능성 | 배치 결정 |
|---|---|
| 좌하단 십자 입력은3방향보다 넓다 | 540높이에서는64×64, 최소360높이에서는48×48의 독립 hit area. 중앙 인물·이동 범위·발밑HP를 손 영역 밖으로 이동 |
| 낮은 지면과 발밑HP | 지면은약82% 유지. HP는 중앙 인물 발 아래에 두고 모서리 버튼 아래에 겹치지 않게 함 |
| 위험 형상과 회피 정답 화살표 혼동 | 키만 삼각형. 위험은 띠/가시/괄호형 궤적으로 구별. 튜토리얼 외 정답 버튼을 계속 강조하지 않음 |
| 기절 막대·보스HP 중복 | 보스HP는 상단 긴 막대, 기절은 종 아이콘을 붙인 별도 긴 막대. 일반 적HP는 발밑. 기절 누적/지속/회복은 한 자리를 바꿔 사용 |
| 치명타 흔들림과 터치 좌표 | 월드 그룹만80ms·최대2px 흔들림. 입력·HP·종막대·위험 예고·메뉴는 고정. 줄이기와OS감소 설정 지원 |
| 640×360 로비에 목록·미리보기·4×10종 | 왼쪽은 안전 너비25%의 가로형 캐릭터 카드 목록. 나머지는 작은 Idle 미리보기+4개 행. 작은 화면에서 목록을 없애거나 전체글자를 축소하지 않음 |
| 캐릭터 기본1~5와 강화10개 종 혼동 | 각 행의 이름 옆에는 채움/빈별5개(예: ★★★☆☆), 종10개는 강화 진행. 각자 의미를 분리 |

‘자동전투’는 **두 행동 뒤 전투 흐름 재개 및 승리 후 다음 층 자동 진행**으로 통합했다. 플레이어 자동공격·자동회피는 추가하지 않는다. 최초 진입/초기화는0골드·0종파편의1층 튜토리얼이다. 로비 검토는 별도 버튼으로 접근한다. HTML은 전투 상태와 입력/VFX를 보여 주는 시안이며 실제 게임 판정·저장·구매 기능을 구현하지 않는다.

적용: [game-ui-wireframe-copy](../../Skills/game-ui-wireframe-copy/SKILL.md). 기존 v2와 총괄/타 담당 파일은 수정하지 않는다.

## 2. 산출물과 범위

- `Visuals/build-wireframes-v3.mjs`: 단일 생성 원본.
- `Visuals/wireframes-v3.html`: 화면/상태 비교, 튜토리얼2행동, 방향 입력, VFX, 캐릭터선택/종채움,9사망/10돌파/50완주 시안.
- `Visuals/wireframes-v3.svg`: 장식 전 주요 화면의 bounds/anchor/hit area 시트.
- `Visuals/landscape-battle-v3.svg`: 컬러 픽셀형 전투 배치 설명.
- `Visuals/lobby-v3.svg`: 캐릭터 목록·Idle·4능력치·강화 종 배치.

기준은960×540,1200×540,최소640×360이며 가로SafeArea·120%한글을 검토한다. 생성SVG는 production 아트나 실제 Unity 캡처가 아니다.

## 3. 전달받은 진행·캐릭터 요구

- 50스테이지, 캐릭터별NG+와10보스 체크포인트.
- 9에서 사망하면 로비의 다음 출전은1.10완료는 잠시 후11층으로 자동 진행하고, 별도 귀환을 누르면 로비에11층 출전을 표시한다. 사망 후 결과를 길게 끼우지 않고 로비로 복귀.
- 50엔딩 뒤 다음 출전은 더 강한1층. NG+와 체크포인트를 캐릭터별로 표시/보존.
- 가제 온: 공격3/체력3/행운3/공명3, 담:2/5/2/3, 린:4/2/4/2.
- 로비 우상단은 골드/종 파편 잔액. 슬롯/교환은 보조 화면.
- 네 스탯은독립Lv.0~50. Lv.0은빈 종10개,1~10은1~10개,11은2단계1개,20은2단계10개. 별점은고정 적성이므로 강화로 채우지 않는다.
- 강화 행은 별5개로 적성1~5, 실제 능력치, 누적Lv/단계,10종과다음 비용,+버튼을 표시한다. 행운은치명 확률과골드 증가를 분리하고 공명은기절 적 피해배율이다.
- 지갑과슬롯 권리는계정 공용.슬롯1→2는10층/4파편,2→3은20층/8파편. 교환1파편→100골드,교환 후 잔액과다음 슬롯 가격을 확인 모달에 표시한다.
- 도달Lv1~10각10G,11은60G,12~20각20G,21은90G,22~30각30G,31은120G,32~40각40G,41은150G,42~50각50G. Lv50은최대로 표시하고+를 비활성화한다.
- 공격/HP는`decisions.json`의선형 증가×돌파 배율,행운·공명은`combat-v3.md`의`E=q×(L+10b)`를 따른다. 행운골드계수0.0018·최종상한20%를 적용했다. 온의공격9/10/11은39.70/43.00/106.49이다.

현재 작성한 배치 결정은 UI 판단이며, 방향 입력의 재미·실기기 정확도·성장 효과를 입증한 결과가 아니다.

- `node Planning/Visuals/build-wireframes-v3.mjs --check`: **522화면/2538개 활성 hit area, 실패 0**. 3해상도×3SafeArea×글자 100/120%×29상태. 안전영역 이탈, 48미만 버튼, 활성 입력 겹침, 중요 인물·HP·위험의 손가림 검사다.
- 생성 HTML 스크립트를 Node VM에서 해석해 튜토리얼의 잘못된 키/올바른 2행동, 0G 시작, 9→10→11 비용과 능력치, 캐릭터별 레벨, 10→11 자동 흐름, 슬롯 잠금·4/8 차감·중복 구매 차단, 50층 후 NG+ 전환 중복 차단을 검사했다. **25개 이상 단언 통과**. 브라우저 시각·터치 시험은 별개다.
- `decisions.json`의 v3 통합값, `combat-v3.md`의 성장식·자동 진행·예고 고정, `market-v3.md`의 계정 소유·4/8·1→100·슬롯 조건을 읽고 대조했다.
- 총괄 1차 렌더가 독립 SVG의 값 없는 `data-world/data-hud` 속성을 XML 오류로 지적했다. 모두 `="true"`로 수정하고 SVG 3개를 Python ElementTree로 다시 파싱해 통과했다.
- 최종 연출 시간은 치명타 80ms/최대2px, 피해 숫자 450ms, 사각 파편 300ms로 동기화했다. HTML 위험 순환 타이머는 패턴 판정 구현이 아닌 검토용이다.
- 총괄의 `Evidence/wireframe-text-check-v3.json`은 3해상도×글자100/120%×29상태 **174조합/1818텍스트, 이탈 0**이다. 튜토리얼→공격→전투, 캐릭터별 성장, 9→10→11의 10G/60G 차감도 브라우저에서 통과했다.
- 총괄이 만든 `wireframes-v3.png`, `lobby-v3.png`, `lobby-small-v3.png`, `battle-small-v3.png`, `plan-overview-v3.png`를 직접 열어 검토했다. 640×360에서도 4키·검·발밑 HP·위험과 로비 4행/10종을 식별할 수 있고, 문구와 +입력이 겹치지 않는다. 숫자·보조 문구는 기기 밀도에 따른 실제 읽기 검증이 남는다.

## 7. 최종 동의

**2026-10-21, UI 담당은 v3 통합 계약과 기획·시각·상호작용 시안 범위에 최종 동의한다. 필수 UI 이견은 없다.**

총괄의 `Evidence/document-render-check-v3.json`을 읽고 검토했다. 기획서 1440/768/360, 시안 뷰어 1600/1440/768/360에서 가로 넘침·이미지 누락·JavaScript 오류가 없었다. 174개 화면 조합의 1818개 텍스트가 소유 영역 안에 있었고, 최초 튜토리얼→회피→공격→전투, 캐릭터별 강화 독립, 9→10→11의 10G/60G 차감이 통과했다.

4방향 삼각키, 검 공격, 인물 주변 위험 형상, 고정 HUD, 발밑/보스 HP, 종 게이지, 별점 5개, 강화 종 10개, 계정 공유 재화·슬롯과 캐릭터별 진행의 구분이 최종 시안에 반영됐다. 담당 파일 6개만 작성했으며 v2, 통합 JSON, 타 담당 문서는 수정하지 않았다.

이 동의는 실제 전투 판정·생존 난이도·저장/결제 구현·모바일 터치·기기별 글자 읽기의 검증 완료를 의미하지 않는다. 이후 Unity 구현은 확정된 상태 소유권과 저장 프리팹 배치 계약을 따라야 한다.
