# 마지막 종지기 v4 — 자동 진행·유물 선택·필수 문구

작성일: 2026-10-21 KST  
상태: **planning-v4 JSON·HTML 최종 대조 완료, 기획 기준 동의. 필수 누락·수정 이견 없음.** UI 실제 렌더·플레이·실기기 검증 완료를 뜻하지 않는다.  
소유 파일: 이 문서만. `decisions.json`의 planning-v4와 `index.html`을 읽어 대조했으며 다른 파일은 수정하지 않았다. 기존 Unity 구조·게임 UI 스킬의 상태 소유권·필요 문구 원칙을 적용했다.

## 1. 이번 요구의 해석

- 회피 키는 화살표만 보인다. 위험 예고는 공간·궤적을 더 분명하게 보여 준다. 피해 숫자는 커지고 치명타는 더 크게 구분하되 다음 예고·체력·버튼을 가리지 않는다. 구체 크기·좌표는 UI 담당 명세로 정한다.
- 죽거나 자발적으로 귀환하거나 50층을 끝낼 때까지 자동 진행한다. **10층마다 정비·출발 확인을 요구하지 않는다.** 유물 선택 대기와 기존 일시정지·앱 중단은 이 흐름의 예외다.
- 로비 출전 버튼에 보이는 문구는 **`Stage {N}` 하나만**이며 선택 캐릭터의 다음 출발층을 뜻한다. `출전`을 별도로 병기하지 않고, 행동 설명은 접근성 읽기 이름에 둘 수 있다. 최고 기록이나 방금 죽은 층으로 표시하지 않는다. 지갑은 우측에 두고 계정 공용 골드·종파편을 표시한다.
- 골드가 모자라면 종파편→골드의 비용과 결과를 보고 교환 여부를 결정한다. 부족하다는 이유만으로 자동 교환·현금 구매하지 않는다.
- 유물 관리 화면은 왼쪽 약 1/3에 장착 상태·보유 목록, 오른쪽 약 2/3에 선택 유물의 효과와 장착 행동을 둔다. **전투 보상 3택1 화면과 로비 유물 관리 화면은 역할이 다르다.**
- 중간보스·보스를 처치할 때마다 세 유물 중 하나를 받는다. 새 유물은 보유 Lv.1, Lv.1~4 중복은 해당 유물 Lv.+1로 처리한다. 일반 중복의 골드 전환은 폐기하고, 이미 Lv.5인 MAX 카드에만 표시된 골드를 지급한다.

## 2. 멈춤·정산·다음 층 순서

| 사건 | 필요한 상태 전이 |
|---|---|
| 일반 적 처치 | 보상·클리어를 한 번 확정 → 기존 짧은 전환 → 다음 적 자동 진입. 결과 확인 버튼 없음 |
| 중간보스 처치 | 적의 예약 공격 종료 → 기본 골드·종파편 지급과 고정 세 후보·선택 대기 저장 → 전투 시계 정지 → 유물 선택 커밋 → 다음 적 자동 진입 |
| 10·20·30·40보스 처치 | 위 선택·커밋에 체크포인트·회복을 함께 처리 → 11·21·31·41층 자동 진입. 로비·`출발`·`계속` 화면 없음 |
| 50보스 처치 | 기본 재화 지급·세 후보 저장 → 유물 선택 확정과 완주·다음 회차 준비 커밋 → 계정 최초만 엔딩 → 로비. 이후 완주는 정산 뒤 바로 로비 |
| 사망·귀환 | 이미 확정한 보상은 유지 → 로비 → 해당 캐릭터의 마지막 10단위 체크포인트 다음 층에서 출전. 현재 적 미처치 보상 없음 |
| 보상 선택 중 앱 중단 | 같은 캐릭터·회차·처치 attempt·세 선택지를 복구. 선택지 재추첨이나 다음 층 선진입 없음 |

**통합 정산 계약에 동의:** 첫 단계는 처치 attempt에 대한 기본 골드·종파편 선지급과 고정된 세 후보·`보상 선택 대기`를 함께 저장한다. 두 번째 단계는 선택한 유물의 획득/Lv.상승 또는 MAX 골드 전환, 해당 선택 완료, 필요한 체크포인트·회복을 확정한다. 50층에서는 완주·다음 회차 준비도 두 번째 단계에 묶는다. 두 단계의 처리 여부를 구분해 복구하며, 후보 저장만으로 유물을 지급하지 않는다. 기본 재화는 선택 커밋에서 다시 지급하지 않는다. 저장 실패 시 같은 미결 결과를 재시도하고, 선택 커밋 성공 전 다음 적으로 진행하지 않는다.

**세 카드 모두 효과 전후를 보여 주고, 각 카드의 `선택` 버튼으로 바로 확정하는 안에 동의한다.** 별도 미리선택·`받기`의 2단계는 요구하지 않는다. 첫 유효 선택 입력을 받으면 선택 대상 ID를 고정하고 모든 선택 버튼을 저장 완료까지 잠가 중복 클릭을 막는다. 확정 뒤 추가 출발 버튼은 없다. 선택에 쓴 터치를 다음 전투의 공격·회피로 전달하지 않으며, 다음 적은 정상 진입 예고부터 시작한다.

선택 중에는 자동 선택 타이머·유료 재추첨·보상 포기 후 진행을 추가하지 않는다. 보상창을 닫거나 귀환해서 미결 보상을 넘길 수 없으며, 앱 종료는 같은 선택 대기로 복구한다. 선택 완료 후에는 기존 일시정지·귀환을 사용할 수 있다. 복구 시 이미 커밋한 결과면 다시 선택하지 않고 확정된 다음 상태로 이어 간다.

## 3. 유물 보유·레벨·출전 능력의 경계

- 유물 보유와 레벨은 계정 공용, 장착 구성은 캐릭터별을 유지한다. 새 유물은 자동 장착하지 않는다. 보상 화면은 획득만 확정하며 로비 장착을 대신하지 않는다.
- 현재 출전 캐릭터가 이미 장착한 유물을 중복으로 받으면, 선택 커밋 뒤 **다음 적 시작 전에 그 유물 효과만** 갱신한다. 캐릭터의 강화 레벨이나 다른 장착 구성을 함께 재선택하지 않는다.
- 미장착 유물의 Lv.상승은 보유함에만 반영한다. 다른 캐릭터의 진행·체크포인트·중단된 출전 능력을 즉시 덮어쓰지 않는다. 그 캐릭터가 새 출전을 시작할 때 최신 보유 레벨을 읽으며, 중단한 전투 복귀는 저장된 능력을 유지한다.
- **HP 처리 조정에 동의:** 현재 출전에서 장착한 체력 유물이 실제로 Lv.상승해 최대 HP가 늘면, 다음 적 시작 경계에 `nextHP = min(newMax, oldHP + max(0, newMax - oldMax))`를 한 번 적용한다. 최대 HP 증가분만 더해 잃은 HP 양을 유지한다. 기존의 현재 HP 고정 제안은 이 절충안으로 대체한다. 10·20·30·40층은 그 뒤 새 최대 HP까지 전회복한다.
- 같은 처치 결과를 재전송·재개해도 Lv.가 다시 오르지 않는다. 정상적으로 다시 싸워 처치한 보스는 새 선택 기회다.

보상 카드에는 유물 이름, `새 유물` 또는 `Lv.{현재} → {다음}`, 실제로 변하는 효과 수치를 보여 준다. 이미 장착 중인 유물에는 장착 상태를 표시해 다음 전투에 도움이 되는 선택인지 알 수 있게 한다. 전투 기절 표시는 계속 무텍스트로 유지한다.

## 4. 실제 화면에 남길 문구

아래는 사용자의 행동·필요 상태·거래 조건·복구에 필요한 목록이다. 표의 설명 열은 게임 화면에 넣지 않는다.

| 화면 | 문구·표현 | 표시 조건 |
|---|---|---|
| 전투 회피 키 | `▲` `◀` `▼` `▶` | 방향 이름을 키 안에 병기하지 않음. 접근성 읽기 이름은 별도로 제공 |
| 전투 공격·기절 | 검 아이콘, 종·막대·자세 | `공격`, `기절!`, `누적 +20`, `자동 진행 중` 같은 상시 설명 없음 |
| 피해 팝업 | 실제 피해 숫자 | 일반보다 치명타 숫자를 크게. 예고가 읽히는지 별도 시각 확인 |
| 최초 학습 | 강조한 화살표/검 아이콘, 필요한 순간의 `눌러 피하기` / `눌러 공격` | 첫 학습만. 회피 키 자체는 화살표만 유지 |
| 로비 | 캐릭터 이름, `Stage {N}`, 각 능력치·Lv.·강화 비용 | 출전 버튼의 보이는 문구는 `Stage {N}`만. 선택 캐릭터 기준, 지갑은 우측 실제 잔액 |
| 부족 골드 교환 | `종파편 {N} → 골드 {G}`, `교환 후 골드 {B}`, `교환`, `취소` | 필요한 교환량·가격을 실제 계산해 표시 |
| 교환 불가 | `종파편 부족` | 교환 버튼 비활성. 자동 현금 구매로 연결하지 않음 |
| 유물 보상 | `유물 선택`, 이름, `새 유물`/`Lv.{현재} → {다음}`, 효과 전후, 카드별 `선택` | 세 카드 모두 결과를 확인 가능. 해당 카드의 버튼 한 번으로 선택 확정 |
| 유물 관리 | 이름, `Lv.{N}`, 실제 효과, `장착`/`해제`/`교체` | 왼쪽 목록의 선택과 오른쪽 상세가 같은 유물을 가리킴 |
| 결과 저장 실패 | `저장하지 못했어요`, `다시 시도` | 같은 미결 결과에 재시도. 중복 보상 없음 |
| 귀환 | `귀환`, `Stage {N}부터 다시 시작`, `귀환`/`취소` | 진행을 끝내는 행동의 결과를 알릴 때만 |

교환 확정안은 **교환만 확정하고 원래 강화 화면으로 복귀**하는 것이다. 기존 `+`에서 시작했어도 추가 강화 비용까지 자동 지출하지 않는다. 사용자가 다시 `+`를 눌러 강화한다. JSON의 `confirmationOnlyExchanges=true`, `autoUpgrade=false`와 HTML의 150G 강화비·0G 보유 → 파편2개 교환 → 200G 보유 → 다시 강화 후50G 예시가 일치한다.

`이 화면에서는 유물을 관리합니다`, `계정 공용 인벤토리`, `다음 적부터 스냅샷을 갱신합니다`, `보상을 커밋합니다` 같은 설계·구현 설명은 화면에서 제외한다. 보상 후 별도의 `다음 층으로`, `출발`, `확인`을 추가해 자동 진행을 다시 끊지 않는다. 로비의 실제 출전 행동은 `Stage {N}` 버튼으로 제공한다.

## 5. 후속 합의로 확정한 정책

1. **세 후보·MAX 처리 후속안에 동의:** 전체 10종에서 균등하게 서로 다른 3종을 제시하고 Lv.5를 상한으로 둔다. 미보유는 Lv.1, Lv.1~4 중복은 Lv.+1이며, 이미 Lv.5인 카드만 구역별 20/40/60/80/100골드로 전환한다. MAX 카드는 선택 전에 `MAX · 골드 {G}`를 보여 준다. 일반 중복의 레벨 상승과 MAX 예외를 구별하고 같은 offer를 재접속으로 바꾸지 않는다.
2. **처치·선택 저장 경계 — 통합안 동의:** 기본 재화·고정 후보 선지급 저장과 유물·체크포인트·회복·50완주 선택 커밋을 구분한다. 앱 중단 시 같은 offer를 복구하고 이미 완료한 단계는 재지급하지 않는다. 같은 attempt는 한 번, 새 정상 처치는 매번 보상한다.
3. **능력 적용 시점:** 현재 출전의 장착 유물 성장만 다음 적에서 갱신하고 최대 HP 증가분을 한 번 적용한다. 캐릭터별 진행과 저장된 출전 스냅샷의 소유권을 유지한다. 50층은 보상 후 전투가 없으므로 다음 새 출전에 반영한다.
4. **교환 이후 행동:** 교환만 처리하고 다시 `+`로 강화한다. 거래 도중 지갑·강화 대상이 달라졌으면 낡은 견적으로 차감하지 않고 다시 확인한다.

## 6. 동의 판정

**일곱 요구와 제시된 자동 진행·유물 Lv.상승 방향에 동의한다.** v4에서 추가로 상점·유물 재추첨·체크포인트 출발 화면을 만들 필요는 없다. 첫 검증은 5층 선택→6층 자동 진행, 10층 선택→회복·체크포인트→11층 자동 진행, 보상 선택 중 중단/복구, 같은 결과 재커밋, 장착 유물 중복의 다음 적 적용, 개발용 50층 정산→엔딩/로비 경계로 한정한다.

5절은 통합된 저장·적용 정책이며 새 기능 요구가 아니다. **최종 v4 JSON·HTML의 기획 정합성 대조를 완료했으며 7절의 최종 동의가 앞선 통합 대기·조건부 표현을 대체한다.** 후보·수치·경제·화면 가독성의 실측은 각 담당의 후속 검증 범위다.

### HP·MAX 후속 절충안 동의 조건

2026-10-21. 총괄 전달안에 동의하며 아래 조건을 함께 적용한다.

- HP 증가분은 **현재 캐릭터가 장착한 유물의 유효 성장 1회당 한 번**만 적용한다. 카드 미리보기·미장착 유물·MAX 골드 전환·같은 결과 재처리는 회복을 만들지 않는다. 효과 상한 때문에 실제 최대 HP가 늘지 않았다면 회복도 0이다.
- 성장 전후 최대 HP와 적용 완료 상태를 해당 보상 결과·출전 능력 갱신에 연결한다. 중단·재접속 시 이미 적용된 증가분을 다시 더하지 않는다. 다른 캐릭터의 진행·중단 출전 HP와 능력은 바꾸지 않는다.
- 일반/중간 경계에는 증가분만 회복하고, 10·20·30·40에서는 그 뒤 체크포인트 전회복한다. 50은 유물 정산 후 출전을 종료하므로 전투를 새로 열지 않고 다음 출전에서 최신 효과를 반영한다.
- Lv.5 MAX 골드 전환은 **금액을 미리 알려 준 선택 보상**에 한정한다. Lv.1~4 중복의 골드 전환을 다시 도입하는 것으로 해석하지 않는다. 골드와 Lv.상승을 동시에 지급하지 않는다.

이 조건이면 체력 유물의 성장 보상을 즉시 체감시키면서 같은 성장의 반복 회복을 막을 수 있다는 설계 판단이다. 실제 생존량·선택 편중은 전투·경제 검증에 남긴다.

### 로비 문구·1회 선택·2단계 정산 후속 동의

`Stage N` 단독 버튼, 효과 전후가 보이는 카드별 `선택` 직접 확정, 기본 재화·후보 선지급 저장 후 선택 커밋이라는 총괄 통합안에 동의한다. 앞선 미리선택+받기 및 일괄 정산 제안은 이 계약으로 대체했다. 선택 입력 소비·저장 중 전체 선택 버튼 잠금·재개 시 단계별 중복 지급 방지가 충족되면 추가 확인 화면 없이 요구를 만족한다.
