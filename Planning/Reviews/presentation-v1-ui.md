# 전투 연출 v1 — UI·가독성 검토

2026-10-21 KST. **기획·오프라인 시안 검토 완료. Unity·GameData에는 적용하지 않았다.** `game-ui-wireframe-copy` 스킬에 따라 실제 저장 프리팹·코드·기존 실행 캡처를 확인하고, 변경 시안의 공간과 상태 규칙을 정리했다. 아래 새 좌표·연출 규칙은 제안이며 실기기에서 검증한 수치가 아니다. 최종 보완 수치는 문서 마지막 절이 앞의 최초 출발값을 대체한다.

## 확인 근거와 현재 문제

- `Client/Assets/Game/Prefabs/GameView.prefab`: 실제 Canvas 기준 960×540, Danger 120×130, NextDanger 138×146, 회피 입력면 72×72, 발밑 HP 80×8. 1280×720 기획 보드는 이 기준을 4/3배로 환산한다. 런타임 해상도를 이미 1280×720으로 바꾼 것이 아니다.
- `Runtime/Presentation/DangerGraphic.cs`: 위 가로 꺾임, 아래 지그재그, 좌우 꺾쇠를 선 메시로 표현한다. 공간적 위험과 진행 접점은 읽히지만 주변의 픽셀 인물·황동 장식과 형태가 다르다. 좌우 꺾쇠는 회피 방향키와 닮아 위험 위치와 정답 방향을 혼동할 수 있다.
- `Runtime/Presentation/MvpPresenter.cs`: 위험 위치는 플레이어의 기본 발 기준 위 53 reference px에 표시한다. `EnemyIntent`를 읽으며 상단 위험→아래 회피, 하단 위험→위 회피, 앞 위험→뒤 회피, 뒤 위험→앞 회피를 사용한다. 이 계약을 유지한다.
- `Art/MvpArtCatalog.asset`, `GameData/mvp-catalog.json`: 3층·7층 `ash_wisp`(재의 불씨)의 현재 전체 높이는 1.0, 온은 1.1, 다른 일반 적은 1.5, 중간 보스는 1.8, 보스는 2.1이다.
- 직접 본 기존 실행 이미지: `Planning/Evidence/Unity/Smoke/03-stage-1.png`, `dodge-back.png`, `06-boss.png`, `Planning/Evidence/Unity/Smoke640/03-stage-1.png`. 실제 파일의 기존 예고·발밑 HP·보스 HP·조작 영역을 확인했다. 이 이미지들은 새 시안을 검증한 이미지가 아니다.

## 공동 기획 의견

아트 담당과 **재의 불씨 1.0→1.5(+50%)**, 예고 **금 간 종의 잔향**, 삼각 화살촉 제거에 동의했다. 1280×720·카메라 orthographic size 3.1을 유지하면 재의 불씨는 약 174px 높이로, 온 약 128px보다 크고 중간 보스 약 209px·보스 약 244px보다는 작다. 전체 스프라이트 기준이며 몸통만의 면적이나 실측 새 렌더를 뜻하지 않는다.

확대는 HP 아래 위치나 피격 판정의 확대로 이어지지 않는다. 공격·기절 포즈에서도 같은 기준 스케일을 사용한다. 기절 별은 고정 발 위 150 reference px 대신 **해당 적의 기준 머리 위 24px(1280 보드 기준)**에 둔다. 그래야 큰 보스의 상체 위에 별이 겹치는 일을 줄일 수 있다.

전투 연출 담당이 제안한 일반 처치 1.40초, 사망 1.80초, 중간 보스 첫 등장 1.40초·보스 첫 등장 1.80초 및 최대 줌 1.12배·1.18배는 기획 시작값으로 수용한다. 실제 재미·멀미·반복 피로 검증은 구현 후 필요하다.

## 1280×720 공간 명세

좌상단 원점, `[x, y, width, height]`, Safe Area 인셋이 0인 16:9 시안 기준이다. 플레이어 기본 발 `P=(548,590)`, 적 발 `(808,590)`, 지면 윗선 약 `y=600`. 월드에 표시할 것은 실제 투영된 기본 발 P를 anchor로 사용하며 회피 포즈·공격 돌진·카메라 흔들림을 따라 움직이지 않는다.

| 요소 | bounds / 규칙 | anchor |
| --- | --- | --- |
| 상단 위험 | `[480,438,136,12]` | P + `(-68,-152)` |
| 하단 위험 | `[480,564,136,12]` | P + `(-68,-26)` |
| 앞 위험 | `[628,478,12,72]` | P + `(80,-112)` |
| 뒤 위험 | `[440,466,40,92]`, 오른쪽 열림 | P + `(-108,-124)` |
| 다음 위험 | 같은 형상의 바깥쪽으로 12px: 상 -Y, 하 +Y, 앞 +X, 뒤 -X | 현재 위험과 같은 P |
| 밝은 핵 / 활성 선 | 핵 8×8, 활성 선 6~8, 암청 외곽 2 | 예고 궤적 |
| 플레이어 HP | `[495,601,106,11]` | 기본 발 아래 |
| 일반 적 HP | `[755,601,106,11]` | 적 기본 발 아래 |
| 중간 보스·보스 HP | 기존 상단 긴 바 유지. 대략 `[213,36,928,21]` | Safe Area 위 좌우 stretch |
| 회피 입력면 | 각 96×96. ▲ 중심 `(200,421)`, ◀ `(93,528)`, ▼ `(200,635)`, ▶ `(307,528)` | Safe Area 좌하단 |
| 회피 그림 | 약 53×53, 배경 없음 | 입력면 중심 |
| 공격 입력면 | 약 `[1117,565,134,118]` | Safe Area 우하단 |
| 일시정지 | 96×96, 우상단. 연출 중에도 접근 가능 | Safe Area 우상단 |

예고는 raycast를 받지 않는다. 회피키의 투명 입력면이 겹치지 않아야 한다. 다음 하단 예고의 끝 y=588과 HP 상단 y=601 사이에는 약 13px 여백이 남는다. 캐릭터가 점프하거나 앞으로 회피할 때 일시적으로 예고 영역을 통과할 수 있으므로 예고 외곽과 접점을 캐릭터보다 앞에 그린다. 예고의 anchor를 점프하는 몸체에 옮기지는 않는다.

피해 팝업의 기본 크기는 기존 일반 약 200×47, 치명타 약 261×67(1280 환산)을 유지한다. 플레이어 피해 숫자는 중심 x=548, y=332~404 범위, 적 피해 숫자는 중심 x=808, y=244~314 범위를 시작 레인으로 삼는다. 숫자는 위로만 떠오르며 위험 예고 띠 안으로 내려오지 않는다. 치명타 장식도 이 bounds 안에 둔다. 같은 대상의 동시 팝업은 가로·세로 중첩을 피하는 슬롯으로 분리하고, 종 게이지·보스 HP·기절 별과도 겹치지 않는지 다시 본다. 작은 화면에서 숫자만 크게 늘려 경고를 가리는 방식은 피한다.

## 작은 화면과 안전 영역

640×360 시안에서는 좌표를 절반으로 환산하되, 예고 핵은 최소 4×4, 활성 선 3~4, 암청 외곽 최소 1, 현재/다음 간격 최소 6px로 유지한다. 회피 입력면은 최소 48×48px이며 이는 캡처 픽셀 기준이다. 실제 모바일 48dp 충족 여부는 화면 밀도와 Safe Area를 포함한 기기에서 별도 확인한다.

19.5:9 등 넓은 화면은 배경을 좌우로 확장하고, 전투 카메라의 세로 구도를 유지한다. 고정 화면 절대좌표로 예고를 붙이지 않고 투영된 P 기준을 사용한다. 노치로 왼쪽 조작 영역이 안으로 밀리면 **회피 입력면 오른쪽 끝과 다음 예고의 왼쪽 끝 사이 최소 24px(1280 기준)**를 다시 확보한다. 부족할 때에는 전투 구도의 기준점을 안전한 중앙 공간으로 조정하고 입력면은 줄이지 않는다. 사망 후 로비·유물 선택·일시정지 같은 조작 화면은 새 연출이 끝난 후 완전한 밝기에서 검수한다.

## 시간과 상태

현재 카탈로그의 단발 650ms, 연타 전체 예고 900ms, 후속 강조 250ms, 최소 타격 간격 450ms를 유지한다. UI는 `EnemyIntent`의 단계와 진행률을 표시한다. 예고 그래픽 자체의 재생 시간이 전투 판정을 만들거나 250ms 뒤에 별도 여유를 붙이지 않는다. 후속은 이미 보인 다음 레인에서 현재 레인으로 강조가 넘어간다.

| 상태 | HUD·입력 규칙 |
| --- | --- |
| 적 처치·분해 | 새 공격 예고와 종 게이지 강조 중단. 마지막 피해 숫자는 짧게 마무리하고 HP 0 상태를 본 뒤 적과 함께 제거. 전투 입력 비활성 |
| 전진·다음 적 정착 | Stage와 일시정지만 고정. 주인공은 앞으로 달리지만 회피·공격 입력을 쌓지 않음. 정착 뒤 입력 활성과 온전한 첫 예고 시작 |
| 중간 보스·보스 등장 | 카메라는 월드만 줌. HP·조작 UI를 확대하지 않음. 예고·종 게이지는 숨김. 마지막 줌 복귀·정착 구간에서 보스 HP를 실제 최대값 상태로 페이드인. HP가 가짜로 차오르는 연출 금지 |
| 보스 처치 후 보상 | 분해가 끝난 뒤 3개 유물 선택 표시. 선택 확정 후 전진. 선택 화면 동안 카메라·배경 흔들림 없음 |
| 플레이어 사망·암전 | 즉시 입력과 위험 예고 중단. 플레이어의 조각이 사라지며 화면이 어두워짐. 새 전투 입력·로비 입력 모두 비활성 |
| 등불·로비 노출 | 등불에서 주변으로 따뜻한 빛이 넓어짐. 재화·스탯·Stage가 최종 위치에서 드러남. 글자는 흔들거나 도트로 분해하지 않음. 완전히 읽히는 밝기에서 버튼을 한 번에 활성 |
| 일시정지·앱 복귀 | 전환 연출도 멈춤. 복귀 시 몰아서 진행하거나 바로 타격하지 않음. 저장 복원 위치는 전투 연출 담당의 상태 계약을 따름 |

입력 잠금 구간에 누른 터치·키보드와 누르고 있던 버튼은 버퍼에서 폐기한다. 전투 조작이 열린 뒤 **새로 누른 입력**부터 받는다. 등장 연출 중 눌렀던 공격이 즉시 발동하거나 남은 회피 무적 시간이 첫 타격에 적용되는 것을 막는다.

## 감소 모션·무음

- 감소 모션은 줌·횡스크롤·화면 흔들림을 제거한다. 다음 적 전환은 고정 구도의 짧은 디졸브, 사망은 고정된 도트 소멸과 조명 전환으로 대체한다. 단순 감소 모션 설정이 전투 예고·판정 시간을 줄이지 않는다.
- 괴성은 소리만으로 시작을 알리지 않는다. 보스가 상체를 펴거나 머리를 들고, 입·가슴에서 낮은 횟수의 각진 파동이 생긴 후 정착한다. 무음·진동 꺼짐에서도 같은 시작 시점을 읽을 수 있다.
- 등불은 반복 점멸보다 한 번 켜진 뒤 천천히 밝아지는 연출로 한다. 전체 화면 백색 섬광은 쓰지 않는다. 감소 모션에서 조각은 낙하 거리·개수를 줄여 사라지게 하되 로비의 숫자·버튼 가독성을 우선한다.
- HUD는 camera zoom과 world shake 대상에서 분리한다. 감소 모션과 별개로 기존 치명타 흔들림 감소 선호를 보존하는 통합 방안은 구현 전에 정한다.

## 검수 기준과 남은 일

기획 보드에서 1280×720·640×360, 위험 4종, 현재/다음 동일·반대 위치, 확대된 재의 불씨의 대기·공격·기절, 피해 팝업 5자리·치명타, 첫 보스·재조우, 무음·감소 모션을 확인한다. 화면 내부에는 실제 게임 문구만 넣고 설명·시간·정답은 보드 외부 주석으로 둔다.

이 문서는 기존 실행 화면을 대조한 기획 검토다. 새 디자인의 Unity 렌더·실제 250ms 가독성·터치 편의·카메라 연출의 멀미·반복 피로가 통과했다는 뜻은 아니다. 새 보드가 완성되면 UI 담당이 직접 열어 제안 bounds와 실제 그려진 형상·레이어·작은 화면을 재검토한다.

## 오프라인 시안 1차 검토

`Planning/Presentation/index.html`, `app.js`, `proposal.json`을 대조하고 `Planning/Evidence/Presentation/`의 `warning-directions.png`, `warning-next.png`, `warning-mono.png`, `wireframe.png`, `scale-comparison.png`, `sequence-storyboard.png`, `death-1800.png`를 직접 열었다. 이는 **오프라인 Skia 렌더 이미지** 검토다. 브라우저는 file URL 정책으로 자동 열기가 제한되어 있었으며 다른 브라우저 경로로 우회하지 않았다. 브라우저 레이아웃·입력 조작 검증은 하지 않았다.

크기 비교에서 재의 불씨가 온보다 작은 문제를 해소하면서 중간 보스보다 낮은 체급을 유지함을 확인했다. 흑백 배치의 조작 입력면과 캐릭터·상단 예고에는 겹침이 없었다. 분해→전진, 암전→로비, 보스 확대→복귀의 장면 흐름도 이미지로 구분된다. 달리기 프레임과 괴성 음원은 제작 전인 시간 모형이다.

다음 사항을 총괄·아트·전환 담당에게 수정 요청했다.

1. 현재 예고의 6px 낱개 도트가 작은 화면에서 사슬 같은 점선으로 보여 다음 예고와 차이가 약하다. **현재는 황동 10px 띠의 약 90%를 연결하고 국소 균열만 두며, 다음은 4×4·간격16px 점선**으로 구분하도록 아트 담당과 합의했다. 핵은 12×12로 키우고 암청 외곽을 포함한 16×16까지 여백을 잡는 안을 권고했다.
2. 핵을 키울 경우 하단 두 레인의 외곽이 붙을 수 있다. 다음 예고 이격 16px, 하단 bounds y=560으로 4px 올리는 보완안을 권고했다. 본문 초기 8px 핵·12px 이격 값은 1차 출발값이며 최종 제안 JSON과 재렌더에서 변경 여부를 확인한다.
3. `death-1800.png`의 등불이 체력 수치와 별을 덮는다. 등불과 빛의 원점을 **(520,130)**으로 함께 옮기면 캐릭터 미리보기 위 빈 공간을 사용하며 스탯 패널·NG+ 문구를 가리지 않는다.
4. 오프라인 렌더의 일시정지 박스 안 `Ⅱ` 글리프가 보이지 않는다. 글꼴에 의존하지 않는 두 개 세로 막대로 표시하도록 권고했다.
5. 소스 비교에서 현행 상단 예고 재현의 첫 점 Y 부호와 Stage 4 다음 적·첫 예고가 실제 카탈로그와 다르다. 비교 시안 왜곡을 피하도록 수정 요청했으며, 전환 담당도 Stage 4 항목을 독립 발견했다.

위 보완을 반영한 이미지를 확인하기 전에는 새 예고 가독성·등불 로비를 최종 통과로 표시하지 않는다.

## 보완 후 최종 오프라인 검토

총괄이 갱신한 `warning-directions.png`, `warning-next.png`, `warning-mono.png`, `death-1800.png`, `normal-1400.png`를 같은 경로에서 다시 직접 열었다. `proposal.json`, `app.js`, `index.html`, `design-spec.md`도 대조했다.

| 보완 | 최종 확인 |
| --- | --- |
| 현재 예고가 작은 사슬점선으로 보임 | 현재는 10px의 이어진 황동띠·국소 균열, 밝은 접점 12×12·외곽16×16이다. 4방향 합성 이미지의 640×360 패널에서도 위치·형태를 구분할 수 있다. |
| 현재/다음 구분 | 다음은 4×4 점, 중심 간격16px, 현재에서 바깥16px이다. 흑백 C형 비교에서 연속 띠와 성긴 점선을 구분했다. |
| 하단 경고와 HP | 하단 bounds `[480,560,136,12]`를 채택했다. 접점 외곽은 기준 슬롯보다 양쪽2px 넘을 수 있다는 `boundsNote`도 확인했다. 새 다음 예고와 HP 사이의 공간이 남아 있다. |
| 로비 등불의 체력 글자·별 가림 | 등불과 빛의 원점 모두 `(520,130)`으로 옮겨졌다. 완전 공개된 이미지에서 스탯·NG+·캐릭터 미리보기를 가리지 않는다. |
| 일시정지 식별 | 글꼴 글리프 대신 2개의 세로 막대가 보인다. |
| 비교·연결 오류 | 현행 상단 예고 재현의 Y 부호를 수정했고, `normal-1400.png`가 Stage 4 파수병과 후방 원호 예고를 표시한다. |

최종 작은 화면 출발값은 **핵 6×6, 활성 띠 5, 다음 점 2×2·간격8, 레인 이격8px(640×360)**이다. 초기 본문의 핵4·띠3~4·이격6 값을 이 수치로 대체한다. 다음 금점4/간격16은 실제 금색 점유율25%이며, 외곽까지 포함한 크기와 혼동하지 않도록 총괄에 비율 대신 픽셀 크기·간격 표기를 권고했다.

확인한 이미지 범위에서 앞선 필수 가독성·로비 가림 수정은 해소됐다. **시각 기획안으로 수용**한다. 브라우저의 실제 레이아웃·슬라이더·키보드 조작, 모바일 터치, 실제 게임의 250ms 예고 인지, 노치 Safe Area, 실행 중 5자리 피해 숫자·기절 별 동시 충돌은 아직 검증하지 않았으며 구현 후 검수 대상이다. 새 보스 포효·달리기 모션과 음원 역시 완성 자산이 아니다.
