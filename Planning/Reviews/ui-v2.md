## 3. 방향3회피와1회피 비교

| 항목 | 위/뒤/아래 + 공격 | 피하기 + 공격 |
|---|---|---|
| 주요 판단 | 공격 높이·사거리 + 시점 + 연속타 순서 | 공격 시점·연속타 순서 |
| 기대 이점 | 뛴다/숙인다/물러선다의 실제 동작 변화. 한 버튼의 반복감 개선 후보 | 초반 학습이 빠르고 시간 판정·기절 보상을 따로 검증하기 쉬움 |
| UI 비용 | 네 입력과 세 자세, 위험 위치와 동작의 연결, 오입력·손 피로 확인 | 큰 회피 버튼 하나. 방향 실패를 구분할 필요가 적음 |
| 주요 반론 | 정답 화살표 따라 누르기·버튼 찾기·대각선 오입력이 재미를 대신할 수 있음 | 기절 숫자가 추가돼도 같은 행동의 단조로움이 남을 수 있음 |
| 이 시안 | 좌하단 3개 분리 버튼, 우하단 공격. 스와이프 없음 | 같은 전장·같은 기절·같은 공격 버튼, 좌하단 회피만 하나로 교체 |

**우선순위는3방향 시험이며 확정 우월 판정은 아니다.** 같은 적, 예고, 시간값, 피해, 기절량, 강화/유물을 고정한 비교가 필요하다. 1버튼 조건은 시간만 맞으면 피하고, 3방향 조건은 방향도 맞아야 피한다. 두 조건의 보상·연출까지 동시에 바꾸지 않는다.

### 방향 의미

- `위`: 낮은 휩쓸기를 짧게 뛰어넘는다.
- `아래`: 머리/상체 높이의 공격에 몸을 숙인다.
- `뒤`: 사거리가 보이는 가까운 공격에서 물러선다. 모든 공격을 피하는 만능 방향으로 만들지 않는다.
- 종지기는 왼쪽, 적은 오른쪽을 기본 대치로 유지한다. `뒤`는 종지기의 뒤이며 화면 반대편에서 임의로 의미가 바뀌지 않는다.
- 버튼은 플레이어의 동작, 예고는 **적의 위험 위치**다. 방향 화살표가 위험의 출발점인지 정답인지 혼용하지 않는다.
- 첫 안내만 `위로 피하기`를 보여 준다. 일반 전투는 낮은/높은 위험 궤적과 적의 준비 자세를 사용한다.

현재 시안의 뒤 회피는 통합 전투의 `찌르기`에 대응한다. 실제 자산에서는 뒤로 물러나야 피할 수 있는 사거리·폭을 보여 준다. 위/아래로도 물리적으로 피할 것처럼 보이는데 게임이 틀렸다고 판정하는 그림은 피한다. 이는 구현 검증 기준이며 기획 확정을 막는 미결 선택이 아니다.

회피 입력은 PointerDown 1회다. 회복 중 입력을 예약·갱신하거나 세 버튼을 누른 상태에서 자동 정답을 골라 주지 않는다. 같은 시각 여러 방향의 우선순위는 전투 계약으로 고정하고 기록한다. UI 이벤트 호출 순서에 맡기지 않는다. 길게 누르기·스와이프·방향별 독립 쿨타임은 초기 비교에 추가하지 않는다.

## 4. 가로 좌표·안전 영역·낮은 지면

### 기준

| 화면 | 논리 크기 | 발 접지선 | 높이 비율 | 회피/공격 |
|---|---:|---:|---:|---|
| 기준16:9 | 960×540 | y444 | 82.2% | 회피64×64, 공격96×88 |
| 긴20:9 | 1200×540 | y444 | 82.2% | 동일 크기, 가운데 전장 여유 증가 |
| 최소16:9 | 640×360 | y296 | 82.2% | 회피56×56, 공격80×72 |

이 값은 출발 배치다. 안전 영역은 `(L,R,T,B inset)` = `(0,0,0,0)`, `(24,24,12,12)`, `(44,32,16,16)`으로 검사한다. 실제 기기의 노치/카메라/제스처 크기를 측정했다는 뜻이 아니다.

전체 화면 좌상단을 원점으로 하고, `L=왼쪽 inset`, `R=W-오른쪽 inset`, `T=상단 inset`, `B=H-하단 inset`으로 정의한다. UI 좌표는 SafeArea root를 기준으로 저장한다. `TL/TR/T`는 안전 영역 상단 모서리/중앙, `BL/BR/B`는 하단 모서리/중앙, `C`는 안전 영역 중앙이다. 월드 지면은 전체 높이 기준이며 상단/하단 인셋에 따라 위아래로 출렁이지 않는다.

### 실제 주요 bounds

표는 `x,y,width,height`. 기본960은 L24/R24/T12/B12, 최소640은 L44/R32/T16/B16의 사례다.

### 손가림과 움직임 범위

검토용 엄지 위험 영역은 버튼 영역보다 크게 잡았다. 기본960에서는 왼쪽 `[0,348,204,180]`, 오른쪽 `[784,352,176,176]`; 최소640에서는 왼쪽 `[0,180,208,164]`, 오른쪽 `[464,176,176,168]`이다. 이는 **가정한 영역**이지 실제 손가락 측정치가 아니다.

중앙의 인물·공격 예고·회피 동작 범위는 이 두 영역과 겹치지 않는다. 최소 화면의 뒤 이동40, 위 이동40 논리 단위까지 포함한 범위도 검사한다. 기본 화면의 뒤 이동64·위 이동96은 설명용 동작 범위다. 애니메이터가 이 범위 밖으로 무기·머리·발을 내보내면 다시 검토해야 한다.

발과 낮은 공격 궤적은 중앙 y296/444에 있어 모서리 버튼 아래에 깔리지 않는다. 화면을 낮췄다는 이유로 주인공을 왼쪽 가장자리로 밀지 않는다. 더 긴 화면은 가운데 전장 폭을 늘리고 HUD와 버튼 크기는 유지한다. 최소 화면은 장식·캐릭터 도트 배율을 조정하며 메뉴 글자·입력 영역을 일괄 축소하지 않는다.

각 메뉴는 상단 제목/잔액, 중앙 두 패널, 하단 주 행동으로 구성했다. 유물 목록이 늘면 목록 영역만 스크롤하고 장착/확장/닫기 동선은 고정한다. 이 시안은 목록 두 항목을 보이는 상태로 표현하며 전체6종 생산을 완료한 자료가 아니다.

## 5. 기절·회피·빠른 연속 입력 표시

통합 기준의 초기 설계값을 표시 계약으로 반영했다. 원작의 수치를 측정한 것이 아니며 실제 기기에서 공정한 값으로 검증한 것도 아니다.

| 상태 | 표시 | 처리 계약 |
|---|---|---|
| 일반 회피 성공 | 짧게 `회피 +20`, 적 기절 막대 증가 | 방향과 시간 모두 유효할 때. 기절량은 세션 판정값 |
| 완벽 회피 성공 | `완벽 +40`, 형태/짧은 효과 차별 | 완벽60ms는 일반160ms 판정 안의 부분집합. 색·소리만으로 차별하지 않음 |
| 회피 복귀 중 | 세 회피 버튼 모두 일관되게 비활성, 이름/위치 유지 | 판정160+회복100=260ms 초기값. 회복 중 예약/무적 갱신 없음 |
| 연속 공격 | 남은 타격 점 + 현재 위험 높이/사거리 | 최소450ms 초기값. 앞 회피 종료 뒤 다음 동작을 읽고 누를 여유를 실측 |
| 피격 | 짧게 `피격 -20`, 적 누적 감소 | 0미만 없음. 모든 누적 소멸 표시를 잘못 사용하지 않음 |
| 적 기절 | 같은 막대 자리를 `기절 · 1.2초` 등 남은 시간으로 전환, 적 멈춤 | 누적100에서 즉시 발동, 패턴/예정 타격 취소, 초과분 폐기. 중간보스 표본1.2초 |
| 기절 종료 후 저항 | 같은 자리에 `기절 저항 · 2.0초`, 누적 불가 형태 | 기절 중/종료 후2초 축적0. 지속시간 연장 없음 |
| 다음 적·이탈 | 해당 적 게이지 초기화 | 시간 경과 누적 감소는 없음. UI가 임의 초기화하거나 보존하지 않음 |

기절 중 일반 공격은 자동 피해×1.40이며 별도 스킬 버튼을 만들지 않는다. 공격 버튼만 강조한다. 상단/하단에 추가 “울림 충전” 아이콘이나800ms 타이머를 병렬로 유지하지 않는다.

HP는 생존/적 격파 정보, 기절 막대는 공격 기회 누적이므로 두 개의 의미를 분리한다. 기절 상태 세 종류(누적/기절/저항)는 **한 자리**를 교체한다. 세 개의 막대를 늘어놓지 않는다. 세션이 값·종료 시각·중단 상태를 소유하고, UI는 표시만 한다.

완벽/일반 회피 피드백과 새 공격 예고가 겹치면 **새 공격 예고가 우선**이다. 회피 성공 문구를 오래 띄우느라450ms 뒤 공격을 덮지 않는다. 시안의 선택 상태는 정지 화면이며450ms 입력·시간 흐름을 실행하지 않는다.

## 6. 화면 흐름과 진행

```text
로비/스테이지 선택 → 현재 스테이지 전투 → 결과
                                    ├ 실패 → 같은 스테이지 다시 도전
                                    ├ 돌파 → 다음 스테이지
                                    ├ 5단위 → 강화/유물 정비 선택
                                    └ 30돌파 → 기록 확정·첫 엔딩 → 로비
로비 ⇄ 강화(공격/체력) ⇄ 출전
로비 ⇄ 유물 목록/장착 → 슬롯 확장 확인
로비 ⇄ 새벽석→골드 교환 확인 → 완료/부족/확인 중/실패
```

- 진행은 스테이지별 저장하며 실패 때문에1부터 다시 시작시키지 않는다.
- 각 전투는 HP가득 시작한다는 최신 기준을 반영한다. 결과의 실패 원인은 실제 입력·판정 기록으로 알 때만 한 줄 표시한다.
- 5/15/25는 중간보스, 10/20/30은 보스다. 여섯 지점에서 지정 유물1개씩을 받으며, 5단위는 정비할 기회다.
- 스테이지 숫자와 공격/체력 레벨은 별개다. `스테이지10 도달=강화Lv10`으로 표시하지 않는다.
- 실패 자체는 처치 보상0, 이전에 확정한 보상은 유지한다. 표본 결과는 일반4단계40G, 중간5단계120G, 보스10단계200G, 최종30단계500G를 사용한다. 새 유물과 중복 골드는 함께 주지 않는다.
- 30돌파 뒤 `다음 스테이지31`을 표시하지 않는다. 첫 엔딩은 기록/진행 확정 뒤1회, 건너뛰기·설정 무료재생으로 제안한다.
- 전투 중 성장·장착을 바꾸지 않는다. 전투 시작 시 확정한 능력치/유물로 한 전투를 진행한다.

## 7. 강화·유물·교환 표시 계약

### 강화

최종 기준은 **공격·체력 각각Lv.1~30**이다. 각 패널에 현재→다음 수치, 해당 레벨, 비용, 강화 버튼을 둔다. 9→10 표본은 `돌파`를 함께 표시해 단순+1과 큰 성장을 구별한다. 공격Lv10과 체력Lv10을 하나의 캐릭터Lv10으로 잘못 합치지 않는다.

비용은 각 능력치의 목표레벨2~9:20G, 10:60G, 11~19:40G, 20:120G, 21~29:60G, 30:180G다. 시안은9→10의60G를 표시한다. 시작은 **0G/0D**이며 로비 첫 시작 상태에 반영했다. 강화의 보유골드200·부족50은 나중 시점의 독립 표본이다.

공격14.22→18.58, HP132→164는 통합 성장식의 각 능력치9→10 표시값이다. 내부 소수값과 표시 반올림을 구분한다. 해당 능력치만 올리며 다른 능력치까지 같이 상승하거나 비용을 두 배 청구하지 않는다.

### 유물·슬롯

미보유는 획득 위치를, 미장착은 효과와 장착 행동을, 장착 중은 해제를 표시한다. 슬롯 가득 참은 “미보유”와 다른 상태다. 첫 유물을 받은 뒤 기본 슬롯1개에 바로 장착할 수 있어야 한다.

최종 기준:

| 확장 | 진행 조건 | 새벽석 | 표시/미달 상태 |
|---|---|---:|---|
| 1→2 | 10스테이지 완료 | 20 | 진행 미달은 조건을 보여 줌. 조건 충족 후에는 비용·잔액 확인 |
| 2→3 | 20스테이지 완료 | 40 | 세 번째 잠금은 두 번째와 별개.2슬롯 보유를 먼저 확인 |

10/20보스가 여는 것은 **구매 조건**이다. 직접 확인해 새벽석을 사용하며 자동 무료 확장·자동 차감으로 표시하지 않는다. 새벽석은 현재 현금 판매하지 않는 인게임 재화다. 지급·장착은 안정 유물ID로 저장하고 중복 ID를 여러 슬롯에 넣지 않는다.

유물6종의 최신 통합 효과를 시안에 반영했다. 이름은 가제다.

| ID / 드랍 | 이름 | 표시 효과 | 상한/구분 |
|---|---|---|---|
| relic_05 / 5 | 재의 고리 | 공격력 +8% | 합산 공격 증가20% |
| relic_10 / 10 | 새벽의 조각 | 최대 체력 +12% | 합산 HP 증가25% |
| relic_15 / 15 | 사슬 종추 | 일반 누적 +25%, 20→25 | 일반만, 증가 상한25% |
| relic_20 / 20 | 맑은 종추 | 완벽 누적 +25%, 40→50 | 완벽만, 증가 상한25%. 일반과 이중 지급 없음 |
| relic_25 / 25 | 종망치 파편 | 기절 피해 배율1.4→1.5 | 배율 상한1.5 |
| relic_30 / 30 | 새벽의 장막 | 받는 피해8% 감소 | 합산 감소15%, 최종 피해 최소1 |

보유함은6종 모두 보관하며 장착만1~3칸으로 제한한다. 슬롯 부족 때문에 보상 유물을 버리지 않는다. 중복은 구역별20/40/60G로 전환하고, 신규 유물과 중복 전환 골드는 동시 지급하지 않는다.10보스 재처치 표본은 처치골드200 + 중복골드20 + 새벽석2를 구분해 표시한다.

### 재화 교환

고급 재화 명칭은 **새벽석**, 강화 재화는 **골드**다. 장식 조각은 사용하지 않는다. 여섯 중간/보스 첫 처치각15, 재처치각2다. 첫15는 최초13+반복2를 합한 수치이며17로 잘못 지급하지 않는다.

교환은 `새벽석5 → 골드100`. 확인창에 소모량, 받을 양, 교환 후 새벽석, 다음 슬롯 가격과 진행 조건을 함께 표시한다. 보스 재처치로 새벽석2를 얻는 경로도 표시한다. 잔액을 슬롯용으로 강제 예약하거나 교환을 막지 않는다. 재화가 충분하고 유저가 확인하면 선택할 수 있게 한다.

새벽석 현금 판매는 현 기준에서 보류한다. 현금 가격처럼 `₩`를 붙이지 않으며 교환과 현금 구매를 같은 버튼으로 숨기지 않는다. **공격·체력이 모두30이면 골드 교환을 숨긴다. 모든 슬롯까지 열렸으면 새벽석 광고도 숨긴다.** 두 조건을 혼용하지 않고 보유 잔액은 보존한다. 외형 결제 상품을 붙이는 단계에는 실제 스토어 가격·구매 pending/복원 계약을 별도 연결한다.

### 오류·저장 원칙

- 진행/처치 보상/첫 유물/중복 전환은 동일 전투 결과ID에 한 번만 확정한다.
- 강화는 레벨·능력치·골드 차감, 슬롯 확장은 개수·새벽석 차감, 교환은 양쪽 재화를 하나의 거래로 확정한다.
- pending 창을 닫았다는 이유로 실패 처리하거나 같은 거래를 다시 허용하지 않는다. 보유량은 확인되지 않은 지급을 포함하지 않는다.
- 미보유·슬롯 꽉 참·진행 잠금·재화 부족·저장 실패는 서로 다른 상태다. 모두 `오류` 하나로 뭉개지 않는다.
- 저장에 실패하면 재시도/닫기/재도전 같은 복구 행동을 제공한다. “앱을 꺼도 보상이 보존된다”는 약속을 구현 없이 쓰지 않는다.
- 앱 복귀·일시정지에서 입력을 해제하고 전투 시계·기절 남은 시간을 세션 계약대로 복구한다.

## 9. 컬러 저해상도 배치 시안의 범위

색 역할은 짙은 남색 배경, 푸른 중간톤 구조물, 밝은 크림 인물/UI, 주황 위험·기절 강조의4개 기본값이다. 일반 배경이 가장 밝은 인물·예고보다 먼저 눈에 띄지 않게 한다.

주인공은16×24 격자형 도형, 적은24×36 임시 도형을 기본 화면에서4배, 최소에서2배로 표시했다. 이것은 형태·지면·빈 공간 검토용이며 최종 보스 해상도나 생산 프레임 수를 확정한 것이 아니다. SVG의 글자는 한글 가독성을 위해 별도 해상도로 렌더한다. 텍스트 안티앨리어싱 때문에 출력 래스터가 정확히4색이라는 뜻도 아니다.

낮은 공격은 지면 가까운 수평 띠, 높은 공격은 상체 높이 띠, 찌르기는 사거리가 있는 중간 높이 띠로 표현했다. 색만 바꾼 세 공격으로 만들지 않는다. 직접 작성한 사각형·실루엣은 최종 애니메이션이나 히트박스가 아니다.

최종 캐릭터·무기·VFX·사슬이 커지면 손가림/회피 동작 범위를 다시 확인해야 한다. 컬러 시안은 분위기 제작을 확대하기 위한 승인이 아니라 UI와 월드 공간의 검토 자료다.

## 10. 검사 결과와 총괄 인계

최종 좌표 검사: 960×540,1200×540,640×360 × 안전영역3개 × 화면/상태와 전투1버튼/3방향 대조 **558개 조합**, 활성 입력 총2178개, 실패0. 입력 겹침·48미만 입력·UI 안전영역 이탈·인물/회피 동작 범위/핵심 예고와 가정한 손 영역 겹침이 없다. 발 접지선은 모두80~84% 범위다.

총괄의 첫 글자 검사에서는120% 확대 글자의 기준선 때문에 선언bounds 이탈246건이 보고됐다. 확대된 실제 글자 크기를 기준으로 label 기준선을 옮기고, 적 이름 영역 높이·기절 텍스트·두 줄 버튼 행간을 보정했다. 이후 [wireframe-text-check.json](../Evidence/wireframe-text-check.json)을 직접 읽어 **3해상도×기본/120%×전체상태300조합, 텍스트3,750개, bounds 이탈0건**을 확인했다.

총괄의 수정 전/후 [컬러 전투 캡처](../Visuals/landscape-battle-v2.png)도 직접 확인했다. 어두운 다리가 배경에 묻혀 적이 떠 보이던 문제를 다리와 발끝의 형태·명도로 수정하고 주인공 발끝도 지면까지 이어지게 했다. 현재 기본 자세는 접지선에 닿는다.

총괄은 최종 문서/뷰어 가로 넘침0, 이미지 누락0, JS 오류0과 접지 육안 확인을 보고했다. 초기 보고의 뷰어 창 너비는360/768/1440/1600이다. 검사 이후 마지막으로 `강화와 슬롯을 모두 완성했어요`를 더 짧은 `강화를 모두 마쳤어요`로 교체하고 교환 숨김 조건 설명을 정정했다. 이 마지막 문구 수정은 동일 bounds를 사용하며 추가 브라우저 재검사를 수행했다고 주장하지 않는다.

좌표/브라우저 검사는 실제 손·실기기FPS·애니메이션·경제를 검증한 것이 아니다. 세 방향 연속탭의 뒤/아래 오입력, 손목 피로,450ms 연속타 대응, 낮은 공격 가림은 실제 기기에서 확인해야 한다.

## 11. 최종 UI 판정

**최신 `decisions.json` planning-v2와 통합 기획에 동의한다. 미해결 필수 UI 수정은 없다.**

동의 범위는 가로960×540/1200×540/최소640×360, 낮은 지면,3방향 회피와1버튼 대조,20/40 기절 누적, 독립 공격/체력 성장, 유물6종과 직접 슬롯 구매, 시작0G/0D, 강제 예약 없는 새벽석 교환이다. 공격Lv9→10 표시값은 공식/통합표와 같은 **14.22→18.58**을 유지했다.

교환은 두 능력치30에서 숨기고, 새벽석 광고는 슬롯까지 완성되어 사용처가 없을 때 숨기는 마지막 조건도 반영했다. 실제 기기 사용성·재미·경제·출시 검증 완료에 대한 동의가 아니며, 다른 담당 파일과 기존 v1은 수정하지 않았다.
