## 판정

**세 번째 적 `ash_wisp`의 전체 높이를 1.0에서 1.5로 늘리는 안, 공격 예고를 ‘금 간 종의 황동 잔향’으로 정리하는 안에 동의한다.** 이 문서의 수치는 적용 전 제안이며 실제 기기 플레이 판정이 아니다. 현재 원본 시트·저장 카탈로그·프레젠테이션 코드·960×540 전투 캡처를 확인했다. Stage 3의 신규 Unity 캡처를 실행해 확인한 것으로 기록하지 않는다.

UI 담당과 전체 높이 1.5, 예고의 삼각/화살촉 제거, 상·하 수평 띠 / 정면 짧은 세로 균열 / 후방 열린 C형 잔향으로 조율했다. 총괄 보드에서 현재/제안 크기를 같은 장면·같은 발 기준점으로 비교한다.

## 실제 크기 원인

- [런타임 데이터](../../GameData/mvp-catalog.json)의 Stage 3과 Stage 7은 `ash_wisp`, 표시 이름은 **재의 불씨**다. 원본 시트도 왼쪽에서 세 번째 열이 이 적이다. ‘재의 종령’은 아트 제작 기록의 별칭이며 이번 검토에서 데이터 이름이나 ID를 바꾸지 않는다.
- [저장 아트 카탈로그](../../Client/Assets/Game/Art/MvpArtCatalog.asset)는 온 1.1, 파수병·사슬 망령 각 1.5, 불씨 1.0, 수문장 1.8, 기사 2.1로 높이를 지정한다.
- [ActorView](../../Client/Assets/Game/Runtime/Presentation/ActorView.cs)는 idle 스프라이트 전체 높이에 `height / sprite.bounds.size.y`를 적용한다. 따라서 현재 불씨는 주인공의 약 91% 높이로 표시된다.
- [스프라이트 메타데이터](../../Client/Assets/Game/Art/Source/gate-enemies-v1.png.meta)의 `gate_02`는 투명 여백을 제외한 160×268 영역이다. 실제 그림은 큰 종모자, 가느다란 부유 몸통, 아래에 늘어진 장식이므로 전체 높이보다 몸통이 더 작게 느껴진다. 단순히 투명 여백이 남아 작아지는 현상이 아니다.
- [명시적 임포터](../../Client/Assets/Game/Editor/MvpArtImporter.cs)에도 세 번째 적 높이 1.0이 들어 있다. 추후 구현 시 카탈로그만 고치고 재임포트로 다시 1.0이 되는 불일치를 남기지 않아야 한다. 이번 기획에서 임포터를 실행하지 않는다.

### 크기 적용 시 지킬 위계

- 불씨는 다른 일반 적과 같은 전체 높이 1.5로 맞춘다. 중간 보스 1.8, 보스 2.1의 체급은 유지한다. ‘작은 부유형’이라는 초기 분류 때문에 주인공보다 작은 현재 크기를 고집하지 않는다.
- 기존 아래 기준점과 발밑 HP 위치는 유지한다. 원본의 떠 있는 인상은 그림 자체로 유지하며 크기 조절과 동시에 적 전체를 위로 띄우지 않는다.
- 몸통·모자·장식을 합친 전체 높이와, 모자·매달린 장식을 제외한 핵심 몸통 가독성을 따로 검수한다. 확대 후에도 몸통이 약하면 몸통 외곽을 다시 그리는 후속안을 검토하며 무조건 1.8 이상으로 키우지 않는다.
- 모든 자세는 같은 스케일을 쓴다. 기절할 때 스프라이트 전체가 같은 높이가 되도록 다시 늘리는 방식은 금지한다. 기절 때 낮아지는 실루엣 자체가 상태 정보다.
- 크기 변경은 미술 표현이다. 피격·회피 판정 거리, HP, 피해량을 함께 바꾸는 밸런스 변경으로 확대하지 않는다.

### 도트·색·시간 규칙

- 외곽 잉크 `#0C172B`, 비활성 황동 `#AC7833`, 활성 금 `#DCA947`, 접점의 밝은 중심 `#FFF0B4`. 네 방향을 각각 다른 색으로 외우게 만들지 않는다.
- 표면은 큰 도트 덩어리 2~3단 명암으로 구성한다. 깨끗한 벡터 호, 광택 그라데이션, 네온, 화면을 덮는 반투명 빨간 부채꼴은 쓰지 않는다.
- 예고 시작부터 위험의 **전체 형태와 위치**는 보인다. 시간에 따라 분절이 채워지고 접점이 밝아져 접근을 표현한다. 초반에는 파편만 보이고 마지막 순간에 방향이 드러나는 연출은 제외한다.
- 현재 예고는 이어지는 분절과 밝은 접점을 쓰고, 다음 예고는 떨어진 점선과 낮은 대비를 쓴다. 동일 위치에 겹치는 연타의 구체적 겹침 처리는 UI 담당 명세를 따른다. 밝기만 낮춘 동일한 두 그림으로 구분하지 않는다.
- 완벽 회피의 밝은 잔향과 일반 예고를 구분한다. 예고 접점은 작고 국소적이며 성공 잔향은 회피 완료 후 짧게 퍼진다. 파편·피해 숫자와 겹칠 때 예고가 읽혀야 한다.
- 확대된 불씨·무기·큰 치명타 숫자·발밑 HP·손가락 영역을 포함한 합성 화면을 1280×720과 640×360에서 확인한다. 실제 기기에서 색·무음·흔들림 감소 조건까지 보는 것은 구현 후 검수다.

## 처치·사망·보스 등장에 필요한 아트

- **적 처치:** 맞은 쪽에서 균열이 생기고 황동 외곽·짙은 청색 몸 조각이 아래로 떨어지며 몸이 사라진다. 온의 회피로 보이지 않도록 적 전체를 점프시키지 않는다. 파편이 정리된 후 온이 앞으로 달린다. 온의 기존 8포즈에 달리기는 없으므로 측면 달리기 4~6프레임을 신규 제작한다.
- **플레이어 사망:** 외곽 도트→몸통→작은 밝은 핵 순서로 소멸한다. 마지막 핵의 따뜻한 색을 로비 등불 불꽃에 이어 주되, 플레이어 몸이 그대로 불꽃으로 날아가 부활하는 설정을 새로 강제하지 않는다. 화면 암전 뒤 등불 점화로 주변 로비가 단계적으로 드러난다.
- **등불 로비:** 등불 꺼짐/작은 불씨/안정 불꽃 3상태, 사각 덩어리 기반 밝기 마스크를 준비한다. 화면 전체를 번쩍 밝히거나 대형 렌즈 플레어를 쓰지 않는다. 로비의 캐릭터·강화 위치는 유지한다.
- **보스 등장:** 몸을 세우고 잠깐 멎은 뒤 얼굴·가슴 불빛과 바깥으로 퍼지는 2단의 각진 잔향으로 괴성을 시각화한다. 중간 보스는 방패/철퇴의 낮은 무게감, 보스는 후광/장병기의 높은 실루엣을 구분한다. 화면 글자로 ‘괴성’이나 ‘보스 등장’을 써서 대신하지 않는다.
- **줌:** 월드만 확대하고 HUD는 고정한다. 큰 무기·후광이 프레임 위에 잘리지 않는 피벗을 쓴다. 도트 월드를 연속 비정수 확대할 때 윤곽 떨림이 생길 수 있어 프리뷰 후 픽셀 스냅/짧은 단계 확대를 결정한다. 이 문서는 카메라 구현 방식을 확정하지 않는다.
- 파편 소멸, 달리기 종료, 카메라 복귀의 시간과 보상·입력 순서는 전투 연출 담당의 공통 전이표를 따른다. 새 공격 예고와 처치 파편을 같은 타이밍에 겹치지 않는다.

## 총괄 시안 제작용 아트 브리프

**미술 기준:** 현재 `gate-background-v1.png`, `on-poses-v1.png`, `gate-enemies-v1.png`의 인물·배경을 유지한다. 어두운 청색 폐허, 낡은 황동색 외곽, 큼직한 네모 도트. 지면은 화면 높이 약 82%, 온은 왼쪽, 적은 오른쪽이다. 새로운 캐릭터나 무기를 추가하지 않는다.

**공격 예고 비교 그림:** 같은 장면과 같은 플레이어 크기에서 아래 수평띠 / 위 수평띠 / 앞 짧은 세로균열 / 뒤 열린 C형 잔향을 각각 보여 준다. 작은 사각 종못과 국소 밝은 접점으로 마감한다. 게임 내부 문구·장식 문양·정답 화살표·네온·부드러운 벡터곡선은 제외한다. 설명 라벨은 시안 프레임 밖에 둔다.

**전환 스토리보드:** 적 균열→도트 낙하→빈 자리→온 전진, 온 붕괴→암전→작은 등불→로비 전체, 보스 접근→줌인 자세→괴성 잔향→기본 카메라의 순서. 대표 그림은 움직임의 분위기 초안이며 타이밍은 별도 전이표가 기준이다.

## 검토 범위와 후속 확인

현재 크기 원인, 체급 관계, 네 위험 형태, 기존 색·실루엣과의 연결을 문서와 원본 그림으로 검토했다. 아트 방향과 수치 제안에는 동의한다. 새 시안의 최종 합성·동작 프리뷰를 별도로 본 뒤 가림·형태·속도에 대한 후속 의견을 남긴다. 이번 문서 작성으로 Unity 적용, 출시 프레임 완성, 실제 모바일 기기 검증이 완료된 것은 아니다.

## 합성 시안 1차 시각 검토

총괄이 만든 `Planning/Evidence/Presentation`의 `scale-comparison.png`, `warning-directions.png`, `warning-next.png`, `warning-mono.png`, `sequence-storyboard.png`, `boss-1250.png`, `death-1100.png`, `death-1800.png`와 `Planning/Presentation/mood-storyboard-v1.png`를 직접 열어 확인했다. `app.js`, `index.html`, `design-spec.md`도 대조했다. **Node Skia 오프라인 Canvas 렌더의 정지 이미지 검토**이며 브라우저 실행·터치·실시간 움직임·Unity 검증을 했다는 뜻이 아니다.

1. **크기 비교 동의:** 같은 구도에서 50% 확대 후 모자·손·하단 장식이 구분되고 주인공보다 큰 체급이 읽힌다. 일반 적이 중간 보스처럼 커진 인상은 없으며 1.5를 유지할 만하다.
2. **예고 굵기 보완 필요:** 1차 이미지의 6~8px 개별 사각형은 작은 사슬 장식처럼 보인다. 640×360 환산에서 현재 예고조차 점선으로 보이며 기존 예고가 잘 보인다는 사용자의 장점을 줄인다. 현행 선의 환산 굵기 약 9.3px보다 가늘게 바꾸지 않는다.
3. **보완 방향 합의:** 현재 예고는 약 10px 황동 띠가 전체 경로의 90%가량 이어지도록 하고 16~24px마다 작은 2px 균열만 남긴다. 암청 연속 받침이 배경과 분리한다. 미진행은 `#DCA947`, 진행은 `#F2D184`, 접점은 `#FFF0B4`로 둔다. `#AC7833`는 국소 손상·장식 색으로 줄인다. 다음 예고만 4×4px 사각 점/간격16px로 끊어 놓고 접점을 없앤다. 이는 ‘황동 잔향’ 컨셉을 바꾸는 것이 아니라 현재/다음의 형상 위계를 강화하는 수정이다.
4. **위치 보완 합의:** UI 담당의 현재 접점12px/외곽16px, 다음 이격16px, 하단 bounds y560안에 동의한다. 접점 외곽이 띠12px 두께 밖으로2px 나가는 범위는 별도로 명세한다. 두 예고의 맞닿음과 발밑HP 가림을 방지한다.
5. **보스 구도 동의:** `boss-1250.png`에서 무기·후광이 화면 밖으로 잘리지 않고 온도 남아 있어 보스 체급과 대치 관계가 읽힌다. 괴성은 별도 포즈·음원 제작 전임을 유지한다.
6. **로비 등불 위치 수정 필요:** 1차 `death-1800.png`의 등불 중심 x682/y238은 체력 값·별점 부근을 가린다. 조명이 완전히 밝아져도 장식이 남아 가림이 지속된다. UI 담당이 확인한 미리보기 빈 상단 x520/y130으로 옮기는 안에 동의한다.
7. **일반 전환 적 그림 정정 필요:** 1차 `app.js`는 Stage 3에서 처치 후 사슬 망령 `gate_01`을 보여 주지만 실제 Stage 4는 파수병 `gate_00`이다. 다음 단계 이해에 혼선을 주지 않도록 모형도 실제 MVP 배치와 맞춘다.
8. **분위기 보드의 한계:** ImageGen 스토리보드는 소멸·등불·종기사의 분위기를 설명하기에 적합하다. 갑옷 디테일과 보스 체급은 현재 실제 도트 자산보다 크고 정교하므로 실제 자산 교체안이나 최종 배치 명세로 취급하지 않는다. 기존 HTML의 분위기 보드/정확 배치 모형 구분은 유지한다.

1차 검토의 필수 보완은 예고 굵기·연결, 등불 가림, Stage 4 그림 정정이다. 수정 렌더를 확인한 뒤 이 절 아래에 해결 여부를 덧붙인다.

**아트 담당의 기획·정지 시안 검토에서 남은 필수 보완은 없다.** 현재 확대와 공격 예고 방향, 처치·사망·보스 등장 미술을 다음 제작의 기준 초안으로 사용할 수 있다. 실제 달리기·포효 프레임, 부드러운 카메라 동작과 도트 떨림, 250ms 예고의 실시간 식별, 피해 숫자·스턴 기호와의 실제 플레이 합성은 구현 이후 확인할 범위다. 브라우저 정책 차단을 우회하지 않았고, 오프라인 Canvas 시안 검토를 브라우저 또는 Unity 실행 검증으로 기록하지 않는다.
