# v6 전투 검토 · 방향별 베기, 참격 선택, 몬스터 피격

2026-10-21 · 기획·검토용. 소유 범위는 이 문서와 `Planning/Presentation/index.html`이다. Unity, GameData, 생성 원본, 합성 스크립트는 수정하지 않는다.

## 1. 유지하는 전투 시간

| 구간 | 플레이어 표현 | 전투 규칙 |
| --- | --- | --- |
|0~120ms|양팔이 움직이는 달리기로x500→체급별 접근점|피해0. 유효한 회피로 취소 가능|
|120~200ms|선택된 상향/하향 베기 준비|피해0.175ms부터 참격의 선행 궤적|
|200ms|검과 적 몸통 접촉|명중·치명 계산·피해 숫자 각각1회|
|200~300ms|같은 베기 동작의 회수|추가 피해0|
|300~460ms|각 접근점→x500 빠른 복귀|회피로 끊을 수 있음|
|460~500ms|원위치 정착|500ms부터 새 공격 허용|

참격은175~425ms의250ms다.175~200ms는 검의 궤적이며 적 피격·숫자·명중음은200ms 실제 피해 사건에만 발생한다. 상향/하향과 세부 각도가 달라도 공격 시간·피해량·치명 확률·사거리·회피 창은 동일하다. 이동 표현으로 무적을 추가하지 않는다.

처치 후 조우 이동은 기존처럼 플레이어x500 고정, 바닥480px/1200ms 이동이다. 달리기400ms 루프가3번 반복된다. 공격할 때만 플레이어 표시 위치가 기본x500에서 체급별 접근점으로 갔다가 돌아온다. 일반3종은x780, 성문 수문장은x690, 종의 기사는x680으로 정해 큰 몸통과 플레이어가 겹치지 않게 한다. 접근 거리가280/190/180px로 달라도 접근120ms·명중200ms·복귀460ms·재공격500ms는 같다. 새 팔 움직임을 이유로 바닥·캐릭터 루트를 중복 이동시키지 않는다.

## 2. 한 공격의 참격 결과를 한 번만 정한다

총괄의 후보 구성은 **실제 상향 베기24프레임, 실제 하향 베기24프레임**, 각 방향의 기준 궤적−7°/0°/+7°로 총6가지다. 외부 VFX만 뒤집어 캐릭터가 위로 베는데 아래로 내려치는 모순을 만들지 않는다. 방향은 해당 실제 베기 클립과 함께 선택한다.

공격이 승인될 때 `{attackId, targetId, direction, anglePreset, clipId}`를 한 번 정하고 해당 공격의 종료·취소까지 유지한다. 피해 처리나 그리기 함수에서 방향을 다시 뽑지 않는다. 첫 공격은6가지에서 선택하고, 이후에는 직전과 같은 방향·각도 조합1개를 제외한5가지에서 선택한다. 같은 상향/하향이라도 각도가 다르면 연속으로 나올 수 있다. '직전과 다름'은 전체 조합에 대한 규칙이며 매번 위아래를 교대로 강제하는 규칙이 아니다.

시각 선택에는 게임의 치명·보상 난수와 다른 난수 상태를 쓴다. 그림을 한 번 더 그리거나 후보를 확인한 횟수 때문에 실제 치명·드랍 결과가 달라지지 않아야 한다. 공격이 입력 거부되면 새 공격 식별자나 결과도 만들지 않는다. 승인 뒤 취소된 공격의 시각 결과가 소비되는 것은 전투 재화·쿨타임에 영향을 주지 않는다.

검토 페이지 동작은 다음과 같다.

| 사용자 동작 | 참격 결과 |
| --- | --- |
|`▶ 공격 재생`으로 새 공격 시작|직전과 다른 조합을1회 확정,0ms부터 재생|
|재생 중 `Ⅱ 멈춤`|정지, 기존 결과 유지|
|프레임 슬라이더 이동|같은 결과의 다른 시간만 표시|
|몬스터 선택 변경|재생을 멈추고 선택한 대상에 같은 결과를 표시. 재추첨 없음|
|치명 체크·화면 크기 변경|기존 방향·각도 유지|
|초기 페이지 표시|명시된 기본 결과를 표시하거나 '재생 시 선택'으로 대기. 프레임마다 추첨하지 않음|
|끝까지 재생 후 다시 `▶ 공격 재생`|새 공격이므로 새 결과1회 확정|

현재 `app.js`의 재생 버튼은 재생 중 누르면 멈춤으로 작동한다. 이 분기보다 먼저 추첨하면 멈추는 순간 방향이 바뀐다. 새 재생이 실제로 시작되는 분기에서만 결과를 정해야 한다. 페이지를 앞뒤로 스크럽해도 실제 피해·보상을 실행하지 않는다.

`slashReadout`은 현재 확정된 방향과 각도를 읽을 수 있게 표시한다. `strikeTarget`의 값은 아래5개를 그대로 사용한다.

| 값 | 표시 대상 |
| --- | --- |
|`gate_sentinel`|성문 파수병|
|`chain_thrall`|사슬 망령|
|`ash_wisp`|재의 불씨|
|`gate_warden`|성문 수문장|
|`bell_knight`|종의 기사|

## 3. 기존 베기 형태와 접점 보존

사용자가 선호한 기존 검의 형태·휘두름을 기준으로 상향/하향 실제 동작을 제작한다. 각 클립은 별도로 접점 프레임을 확인하고200ms에 맞춘다. 같은 번호의 원본 프레임이 두 방향에서 같은 동작 단계라고 가정하지 않는다.

각 방향 안의3각도는 해당 방향의 접점을 읽을 수 있는 범위에서 고른다. 플레이어 칼끝에서 출발해 선택 몬스터의 상향/하향별 몸통 앵커를 지나야 한다. 각도 변주도 이 접점을 기준으로 배치해 몸통에서 벗어나지 않는지 확인한다. 상향/하향을 바꾸며 기존 고정 선분만 회전시켜 검이나 적에서 떨어지는 효과를 만들지 않는다. 파수병의(885,424) 접점을 모든 크기의 몬스터에게 복사하지 않고5종별 몸통 접점을 지정한다.

캐릭터에 포함된 검흔과 외부 VFX는 같은 한 번의 베기다. 외부 효과는 캐릭터 검흔과 방향·접촉 시점을 맞추고, 겹침 강도를 조절해 두 번 베거나 X자로 교차하는 별도 공격처럼 보이지 않게 한다. 두 효과 모두 피해 이벤트를 생성하지 않는다.200ms에 이미175ms부터 재생 중인 효과를 새로 재생하지 않는다.

타격 전 회피·사망·대상 교체가 발생하면 예약 타격과 선행 궤적을 취소한다. 취소 후 외부 검흔이 혼자 적에게 닿거나 피격 애니메이션을 시작하지 않는다. 타격 후 회피는 이미 확정된 피해를 되돌리지 않으며, 남은 적 접점 효과는 그 자리에 남긴다. 현재 표시 위치에서 회피를 시작하고 기존500ms 재공격 간격은 환불하지 않는 v5 계약을 유지한다.

새 베기24장을120~300ms의180ms에 모두 균등 배치하면 약133FPS다.60Hz 화면에서는 원본24장이 모두 보이지 않는다. 원본은 보존하고 준비·접점·회수의 중요 프레임을 골라 재생 순서를 명시한다. 동작이 건너뛰어 보이면 실제 프레임의 단계 배분부터 조정하고, 접점200ms·재공격500ms 변경이 필요할 때만 총괄과 다시 합의한다. 생성 장수에 맞춰 조용히 전투 시간을 늘리지 않는다.

## 4. 몬스터5종의 피격은 표현 계층이다

각 몬스터의 실제 피격16프레임 후보를 제작한다. 실제 `EnemyDamaged` 사건이 시작 조건이며, 피격 모션·숫자·파편에서 피해를 재귀적으로 발생시키지 않는다. 발 기준과 평상시 체급을 유지하고 몸통 반응만 짧게 표현한다.

합의한 기본 길이는 명중 뒤180ms, 이 공격에서는200~380ms다. 원본16장 전체를180ms에 재생하면 약89FPS이므로 주요 반응·회수 프레임을 고르고 실제60Hz에서 읽히는지 확인한다. 원본16장 보존과 실제 재생 프레임 수는 구분한다. 길이 조정이 필요해도 전투 시간은 계속 흐르며, 이를 경직 시간으로 사용하지 않는다.

| 대상 | 읽혀야 할 반응 | 유지할 기준 |
| --- | --- | --- |
|성문 파수병|갑옷·상체가 맞고 돌아오는 짧은 반동|무기와 발 기준 보존|
|사슬 망령|몸과 사슬의 짧은 뒤늦은 흔들림|원래 공격 궤적·몸통 접점 보존|
|재의 불씨|불씨 몸체의 압축·밝기 변화|인간형의 머리·관절 반응을 억지로 추가하지 않음|
|성문 수문장|큰 상체·어깨의 작은 충격 반응|뒷걸음질로 전투 거리를 바꾸지 않음|
|종의 기사|무게 있는 상체 반동·금속 파편|보스가 일반 공격마다 기절한 것처럼 멈추지 않음|

기본 정책은 **일반 피격이 기절·공격 취소·예고 재시작을 만들지 않는 것**이다. `ResolvePlayerHit`는 피해를 적용하지만 적의 예고·타격 시각을 일반 피격 때문에 지우지 않는다. 회피로 쌓이는 종 게이지와 실제 `EnemyStunned` 사건만 기존 기절 규칙을 바꾼다. 치명타도 별도 규칙 승인이 없으면 같은 정책을 따른다.

표현 우선순위는 사망 → 실제 기절/회복 → 현재 공격의 준비·발동 → 일반 피격 → 대기다. 일반 피격 중에도 적의 논리 공격 시계는 진행한다. 현재 준비·발동 자세를 피격 클립이 가릴 경우 그 자세를 유지하고 짧은 색 변화·접점 파편만 겹친다. 대기·공격 회수처럼 핵심 신호를 가리지 않는 때에는 전체 피격 클립을 보여준다. 모션이 끝나면 이전 공격의 첫 프레임이 아니라 현재 시각에 해당하는 상태로 돌아간다.

기절 중 피격이 기절을 풀거나 시간을 연장해서는 안 된다. 기절 자세를 우선하고 보조 반응만 얹는다. 치명적 피해에서는 일반 피격 클립을 끝까지 기다리지 않고 처치·분해로 전환한다.500ms 뒤의 다음 타격이 오기 전에 기본180ms 반응은 끝나며, 느린 생성 원본의 전체 길이를 그대로 사용해 무한 피격 상태를 만들지 않는다.

현재 Unity의 `MvpPresenter.OnSessionEvent`는 적 피해 때 `ActorView.PlayHit()`를 부르고, `ActorView`는 하나의 `pose`를 피격 상태로 덮어쓴다. 세션의 예정 공격은 계속 남아 있으므로, 이 구조에 긴 피격 시트만 붙이면 보이지 않는 적 공격이 발생할 수 있다. 실제 구현에서는 핵심 공격 자세를 보존하는 위 표현 정책이 필요하다. 이번 작업은 기획만 수행하며 이 Unity 코드를 수정하지 않았다.

## 5. 검토 페이지와 남은 검증

첫 화면에서 새 질주·기존 형태의 베기·몬스터 피격 확인 위치로 바로 이동할 수 있게 한다. 공격 영역에는 `strikeTarget`, 현재 방향 `slashReadout`, 재생/스크럽을 모아 둔다. 재생 시 새 결과가 정해지고 스크럽에는 고정된다는 설명은 검토 화면 밖의 도구 안내이며 게임 HUD 문구로 옮기지 않는다.

통합 후 확인할 항목:

- 6개 후보 각각에서 실제 상향/하향 클립과 VFX 방향이 일치하고 접점200ms가 유지되는가.
- 새 공격1회에 직전과 다른 조합을1회 선택하며, 멈춤·스크럽·대상/치명 선택·리사이즈는 선택 횟수0인가.
- 같은 입력·전투 난수 상태에서 시각 방향을 바꿔도 치명·피해·보상 결과가 같게 유지되는가.
- 199ms 취소는 피해/몬스터 피격0회,201ms 취소는 이미 확정된 피해1회를 유지하는가.
- 일반3종x780·수문장x690·종의 기사x680 접근점이 지켜지고 상향/하향 몸통 접점이 맞는가.5종의180ms 피격이 적의 다음 예고·타격 시각·종 게이지를 바꾸지 않는가.
- 적의 준비/발동과 겹친 피격에서 위험을 읽을 수 있는 자세가 유지되는가. 기절 중 피격·사망도 우선순위가 맞는가.
- 양팔의 어깨·팔꿈치·손이 실제 생성 프레임에서 교차하며, 같은 팔을 고정한 채 몸통만 흔들지 않는가.
- 400ms 달리기 반복, 접근0~120ms, 복귀300~460ms에서 무기 손·피벗·접지의 연결이 자연스러운가.

현재 기록은 기존 소스와 새 요청의 전투 계약 검토다. 신규 프레임 생성·합성은 총괄 담당이며, 이 문서만으로 생성 완료·최종 아트 승인·브라우저 또는 Unity 플레이 검증을 주장하지 않는다.

### 일치한 연결

- 현재 페이지는 v6 모션 스크립트를 사용한다. 새 질주·두 방향 베기·몬스터5종의 피격을 확인하는 링크와 GIF가 메인 기획의 전투 영역에도 연결되며, 생성기에도 같은 링크가 반영되어 재생성 때 사라지지 않는다.
- `proposal.playerAttack`, 페이지 시간표, `attackPose` 및 메인 기획의 공격 설명이 접근120ms, 명중200ms, 복귀 시작300ms, 원위치460ms, 재공격500ms로 일치한다. 체급별 접근점780/690/680도 유지된다. `strikeIndex`의 일반 기본 인자는100ms지만 실제 베기 호출은 준비 시작120ms에 대한 상대 접점80ms를 넘기므로 이 호출의 명중은200ms다.
- 실제 상향·하향 베기 클립을6조합과 연결한다. `rollSlashVariant`는 현재 조합을 제외한 나머지5개에서 다음 결과를 고르고, `app.js`는 새 공격 재생을 시작하는 때만 호출한다. 일시정지·스크럽·대상/치명 변경은 렌더링만 갱신한다. 표시 함수에는 새 추첨 호출이 없다. 초기 화면은 고정된 기본 조합을 표시한다.
- 참격은175~425ms, 적 피격은200~380ms다. `effects-v6.js`의 숫자·명중 파편은200ms 이후에만 표시한다. 이 페이지는 시간에 따른 그림을 표시하며 실제 피해나 보상 처리를 실행하지 않는다.
- 질주 시트는 입력 참고1셀과 생성24셀을 보존하고 재생에는01~13을 선별한다. 두 베기도 각 생성24셀을 보존하되 상향14셀·하향12셀의 재생 순서를 사용하며 각자 다른 접점 원본을 지정한다. 몬스터5종의 채택 후보는 `*-v6-hit-clean`이다. 각 생성16셀과 입력 참고1셀을 보존하고 **참고 셀·반복 셀을 포함한9개의 재생 셀**을180ms에 배치한다. 이는50FPS의 시각 재생이며9장의 신규 원화를 뜻하지 않는다. 제외한 이전 피격 후보는 채택 모션으로 연결되지 않는다.
- 검 색·후드 방향·파수병 도끼 형태의 후속 정리, 생성 완료와 출시 품질 승인의 구분, Unity·GameData 미적용이 페이지에 명시되어 있다. 생성 원본 수와 실제 재생 수를 따로 표시한다.

### 총괄에게 전달한 기존 문구 정리

| 위치 | 발견한 내용 | 필요한 구분 |
| --- | --- | --- |
|`proposal.parallax.status`|절차 다리로 보폭을 비교한다는 이전 설명|현재 실제 `hero-v6-run`을 사용하는 기획 후보로 정정|
|`decisions.production.resources`·`animationFrames`와 메인 제작 표|플레이어3명×16장·총212프레임이 현재 수량처럼 남음|이전 초기 제작 예산으로 표시하고 v6 실제 후보 수량은 자산 목록, 후속 공수는 재산정 대상임을 구분|
|메인 첫 시작의 연속 전투 설명|일반 처치는 '즉시 다음 층'|분해·복귀·질주 연출 뒤 자동으로 다음 층임을 명시|
|메인 전투 위험 형태 표|하단은 발목 수평 궤적, 후방은 빈 곡선으로 표시|대응 회피는 유지하고 현재 큰 가시·등 뒤 사선 화살 형태로 맞춤|

위 항목은 새로운 게임 규칙 제안이 아니라 이미 합의한 연출과 기존 본문을 맞추기 위한 수정 사항이다. 다른 기획 범위·제작 수량·게임 균형을 이번 검토에서 확정하지 않는다.

**총괄 수정 후 재확인:** 위4항목의 정리를 실제 소스와 재생성한 메인 기획에서 확인했다. 패럴랙스 설명은 실제 `hero-v6-run`과 배경 합성 후보로 바뀌었고 선별13셀을 별도로 기록한다. 제작 표의 기존212프레임·플레이어3명×16장 등은 이전 초기 예산으로 표시하며, v6 생성 후보 수량과 자산 목록 기준·공수 재산정을 별도 행과 문장으로 구분한다. 연속 전투는 분해→복귀→질주 후 자동 진행으로, 하단·후방 위험 표는 큰 가시·화면 밖 사선 화살로 정정되었다. 초기 와이어프레임도 UI 배치 참고용이라고 명시했다. 이 소스 대조 범위에서 추가로 남은 실질적인 기획 충돌은 발견하지 않았다.

### 검토의 한계

이번 확인은 문서와 소스의 연결 대조다. 총괄이 별도로 보고한 오프라인 검사·링크 검사를 재실행하거나 Unity 플레이 검증으로 대신하지 않았다. 실제 프레임의 접지·실루엣·접점 품질 승인은 아트 검토에 따른다. 적 공격 준비·발동 중 일반 피격이 핵심 자세를 가리지 않는 우선순위, 입력 취소와 단일 피해, 시각 난수와 전투 난수의 분리는 Unity 적용 때 구현·검증할 계약이며 현재 단일 장면 미리보기만으로 검증 완료라 하지 않는다.
