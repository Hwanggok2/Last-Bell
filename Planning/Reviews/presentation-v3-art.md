# 연출 개편 v3 — 아트 검토

2026-10-21 KST · 기획·자세 모형 검토 · Unity·GameData 변경 없음

## 이번 변경의 기준

v3는 포효를 얼굴에서 퍼지는 원형 파동과 한 번의 공격 동작으로 바꾸고, 전진 거리를 늘리며 화면의 온은 x500에 고정한다. 모든 캐릭터와 몬스터의 필수 모션을 계획하며, 후방 공격은 화면 밖 하늘에서 사선으로 꽂히는 큰 화살, 하단 공격은 왼쪽 위로 솟는 큰 가시로 표현한다.

기준은 현재 원본 시트·아트 카탈로그, [v2 아트 검토](presentation-v2-art.md), 총괄의 `Planning/Presentation` 기획 수치다. 이번 파일은 아트 형태·접점·클리핑·성공 회피와의 관계를 소유한다. 모션별 최종 프레임 수·합산 예산은 별도 모션 카탈로그가 소유하며 이 문서에서 중복 총계를 만들지 않는다.

## 1. 얼굴 중심 원형 포효와 공격 동작 1회

### 중심과 형태

v2의 가슴 좌표에서 나오는 팔각형 타원을 삭제한다. 새 파동은 **얼굴에서 방출되는 원형**이며 화면상 가로·세로 반경이 같다. 도트 계단으로 원을 표현할 수 있지만 육각/팔각 테두리나 납작한 고리로 대체하지 않는다.

현재 시트는 idle과 attack에서 얼굴 높이가 크게 변하므로, 얼굴 앵커는 캐릭터 공통 고정값 하나가 아니라 **포즈별 로컬 좌표**여야 한다. 얼굴에 놓인 빛이 가슴이나 허공으로 떨어지지 않도록 한다. 직접 본 원본 시트에서 출발점으로 추정한 다음 값은 정밀 픽셀 마스크 측정값이 아니다.

| 대상 | idle 얼굴의 기본구도 좌표 | attack 얼굴의 기본구도 좌표 | 주의점 |
| --- | --- | --- | --- |
| 성문 수문장 | 약(848,330) | 약(848,372) | 방패가 가슴을 가리므로 얼굴 중심을 유지 |
| 종의 기사 | 약(874,244) | 약(847,376) | 공격 자세에서 크게 숙인다. 한 고정 y값을 쓰면 얼굴에서 벗어남 |

얼굴 앵커는 현재 포즈·자세 변위·카메라 확대에 맞춰 계산한다. **방출된 파동의 중심은 방출 순간 위치에 고정**하고 반경과 명도만 변화시킨다. 캐릭터가 공격 회수 중 이동했다고 이미 퍼진 모든 원의 중심이 뒤늦게 따라 움직이지 않는다. 새 파동만 새 얼굴 위치에서 시작한다.

### 큰 줌 안에서의 한 번의 동작

- v2의 중간 보스1.45×, 보스1.60× 확대와 상체 구도를 유지한다. 카메라 확대 완료 → 고정된 확대 상태에서 준비·공격 동작1회·회수와 얼굴 파동 → 줌아웃 순서다.
- 공격 애니메이션은 공격 클립의 **한 사이클**이다. 포효 구간 전체에 공격 프레임을 반복 재생하지 않는다. 화면 모형에서 idle→attack→idle로 표현했다면 한 장의 공격 포즈를 활용한 자세 모형이라고 표시한다.
- 이 공격 동작은 등장 연출이다. 피해 판정, 적 공격 예고, 플레이어 피격, 투사체 발사, 명중음, 피해 숫자를 발생시키지 않는다. 얼굴 파동과 괴성은 표시 전용이다.
- 미니/보스의 무기가 앞으로 뻗는 포즈의 **합집합 bounds**로 클로즈업을 검수한다. idle 얼굴만 프레임에 들어간다고 통과 처리하지 않는다.
- 머리·후광·얼굴의 밝은 접점은 원형 파동에 가려 사라지지 않아야 한다. 파동은 얇고 바깥으로 확장되며 빠르게 낮아지는 명도를 쓴다. 전체 화면 흰색 점멸은 사용하지 않는다.
- 확대 상태에서는 발·하반신·온 일부를 잘라도 되지만 얼굴·후광·공격 손·무기 핵심 부위는 읽혀야 한다. 줌아웃 종료 후 전투 발 위치(온500/적900, y590)를 복원한다.

## 2. 더 멀리 이동하되 온의 화면 x는 고정

전투 담당과 **바닥 진행480px / 달리기1200ms / 온 화면 x500 고정**으로 조율했다. 일반 처치 전환은 분해550ms + 달리기1200ms + 정착200ms =1950ms다. 다음 적의 기본 발 x는1380에서900으로 같은 이동 진행률을 따라 들어온다.

- 온의 root를 좌우로 흔드는 `sin` 이동을 없앤다. 달리기는 몸을 앞뒤로 움직여 대신하는 것이 아니라 다리 교차·발의 접지·골반·팔의 작은 반대 움직임으로 읽힌다.
- 달리기 루프는 접지A → 눌림A → 통과 → 접지B → 눌림B → 통과의 여섯 대표 상태를 출발점으로 삼는다. 루프의 첫·마지막 실루엣이 이어져야 한다. 최종 프레임 수는 모션 카탈로그를 따른다.
- 머리/몸의 수직 상하 움직임은 약2~4px부터 검토하되 발 접지 구간에 발이 미끄러져 보이지 않게 한다. 달리기 중 몸의 화면 x500은 유지한다.
- 접지한 발은 그 구간의 바닥 이동을 따라 화면 왼쪽으로 이동하고, 공중 발은 앞으로 회수한다. 단순히 idle 그림을 위아래로 흔들면서 ‘달리기 완성’으로 세지 않는다.
- 배경 이동은 원경보다 바닥이 빠르다. 누적480px을 다음 전환 시작에서0으로 초기화하지 않는다. 바닥 타일 반복 경계를 실제 스크롤에서 확인한다.
- 온은 제자리에 남고 배경과 다음 적이 왼쪽으로 들어오기 때문에 플레이어가 전방으로 나아가는 인상이 난다. 다음 적이 순간 생성되거나 다른 곡선으로 반대 방향 미끄러짐을 만들지 않는다.
- 모션 줄이기에서는 횡스크롤·바운스를 줄이는 기존 정책을 유지하되 입력 재개 시각을 앞당기지 않는다. 일반/감소모션 두 시안의 결과 스테이지는 같아야 한다.

## 3. 후방 큰 화살: 화면 밖 상공에서 사선 착탄

총괄의 v3 수치를 채택한다.

| 요소 | 기획값 |
| --- | --- |
| 세 착탄점 | (350,590), (410,590), (470,590) |
| 시작점 | 각 착탄점 + (400,-780), 즉 y-190의 화면 밖 하늘 |
| 이동 방향 | 오른쪽 위 → 왼쪽 아래 |
| 전체 길이 | 200px |
| 축 폭 / 큰 화살촉 폭 | 10px / 40px |
| 마지막 낙하 구간 | 타격 전180ms. T에 착탄 |
| 성공 앞 회피의 시각 발 x | 600 (기본500에서+100) |

### 모양과 방향의 일치

화살 위치만 사선으로 움직이고 그림은 수직으로 세워 두면 요청한 효과가 되지 않는다. **화살의 축과 큰 촉은 이동 방향과 나란히 기울고**, 촉이 먼저 땅에 닿는다. 꽂힌 뒤에도 기울어진 각도를 유지한다. 뒷축은 착탄점에서 오른쪽 위로 뻗는다.

화면 밖 시작은 단순히 화면 안 상공에 그림을 미리 놓아 둔 것과 구분한다. 원점과200px 길이의 화살 전체가 시작 시 화면 위에 있어야 한다. 준비 기간에는 몬스터의 하늘을 향한 자세와 작은 착탄 표시로 방향을 읽고, 마지막180ms에 실제 큰 화살이 진입한다.

세 화살은 기존 한 패턴 스텝의 한 번 타격을 나타낸다. 수량 때문에 피해3회·화면 흔들림3회·명중음3회가 되지 않는다. 착탄 뒤 활성 명도를 낮추고 T+140ms 안에 퇴장하는 정책을 유지한다. 다음 공격의 준비와 같은 강도로 밝은 잔해를 남기지 않는다.

### 성공 회피와 HUD 충돌

가장 오른쪽 화살의 착탄점470에서 오른쪽 위로 뻗는200px 뒷축 끝은 대략(561,412)다. 성공 앞 회피 `on_07`의 발 x600에 대한 외곽 왼쪽은 약581px이므로 현재 좌표는 v2의 x570보다 분리 여유가 있다. 이 계산은 외곽 사각형과 축의 비교이며 투명 마스크·모든 중간 프레임 검증은 아니다.

첫 착탄점350의 큰 화살촉은 왼쪽 앞 방향 버튼의 터치 영역 끝(x355 부근, y576 부근)에 가까울 수 있다. **실제 삼각 버튼의 보이는 면·손가락에 핵심 촉이 가려지는지** 640×360과 타격 직전/직후 이미지에서 확인한다. 입력 레이어를 단순히 위에 덮는 것만으로 가림 문제가 해결된 것으로 보지 않는다.

## 4. 왼쪽 위로 솟는 큰 가시

| 요소 | v3 채택값 |
| --- | --- |
| 기저 x | 464,506,548,590 |
| 높이 | 94,110,120,104px |
| 끝의 왼쪽 이동 | 최대52px. 각 가시 높이에 비례 |
| 최대 높이 / 시점 | 120px / T+40ms |
| 퇴장 | T+140ms까지 |
| 성공 위 회피 발 상승 | 144px |
| 성공 공중 유지 / 착지 | T+140ms까지 / T+220ms |

화면 좌표에서 tip은 `(baseX-52*(height/120), 590-height)`가 된다. 최종 높이 순서의 왼쪽 이동량은 약40.7·47.7·52·45.1px이며 네 가시의 기울기는 같다. 단순한 세로 이등변삼각형을 왼쪽으로 이동시키는 것이 아니라 **넓은 뿌리에서 왼쪽 위의 뾰족한 끝으로 기울어진 돌·황동 덩어리**로 그린다. 밝은 날 한 면, 어두운 면, 암청 외곽으로 큰 체적을 보여 준다. 하단은 지면에 붙고 끝만 커져야 한다.

기저·끝의 최종 위치를 준비 균열이 먼저 알려 준다. 사선 가시가 지면의 작은 점과 동떨어진 곳에서 솟으면 예고 신뢰가 떨어진다. 최대높이120px은 온 대기 전체 높이128px에 가까우므로 위협을 크게 느끼게 하되, 성공 점프 발 상승144px와 함께 검수한다.

최고 가시 끝 y470과 성공 발 y446 사이에는24px의 기하학적 여유가 있다. 다만 늦은 완벽 회피의 원래 발 위치가 이미144px 높이인 것은 아니다. 판정 순간의 시각 보정·다음 입력 취소·회복이 자연스럽게 이어져야 한다. -160/-60/0ms 입력 경계를 실제로 검증하기 전에는 성공 포즈 정지 모형을 모든 입력의 안전 증명으로 쓰지 않는다.

## 5. 모든 캐릭터·몬스터의 필수 모션

### 플레이 가능한 캐릭터

온·담·린 모두 같은 필수 상태를 준비한다. 앞으로/뒤로/위로/아래로 회피를 한 가지 번쩍임 효과로 대신하지 않는다. **모션 목록이 있다는 것과 각 캐릭터의 실제 스프라이트가 있다는 것은 다르다.** 현재 MVP의 그림과 플레이 가능 캐릭터는 온이며 담·린의 새 자산은 제작 전이다.

| 상태 | 온·담·린 공통 필수 읽힘 | 캐릭터별 구분 |
| --- | --- | --- |
| 대기·로비 idle | 발 기준점·호흡·무기 | 각 인물의 기존 무기·장비·몸짓에 맞춰 제작. 모션을 위해 새 부유/이동 능력을 임의 추가하지 않음 |
| 달리기 | 고정 root x, 발 접지/통과/회수 | 장비 질량과 팔·옷자락 차이 |
| 공격 준비·타격·회수 | 준비와 실제 명중을 구분 | 무기/손·흔적의 실루엣 개별 제작 |
| 피격 | 맞은 방향의 작은 반동 | 장비·망토 반응 개별 |
| 위 회피 | 다리 접기→공중→착지 | 머리 높이만 바꾸는 이동이 아니라 몸을 접은 자세 |
| 아래 회피 | 무릎 굽힘·낮은 머리→복귀 | 선 자세를 세로 축소하는 것만으로 완성 처리하지 않음 |
| 뒤 회피 | 적을 보는 시선 유지·뒤로 체중 이동 | 좌우 미러로 얼굴을 돌리지 않음 |
| 앞 회피 | 몸을 낮춰 적 쪽의 빈 공간으로 파고듦 | 적 관통·좌우 자리 교환 없음 |
| 사망 | 힘이 빠지는 키 포즈→도트 분해 | 동일 공통 분해 방식과 각 인물 실루엣 연결 |

현 규칙에는 플레이어 기절이 없으므로 적 기절 애니메이션이 필요하다는 이유만으로 캐릭터 기절 규칙을 추가하지 않는다. 로비 idle은 전투 idle을 재사용할 수 있으며 중복 제작 수량으로 자동 합산하지 않는다.

### 몬스터 50종의 공통 범위와 원형

기존 `world-art-roster.json`의50종·10원형 명단을 사용한다. 모든 종에 대기, 실제 사용하는 방향의 공격 준비·발동·회수, 피격, 기절, 사망/분해가 있어야 한다. 적의 등장/접근은 현재처럼 대기 자세와 세계 이동을 합성할 수 있으며 별도 보행 클립을 모든 종에 추가 요구하는 뜻이 아니다. 중간 보스·보스에는 얼굴 포효와 한 번의 공격 동작을 포함한 등장 클립을 추가한다. 적의 네 방향 회피는 현 게임 규칙에 없으므로 일괄 필수로 만들지 않는다.

| 원형 | 이동·기절의 핵심 | 별도 제작/검수 |
| --- | --- | --- |
| 갑옷 이족 | 발걸음·갑옷 무게·무릎 꺾임 | 방패/무기·투구 때문에 가려지는 준비자세 |
| 가벼운 이족 | 짧은 발구름·낮은 중심 | 같은 속도라도 팔·무기 회수의 차이 |
| 낮은 사족 | 앞뒤 발 교대·등 굽힘 | 얼굴·턱을 공격 접점으로 지정 |
| 작은 부유체 | 떠 있는 중심·수축·낮아짐 | 다리가 없는 개체를 이족 달리기로 강제하지 않음 |
| 넓은 중형 거체 | 무거운 짧은 걸음·두 손 반동 | 큰 몸과 손의 프레임 밖 크롭 |
| 긴 옷 부유체 | 소매·옷자락·부유 높이 | 종모자·소품과 준비 방향 분리 |

133개라는 기존 방향 합집합 수, MVP19개 방향 수는 공격 방향 커버리지의 근거다. 그 수만큼 실제 애니메이션이 완성됐다고 표시하지 않는다. 50종을 한 그림의 색/무기만 교체해 새 모션으로 계산하지 않는다. 시안에서 관절선·도형 캐릭터로 움직임을 만들었다면 **자세·시간 모형**으로 표시하고 새 완성 스프라이트 수에 포함하지 않는다.
