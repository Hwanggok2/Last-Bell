## 2. 통합 계약

- 유물10종의 Lv1~5는 `combat-v4.md` 및 `decisions.json`의 확정표와 일치한다. 일반/완벽 기절 유물은 실제 누적량21→22,42→44처럼 표시한다. 효과는 해당 레벨의 총효과이며 단계별 값을 누적 합산하지 않는다.
- 전체10종에서 균등 비복원3추첨. ID 끝의05/50은 식별자이며 고정 드랍층이나 해금 조건이 아니다. 미보유→Lv1, Lv1~4→+1, Lv5는 처치 구역의20/40/60/80/100G. 일반 중복은 골드를 지급하지 않는다.
- 유물 보유·레벨·지갑·슬롯 권리는 계정 공유, 스탯 강화·장착ID·NG+·체크포인트는 캐릭터별이다. 신규 자동 장착과 같은 ID 중복 장착은 없다.
- 출전 시 스탯 강화와 장착ID를 고정한다. 장착 중인 유물의 중복 성장만 선택 후 다음 적에 해당 유물 레벨을 반영한다. 미장착 유물은 보유함만 바뀐다. 다른 캐릭터의 장착은 바뀌지 않는다.
- 실게임 HP는 최대HP 증가분만 현재HP에 한 번 더하고,10단위 보스의 전회복은 그 뒤 적용한다. 피해/현재HP의0.001 단위 보존과 HP 정산은 전투·저장 모델의 책임이다. 이 시안은 실제 HP 판정을 구현하지 않는다.
- 처치 시 기본 골드·파편·고정 후보를 먼저 지급/기록한다.10·20·30·40 체크포인트는 선택 성공 시 확정한다. 50층도 선택 이후에만 엔딩으로 이어진다.
- 선택 대기에는 타이머·자동 선택·취소/로비 우회·후보 재추첨이 없다. 선택1회만 유효하며 두 번째 선택 요청은 무시한다. 앱 재접속 계약은 같은 처치ID·선지급 여부·후보ID·선택 상태를 복원하는 것이다.
- 시안은 미선택 offer와 현재 시안 상태를 브라우저의 전용 임시 키 `jong-ui-v4-pending`에 저장한다. 새로고침/“같은 후보 복원”에서 같은3개를 복원한다. 상용 저장·거래 원장·다중 기기 동기화 구현은 아니다.
- 교환 견적에 캐릭터·스탯·레벨·가격·골드/파편 잔액을 보관한다. 확인 시 달라졌으면 새 견적을 다시 보여 준다. 골드가 충분해졌다면 닫고 다음 +를 기다린다. 묵시적 재견적 차감·자동 강화는 없다.

| 파일 | 내용 |

| `Visuals/relic-choice-v4.svg` | 신규·중복·MAX 보상3카드 |
| `Visuals/exchange-v4.svg` | 2파편→200G 부족분 교환 모달 |

브라우저의 `app`, `action`, `rec`, `initial`은 v3 검토와 같은 접근을 유지한다. 화면 kind는 `lobby/battle/tutorial/relics/reward/ending/slots/exchange`다. `progress`는 없다.

- `scenario("reset")` 후 `scenario("convert")`: 150G 부족,2파편→200G 모달. `action("close")` 취소, `action("convert-confirm")` 교환만, `action("upgrade-0")` 별도 강화.
- `scenario("fragment-shortage")`:0파편 부족 확인. 실행 확인을 비활성화하며 필요한 수와 보유량을 표시한다.
- `scenario("relics-empty")`, `scenario("relics-owned")`: 전체 미보유/첫 유물Lv1. `action("relic-equip")`와 `action("relic-unequip")`로 선택 유물 장착 변경.
- `scenario("duplicate")`, `scenario("max")`: 고정 검토 후보의 첫 카드에서 Lv1→2/MAX 보상 확인. `action("reward-relic_05")` 또는 `chooseReward("relic_05")`로 커밋한다.
- `scenario("finish5")`, `scenario("finish10")`, `scenario("ending")`: 처치 선지급→실제3카드→Stage6/11 또는50엔딩. pending 동안 다른 시나리오는 `reset/resume-offer`를 제외하고 막는다.
- `completeStage()`는 현재 모의 적 처치, `beginOffer(stage, ids?)`는 저장된 선택권 생성/유지, `restoreOffer()`는 같은 후보 복원이다. `scenario("mixed")`는5자리 두 숫자와 위험 예고의 동시 표본이다.

공격3회·적 처치·사망·재화 채우기는 시안 밖 검토 도구다. 이 기능으로 실제 전투 판정·자동 조작·밸런스·보상 획득 속도를 입증하지 않는다. 게임 화면에는 검토 설명을 넣지 않았다.

## 4. 배치와 검증

- 960×540/1200×540/640×360, SafeArea 0/기본/최대, 글자100/120%의35상태: **630화면·2952개 활성 hit area, 실패0**. 버튼48 이상, hit 겹침, 안전영역 이탈, 손가림, 위험·HP·피해 숫자 상호 겹침을 검사했다.
- 목록은 작은 화면2개/큰 화면4개씩 보여 주며48px 이전/다음 버튼으로10종 전체에 접근한다. 목록 너비는 안전너비1/3이다. 장착 슬롯 도형은32px, 선택/장착 동작은 별도48px 이상 버튼이다.
- 생성 SVG6개를 ElementTree로 파싱해 XML 정상임을 확인했다. 값 없는 data 속성은 없다.
- HTML 스크립트를 Node VM에서 실행했다. 첫 튜토리얼, 교환/취소/재견적/부족 파편/중복 확인, 고정 후보 복원, 공유 보유·캐릭터별 장착, 중복Lv·장착 효과 갱신,35층 MAX80G,10선택 전/후 체크포인트,50엔딩 중복 차단의 **48개 이상 단언 통과**.
- 총괄 1차 브라우저 검사에서210상태/2454문구와뷰어 가로 넘침을 검사했다. 보상 이름과 장착 상태의120% 글자 높이에 각각3px 여유 부족이 있어 소유 영역을36/26px로 확대하고 재생성했다. 빈 문구는 텍스트 검사의 대상에서 제외한다.
- 실제 기기 그립·터치 성공률·작은 숫자의 읽기·상용 저장/결제는 별도 검증이다. 최종 동의는 아래 교차 검토 절에 기록했다.

## 5. 최종 교차 검토와 동의

**2026-10-21, UI 담당은 v4 통합 기획·시각·상호작용 시안 범위에 최종 동의한다. 필수 UI 이견은 없다.**

`Evidence/document-render-check-v4.json`과 `Evidence/wireframe-text-check-v4.json`을 읽었다. 최종 검사는210조합/2436개 문구의 영역 이탈0, 기획서1440/768/360 및 뷰어1600/1440/768/360의 가로 넘침0, 이미지 누락0, JavaScript 오류0이다. 빈 라벨은 텍스트 수에서 제외했다.

브라우저에서 교환 취소·2파편200G·자동 강화 없음·별도+강화·부족 파편·낡은 견적·중복 확인, 신규Lv1·중복Lv2·MAX20G·같은 후보 복원·중복 선택 차단·10선택 후11→12 자동 진행·Stage11 표시·50선택 후 엔딩·장착/해제가 통과했다. 직접 Node VM 검사에서는35층 MAX80G와 캐릭터별 장착 독립도 확인했다.

총괄이 생성한 `relics-small-v4.png`, `damage-mixed-small-v4.png`, `relic-choice-v4.png`를 직접 열었다. 작은 화면에서 좌1/3 목록과 우2/3 상세가 분리되고, 큰5자리 피해와 위험 궤적·HP·화살표가 구별됨을 확인했다. 신규·중복·MAX 카드의 결과와 장착 여부도 확인했다.

마지막 정합 수정으로 교환 개별 SVG의 배경을 공격Lv40/다음 비용150G로 맞춰2파편200G 모달과 일치시켰다. 보유 목록은 보유 유물을 먼저 보여 준다. 수정한 원본에서 HTML/SVG를 다시 생성했다. 기존 v3 및 통합 JSON·메인 문서·타 담당 파일은 수정하지 않았다.

이 동의는 모의 전투의 게임성·실제 저장 원자성·결제 구현·모바일 터치 검증 완료를 의미하지 않는다. 확정된 피해/HP 정밀도·선지급/선택 커밋·유물 효과 경계는 실제 게임 모델에서 구현해야 한다.

마지막 문구 정리: 미보유 상세의 상태는 한 번만 표시하고, 효과 줄은 “획득 시 공격 +4%”처럼 Lv.1 효과를 보여 준다. 미보유의 중복된 다음 효과 줄은 비웠고, 비활성 버튼은 “장착”으로 유지했다. 보유·레벨·장착 동작은 바꾸지 않았다.
