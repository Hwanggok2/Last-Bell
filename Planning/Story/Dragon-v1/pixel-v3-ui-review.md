# 굵은 도트 전투 시안 · UI 검토

2026-10-24 · 담당: UI/가독성 · 최종 기획 이미지 종합 검토. Unity·프리팹·런타임 데이터는 수정하지 않았다.

## 판정

**플레이어·NPC와 배경의 굵은 도트 방향, 일반전/보스전의 크기·접지·UI 배치는 기획 시안으로 채택 가능하다.** 최종 5개 전투 PNG와 인물·배경 원본을 한 번에 확인했다. 배경의 중앙을 비워 캐릭터가 먼저 보이고, 온의 후드·검, 토끼의 귀·뿔, 큰엄니의 등선·상아를 구분할 수 있다. 기존 캐스트 원화의 세부 묘사로 돌아가지 않았다.

이 판정은 원작과 동일한 원본 해상도·색상 수를 달성했다는 뜻이 아니다. 생성 이미지에는 큰 색면의 약한 농담과 불균일한 격자가 남아 있다. **이번 결과는 더 낮은 도트 밀도로 실제 전투 구도를 합의하는 시안이며, 정수 격자·투명 스프라이트·애니메이션을 완성한 런타임 자산이 아니다.**

## 기준

이번 검토는 플레이어·NPC·배경을 `images/monster-pixel-v2.png`의 굵은 도트 방향에 맞춘 뒤, 기존 전투 UI를 올렸을 때 실제 플레이 장면으로 읽히는지 확인한다. `design.json`이 현재 배치·명칭 기준이며, 이전 종지기/축제 시안의 명칭이나 화면 구조를 다시 가져오지 않는다.

몬스터 원본을 직접 확인했다. 큰 사각 색면과 계단 외곽, 단순한 눈·무기·몸통이 핵심이다. 생성 이미지에는 미세한 농담과 불균일한 격자가 남아 있으므로, 비슷하게 굵어 보인다는 판단을 정수 배율·색상 수·런타임 스프라이트 규격 준수로 표현하지 않는다.

실제 레퍼런스 `Planning/Reference/TimingHero-20261023/boss10/00240.000.jpg`도 직접 확인했다. 원작에서 가져온 기준은 **거의 비어 있는 단색 전장, 가장자리의 반복 환경물, 적은 색 단계의 실루엣, 큰 피해 숫자**다. 원작의 캐릭터·모노크롬 팔레트·지시문·다이아몬드 버튼은 복제하지 않는다. 한 장의 영상 캡처로 원작 스프라이트의 정확한 논리 픽셀 수를 추정해 확정하지 않는다.

## 배치 기준

| 항목 | 기준 |
|---|---|
| 프레임·접지 | 1280×720. 발 기준 y468, 조작 영역 y500 이후. 발끝·그림자·지면 접점이 일치하고 떠 있거나 길에 묻혀 보이지 않을 것. |
| 캐릭터 크기 | 온의 후드·남색 얼굴·짧은 검이 작은 표시에서도 분리될 것. 일반 적의 몸·얼굴·무기가 지나치게 작아지지 않고 실제 표시 높이로 비교할 것. 라인업의 큰 원본 크기만 보고 통과시키지 않을 것. |
| 도트 밀도 | 새 온/NPC·몬스터·배경이 함께 있을 때 한쪽만 미세한 삽화처럼 보이지 않을 것. 배경의 나뭇잎·돌·구름 내부 잡티보다 캐릭터 윤곽이 먼저 보일 것. |
| HP | design.json의 기본 예시는 플레이어 [420,524,160,16], 적 [808,524,184,16]. 최종 합성은 실제 몸 중심을 따르므로 아래 기록의 x로 보정한다. 각 캐릭터 아래에서 누구의 HP인지 분명하고 화살표·검·이름과 겹치지 않을 것. |
| 회피·공격 | 점프·후퇴·전진 3방향, 버튼 배경 없이 화살표만. 공격은 검 아이콘이며 상단 쳐내기도 같은 버튼. 아래 회피·S 버튼·장식용 방향 화살표를 추가하지 않을 것. |
| 터치 영역 | 회피 104×104, 공격 144×144, 일시정지 96×96 유지. 정적 PNG의 그림 크기와 실제 입력 영역을 혼동하지 않을 것. |
| 신호 우선순위 | 위험의 산호/어두운 외곽, 성공의 청록/별 형태, 박자의 파형/방패 접점을 구별할 것. 배경의 무늬·수풀·장식이 위험선이나 공격 방향으로 오인되지 않을 것. |
| 명암·문구 | Stage/골드 받침과 HP가 배경 변화에 묻히지 않을 것. 피해 숫자와 중요 경고는 밝은 면 위에서도 외곽이 유지될 것. 전투 화면에 제작 설명이나 설정 문장을 추가하지 않을 것. |
| 범위 표시 | 시안은 정적 기획 합성. NPC가 자동 동료·플레이어 해금으로 보이지 않게 하고, 실제 모션·충돌·터치·Unity 실행 검증과 구분할 것. |

`design.json`의 Safe Area는 x16부터지만 기존 후퇴 터치 영역은 x12부터라 4px 차이가 있다. 이번 작업은 아트 합성 검토이므로 배치값을 임의로 바꾸지 않는다. 실제 Safe Area 연결 단계에 남길 좌표 점검 사항이다. 640×360으로 축소할 경우 회피 52px·공격 72px·일시정지 48px에 해당하나, 이는 이미지 좌표 환산이며 물리 기기 dp 검증이 아니다.

높이·폭은 최종 PNG에서 읽은 대략적인 화면 점유값이다. 생성 프롬프트의 132px/248px 목표나 원본 논리 픽셀 수를 실측값처럼 바꾸어 적지 않았다. 640×360에서 캐릭터 크기를 환산할 수는 있으나, 별도의 축소 렌더나 실제 휴대전화 터치 검증을 한 것은 아니다.

## 최종 합성 좌표

`pixel-v3-generation.json`과 렌더러가 기록한 실제 좌표는 다음과 같다. x 보정은 게임의 world-follow 의미를 유지하기 위한 것이며, 저장된 Unity UI를 이동시킨 것이 아니다.

| 대상 | 중심/영역 |
|---|---|
| 플레이어 몸 중심 | x470 |
| 일반 적 몸 중심 | x810 |
| 큰엄니 몸 중심 | x850 |
| 플레이어 HP | [390,524,160,16] |
| 일반 적 HP | [718,524,184,16] |
| 큰엄니 HP | [710,524,280,16] |
| 발 기준 | y468 |
| 조작 패널 | y500~720 |
| 원호 클립 영역 | [0,112,1280,388] |

원본 장면 PNG는 수정하지 않고 viewport y−16으로 맞췄다. HP 세로 위치·회피/공격 터치 영역은 기존 규칙을 유지한다. 원호와 사각 모서리는 읽기 비교를 위한 정적 오버레이다. 실제 공격 준비 자세, 540ms 박자 동기화, 회피 성공/실패의 피해 판정이나 순간 가림을 구현한 것이 아니다.

## 남는 범위와 전달 결론

이번 종합 검토에서 정적 시안의 접지·크기·글꼴·조작 영역 때문에 이미지를 다시 생성해야 하는 문제는 발견하지 못했다. 이 결과로 현재 아트 방향과 화면 구도를 사용자에게 보여 줄 수 있다. HTML 설명에도 정적 합성/생성 원화/런타임 미완성을 구분하는 안내가 있으며, 캐릭터 시트가 모두 현재 조작 가능한 플레이어라는 표현은 없다.

피해 숫자·치명타 팝업·성공 별 효과는 이번 PNG에 표시돼 있지 않아 검증하지 않았다. 정식 스프라이트의 고정 격자/색 수, 달리기·회피·쳐내기 모션, 모든 방향의 공격 준비 자세, 이동 중 배경/신호 겹침은 제작 단계에 남는다. **브라우저 실행·Unity 실행·모바일 터치·DPI·Safe Area QA는 수행하지 않았다.** 최종 PNG의 종합 시각 검토와 실제 게임 검증을 구분한다.
