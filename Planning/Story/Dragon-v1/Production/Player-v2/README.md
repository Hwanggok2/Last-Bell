# Player-v2 · 용을 잡으러 가는 모험가

직전 `Production/Player`의 후드 외형과 모션은 이번 제작의 참고 원본으로 쓰지 않는다. 마지막 사용 중이던 `hero_on` 승인 질주와 올려베기·위/뒤 회피의 실제 포즈·순서를 검토한 뒤 새 외형에 이식한다. 조사 내용은 `motion-reference-review.md`다.

새 외형은 보이는 얼굴과 갈색 머리, 붉은 짧은 스카프, 초록 튜닉, 작은 여행 가방, 한손검이다. 확정 원형은 `canonical-coarse.png`이며 32×32 캔버스 안 불투명 높이 22px·8색이다. 7배 정수 확대 시 기준 몸높이 154px다. 최초 48px 후보는 26px 높이로 밀도가 더 높아 제외했고, native24px 재생성도 22px 높이에 불필요한 옷 점이 생겨 제외했다. 원형을 임의 축소하지 않았다.

## 생성 경로와 검증

PixelLab ProFlash로 원형을 생성했다. 기존 승인 질주 PNG는 128×128이므로 `transfer_outfit` 출력 32×32에 직접 넣으면 잘림 위험으로 생성 전 검증 오류가 발생했다. 공식 `image_to_pixelart`로 포즈를 변환한 뒤 `transfer_outfit`으로 교체하는 방법도 3포즈씩 시험했으나 상의색·검길이·전경 자세가 흔들려 반려했다.

최종 모션은 승인된 기존 프레임에서 관절 위치와 포즈 순서를 읽어 작은 캔버스의 골격으로 재구성한 뒤, 동일 canonical·8색 팔레트를 참조해 PixelLab로 생성했다. 원본 이미지를 단순 축소하거나 기존 옷을 그대로 옮긴 결과가 아니다. Run은 기존 8포즈의 접지→밀기→체공→회수와 400ms 시간을 유지했고, 자유팔은 두 반주기에 앞뒤 교대가 보이도록 강화했다. Attack은 기존 올려베기 14포즈 순서를 유지한다. 위·뒤 회피는 기존 완성 포즈를 중심으로 진입·착지 8포즈를 구성했다.

생성 후 PixelLab `pixelart_workbench`로 검토에서 지적된 부분만 보정했다. Run의 부츠 녹색 6px, Attack의 두 프레임 칼날 재질·머리와 칼끝 초록 누출·위쪽 돌출 4px, Back의 밑창 아래 잉여 3px를 정리했다. Attack 전체에 같은 x+1px 여백을 추가하고 공통 pivot을 [17,30]으로 함께 이동했다. 프레임마다 몸이나 발을 정렬하지 않았다. 정확한 좌표·원본 ID·요청·수정 결과는 `requests/`에 보존했다.

`manifest.json`은 **ready**다. Idle8·Run8·Attack14·DodgeUp8·DodgeBack8·Hit6의 원본 52장을 제공하며 DodgeDown은 Attack14를 쳐내기 시간에 맞춰 재사용한다. Idle은 생성 8장 중 7개 고유 포즈이며 중간 정지 포즈를 부풀려 계산하지 않는다. 모든 원본은 32×32 투명 PNG, 실제 8색, 반투명 픽셀 없음이다. Stun과 비활성 Forward는 이번 필수 묶음에 포함하지 않는다.

원본 시트 검토는 총괄과 독립 검토 담당이 완료했다. 게임 내 실제 이동 속도·타격 접점·발 미끄러짐은 총괄의 최종 Unity QA에서 확인한다. 아트 파일 준비 완료가 Unity QA 완료를 의미하지 않는다. Unity 파일과 이전 자산은 이 폴더에서 변경하지 않았다.

## 최종 합격 기준

- 얼굴·머리·스카프·가방·튜닉 비율을 프레임마다 유지한다.
- 검 손잡이와 손이 연결되고 칼날 길이가 유지된다.
- 달리기는 전경이 유지되고 접지→밀기→체공→회수가 구분된다.8장400ms 및40/40/60/60/40/40/60/60ms 시간을 계승한다.
- 공격은 낮게 둔 검을 앞위로 베는 원래 관절 흐름을 계승한다. 기존0~120ms 접근,120~200ms 준비,200ms 접점,500ms까지 회복을 유지한다.
- 위·뒤 회피는 완성 포즈를 별도로 지정한다. 아래 쳐내기는 올려베기 포즈를 재사용한다. 앞 회피를 활성화하지 않는다.
- 프레임별 자동 중앙정렬·발높이 보정·비균등 확대를 하지 않는다.
- 준비된 아트는 총괄 및 독립 검토 담당이 확인한 뒤 묶음으로 넘기고, 최종 Unity QA는 총괄에서 한 번 진행한다.

원본 요청과 job/gallery ID는 `requests/`에 기록한다. 원본 포즈를 참조했다는 사실만으로 모션 품질을 합격 처리하지 않는다.
