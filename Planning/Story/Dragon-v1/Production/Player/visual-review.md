# 온 제작 자산 시각 검토

2026-10-24. PixelLab 원본 및 개별 PNG를 직접 확인했다. 이번 판정은 **아트 통합 준비 완료**다. Unity 플레이모드에서의 피격 판정·이동·접촉 타이밍·UI 가림 여부는 총괄 세션의 통합 QA 범위다.

## 기준 외형과 밀도

48×48 투명 캔버스, 기본 불투명 높이26px,7색이다. 크림 후드와 짧은 튜닉, 남색 얼굴·몸, 황토 스카프, 갈색 신발, 강철색 짧은 검을 유지했다. 승인된 밝은 판타지 시안의 작은 실루엣을 기준으로 삼았으며 종 문양과 긴 망토를 추가하지 않았다. 캐릭터 원본 전체48px를 몸높이로 사용하지 않는다.

`canonical-preview.png`는 정수 확대 확인용이며 실제 게임 원본은 `canonical.png`다. 모든 게임 프레임은48×48, 불투명7색, 알파0/255다. 크기와 팔레트는 `frame-audit.json`으로 다시 확인했다.

## 모션별 검토

| 동작 | 실제 프레임 | 판정과 근거 |
|---|---:|---|
| Idle | 8 | 작은 호흡과 검의 안정된 움직임. 복장과 발 접지 유지. |
| Run | 8 | 전경 자세를 유지하며 양팔·다리를 교차한다. 검이 모든 프레임에서 손에 연결되며 뒤·아래로 향한다. 후드·눈·튜닉·스카프를 재고정했다. |
| Attack | 8 | 검을 들어 준비하고 사선 아래로 베어 내린다. 찌르기 동작으로 사용하지 않는다. 시각 접촉은0기준5프레임. |
| DodgeUp | 8 | 무릎을 접고 몸을 모으는 상방 회피. 큰 이동은 런타임이 담당한다. |
| DodgeBack | 8 | 뒤쪽으로 무게중심을 옮기는 회피. 방향과 검을 유지한다. |
| DodgeForward | 8 | 낮게 몸을 밀어 넣는 전방 회피. 자산 제공과 조작 활성화는 별개다. |
| DodgeDown | 8 | 손 앞에 검을 세우는 쳐내기. 생성 중 섞인 빛 띠는 제거했다. |
| Hit | 6 | 무릎과 어깨가 뒤로 반응하는 피격. 흰 플래시와 도트 파편은 런타임이 담당한다. |
| Stun | 8 | 중심을 잃고 흔들리는 기절. 추가 외부 이펙트 없이 몸 움직임만 제공한다. |

9개 클립 각각의 픽셀 해시가 모두 다르다. 입력 그림을 끼워 넣거나2프레임을 반복해8프레임처럼 부풀리지 않았다. `animate_image` 계열은 원본 입력0번을 제외한1~8번(피격1~6번)을 썼다. skeleton/transfer는 입력이 포함되지 않는 결과0~7번을 썼다. 정확한 출처는 각 클립의 `sourceIndices`와 `processedIndices`에 기록했다.

## 달리기 재작업과 접지

첫 결과는 중간에 상체가 곧게 펴져 제외했다. 이어 명시적8포즈 골격으로 상체 기울임·팔 교차·다리 접지를 지정했다. 이 골격 결과의 검이 일부 프레임에서 약해져, 마지막 단계에서 기준 복장을 다시 적용하고 모든 프레임의 검 길이와 손 연결을 확인했다. 최종 연락표는 `reviews/run.png`다. `reviews/run-initial.png`, `reviews/run-skeleton.png`는 비교 기록이며 등록 대상이 아니다.

검을 앞에 고정한 채 몸만 흔드는 동작이 아니라, 검을 든 팔이 뒤·아래쪽으로 움직이는 달리기다. 낮은 해상도에서 손과 손잡이가 몇 픽셀로 합쳐 보일 수 있으므로, 최종156px 표시 크기에서 실루엣 읽힘을 통합 QA로 확인해야 한다. 총괄 세션도 최종 연락표를 직접 보고 통합 진행에 동의했다.

Run 접지 프레임의 불투명 바닥은 y=40, 비행 프레임2장의 바닥은 y=38이다. 모든 Run 프레임에 피벗(21,40)을 동일하게 사용한다. 다른 모션은(21,38)이다. 프레임별 재중앙정렬이나 리사이즈는 하지 않는다. 따라서2px 비행이 남으며 원본의 몸 비율과 접지 관계를 유지한다. 기본 몸높이26은 모든 클립에서 유지하고, 팔·다리를 뻗어 생기는 실루엣 범위 차이를 별도 확대/축소로 제거하지 않는다.

## 검을 세우는 쳐내기 보정

원본 쳐내기4~6번 프레임(워크벤치1기준)에 원치 않는 빛 띠가 섞였다. 확인된 깨끗한3번 프레임의 검·손목 영역(26,8)~(36,39)만 PixelLab `copy_region`으로 복원했다. 다른 몸 영역은 보존했고, 최종8프레임은 각각 서로 다르다. 변경 영역과247픽셀 보정 내역은 `parry-cleanup-provenance.json`, `requests/parry-cleanup.json`에 남겼다.

## 통합 조건과 남은 확인

- `manifest.json`의 Point 필터·무압축·mipmap 없음·FullRect를 적용한다.
- Run 클립 피벗 재정의를 읽어야 한다. 임의로 원본 좌표를 이동하거나 프레임별 발높이를 맞추지 않는다.
- 기존400ms 달리기 주기를20fps로 유지한다. 기존1.5배 요구를 다시 중복 적용하지 않는다.
- Attack의 시각 접촉5번을 기존 공격 판정0.2초에 정렬한다. 원본24fps를 근거로 데미지 시각을 늦추지 않는다.
- 피격 흰 플래시, 도트 소멸, 사선 참격과 실제 대시는 기존 런타임 효과와 함께 확인한다.
- 이번 묶음이 조작 변경을 승인하거나 Unity QA 완료를 뜻하지는 않는다.

원본 요청·job ID·다운로드 출처는 `requests/`와 `manifest.json`에, 서비스 약관 기록은 `license.json`에 있다. 로컬 시안 외부 업로드는 자동 승인 검토 거절 후 실행하지 않았다. 텍스트로 원본을 만든 뒤 PixelLab 자체 생성 URL만 후속 모션 입력으로 사용했다.
