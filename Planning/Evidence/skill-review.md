# 두 신규 스킬 독립 forward-test

검토일: 2026-10-20. 검토 대상은 `Skills/unity-project-foundation`, `Skills/game-ui-wireframe-copy`의 본문과 연결된 references다. 이 검토에서는 스킬과 원본 프로젝트를 수정하지 않았으며 Unity를 실행하지 않았다.

가상 요청:

> 사용자가 직접 조정한 설정 프리팹이 있는데 OnEnable에서 참조가 누락된다. 설정 화면에 부활 횟수 옵션을 추가하고 데이터는 Excel에서 바꿀 수 있게 해줘. 기존 UI는 유지하고 Unity 실행 없이 가능한 작업까지 해줘.

## 예상 수행 경로

1. 프로젝트 규칙, 현재 설정 프리팹·View·Presenter, `OnEnable/Awake/Initialize` 호출 관계, 부활 상태 소유자, Excel 파서와 실제 지원 스키마를 읽는다. 현재 변경 파일도 확인해 사용자의 수동 수정과 구별한다.
2. 누락 원인을 직렬화 연결 누락과 초기화 순서 문제로 나누어 특정한다. `OnEnable`의 null을 근거로 전체 프리팹을 다시 만들거나 `Find` 연쇄로 임시 보정하지 않는다. 재개방 시 중복 구독도 확인한다.
3. 기존 설정 행을 기준으로 부활 옵션 한 행의 작은 변경 시안을 만든다. 기존 위치·글꼴·색·스프라이트를 유지하며 같은 조작 형식의 요소를 재사용한다. 전체 화면 리디자인을 시작하지 않는다.
4. Excel의 부활 기본값/허용 범위와 플레이어의 저장된 선택값, 현재 전투에서 사용한 횟수를 구분한다. 기존 게임 계약으로 의미와 기본값을 확인하고, 새 부활 횟수를 임의로 확정하지 않는다. 필요한 필드만 현재 파서·검증·생성 모델에 추가한다. 메타행과 필터는 실제 지원되는 형식만 사용한다.
5. 게임에는 `부활 횟수`와 현재 값처럼 판단에 필요한 문구만 넣는다. “Excel에서 자유롭게 관리할 수 있습니다”, “안정적인 참조 구조를 적용했습니다” 같은 구현 설명은 작업 보고서에만 둔다.
6. Unity 없이 가능한 코드·원본 데이터·마이그레이션 도구 작성, 정적 참조·diff 점검을 끝낸다. 프리팹에 직접 반영하기 어렵다면 기존 자산을 제자리에서 읽고 필요한 행/참조만 추가하는 멱등 Editor migration을 준비하되 실행하지 않는다. 임포트·Editor migration·실제 렌더·터치 검증의 미실행 상태를 명시한다.
7. 추가 실행 승인 질문으로 멈추지 않는다. 사용자가 지정한 범위의 결과물과 남은 실행 검증을 전달한다. 기존 코드로도 결정할 수 없는 게임 규칙만 질문이 필요하며, 그동안 독립적인 참조 오류 수정·데이터 계약 작업은 계속할 수 있다.

## 판정

| 실패 위험 | 현재 지침의 효과 | 판정 |
|---|---|---|
| 누락 참조 때문에 프리팹 일괄 재생성 | `CreateMissing/MigrateExisting/Validate`, 재생성 금지, 수동 요소 재사용 규칙이 차단 | 기본 통과. 일괄 재생성 예외의 표현은 아래 수정 권고 |
| 불필요 승인 요청 | 이미 받은 승인 반복 금지, 사소한 수정 승인 금지 | 기본 통과. UI 단계 5 첫 문장이 외부 검토 수신으로 읽힐 여지 있음 |
| 런타임 UI 재구축 | 저장 프리팹을 사용하고 UI 계층 전체 재생성 금지 | 통과 |
| 구현 설명 게임 노출 | 역할 없는 문구 삭제, 개발 설명은 문서/진단에 배치 | 통과 |
| 미지원 Excel 기능 추정 | data-contract가 지원 메타만 사용하고 Client/Server·ExportType 지원을 추정하지 말라고 명시 | 통과 |
| Unity 미실행인데 적용·검증 완료로 보고 | 빌드/렌더/기기 검증을 구별하는 지침 있음 | 기본 통과. 사용자 제한에 따른 부분 완료 보고를 명시하면 더 안정적 |

이 가상 요청을 정상적으로 읽으면 파괴적 작업을 해야 할 이유는 없다. 아래는 스킬을 재사용하는 다른 실행에서 오독을 줄이는 좁은 문구 수정 제안이다.

## 구체 수정 권고

### 1. 전체 재생성 예외를 정확한 자산의 명시적 요청으로 제한

위치: `Skills/unity-project-foundation/SKILL.md:49`

현재:

> 수동 수정된 대상의 일괄 재생성은 현재 요청 범위를 확인한 뒤 수행한다.

문제: “확인”이 에이전트의 내부 판단만으로 충족되는 것처럼 읽힐 수 있다. 같은 절의 보존 규칙이 있어 이번 가상 요청에서는 차단되지만, 원본 AGENTS의 “그 자산 전체 교체를 명시적으로 요청” 조건보다 약하다.

권고 문구:

> 기존 자산 전체 재생성은 사용자가 해당 자산의 전체 교체를 명시적으로 요청한 경우에만 수행한다. 누락 참조·컴포넌트 추가는 제자리 부분 수정으로 처리하며, 이미 허용된 부분 수정에 별도 승인을 반복 요구하지 않는다.

### 2. 시각 검토의 주체를 명시

위치: `Skills/game-ui-wireframe-copy/SKILL.md:16`

현재 첫 문장:

> 시각 검토 결과를 받은 뒤 색·도트 자산·타이포를 적용한다.

문제: 외부 검토 결과를 “받는” 것이 모든 변경의 선행 조건처럼 읽힌다. 후속 문장의 승인 남발 금지와 긴장이 있다. 가상 요청의 작은 설정 행 추가에서도 불필요하게 멈출 수 있다.

권고 문구:

> 시안을 시각적으로 검토한 뒤 색·도트 자산·타이포를 적용한다. 담당자 검토가 요청된 경우에는 실제 담당 피드백을 받고 기록한다. 별도 검토 요구가 없으면 에이전트가 기존 디자인과 변경 시안을 비교해 진행한다.

### 3. 실행 제한이 있을 때 산출물 상태를 별도로 보고

위치: `Skills/unity-project-foundation/SKILL.md`의 `제작 흐름과 검증`, `Skills/game-ui-wireframe-copy/SKILL.md`의 `전달과 완료 기준`

문제: 현재 지침은 실제 화면 검증을 기본 흐름으로 요구하지만, 사용자가 Unity 실행을 금지한 경우 코드/데이터 준비와 에디터 적용을 어떻게 구별해 보고할지는 직접 쓰지 않았다. 사용자 지시가 우선하므로 작업 자체가 막히지는 않지만, 미실행 migration을 적용 완료처럼 보고하지 않도록 한 문장을 추가하는 편이 좋다.

권고 문구:

> 사용자가 Unity 실행·렌더·빌드를 제한하면 가능한 코드·데이터·마이그레이션 준비와 정적 검사를 완료하고, 자산 적용/임포트/화면/입력 검증 중 실행하지 않은 단계를 구체적으로 남긴다. 준비한 도구를 실제 실행한 것으로 보고하지 않는다.

## 변경 불필요

- Excel 메타 지원 추정 방지 문구는 충분하다. 새로운 필터 규약이나 `ExportType`을 강제할 필요가 없다.
- View/Presenter·세션 상태 소유권, 제한 Pool, 자료구조 선택을 이 작은 작업에 억지로 확대할 이유가 없다.
- 사용자 문구 기준은 필요한 옵션 이름·값을 유지하면서 내부 구현 설명을 제거하도록 잘 동작한다.
- 전체 와이어프레임·다수 기기 렌더를 이번 작업의 완료 선행 조건으로 강제하지 않고, 변경 행의 배치 근거와 미실행 검증으로 범위를 좁히면 된다.
