## 하나의 박자

|종류|점멸 시작|마지막 밝음 종료/발사|중앙 접촉·타격|연타 간격|
|---|---|---|---|---|
|기본|0,180,360ms|450ms|540ms|360ms|
|빠름|0,160,320ms|400ms|480ms|320ms|

한 범위당3박자, 각 박자의 전반은 밝음(.20)/후반은 흐림(.04). 마지막 반 박자는 무기의 비행이며 추가 대기를 넣지 않는다. 빠른 패턴도 같은 비율을 사용하므로 기존650ms보다 짧지만390ms로 무리하게 압축하지 않는다. 방어 재사용260ms를 수용하는 두 박자 간격320ms를 유지한다.

연속 공격은 **모든 방향의3회 점멸 → 같은 순서로 공격**이다. 기본2연타: 앞0/180/360, 뒤540/720/900, 첫 발사990, 타격1080/1440ms. 빠른2연타960/1280ms, 빠른3연타1440/1760/2080ms. 마지막 범위의 세 번째 밝음까지 끝난 후 첫 공격이 출발한다. 먼저 예고한 영역은 윤곽alpha.14만 남겨 방향을 기억하게 한다. 연타 사이에는 다시 점멸하지 않는다.

## 중앙에 모이는 큰 원과 종

화면 밖 고정 원점(-.125W,.5H)/(1.125W,.5H), 접촉 반경.625W. 모든 공격에서 T−2.5박자에 발생해 T−2박자부터 가장자리에 보이고 T에 맞닿는다. 첫 공격/후속 공격의 가시 이동 시간과 속도가 동일하다. 첫 타만600ms 이동하던 규칙은 폐기한다. 원의 X/Y 반경은 동일하며 카메라·캐릭터·SafeArea 위치와 무관한 전체 화면 좌표다.

중앙 상단(.5W,H/3)에 종1~3개. 한 타가 확정되면 해당 종만 제거하고 나머지를 재중앙정렬하지 않는다. 기절·사망·로비/결과 전환에서 남은 큐와 함께 지운다. 금빛 위험 영역과 종, 푸른 타이밍 파동, 청록 성공 파동을 구분한다. 청록 파동은 완벽 방어 확정 후에만 화면 정중앙에서 모서리 밖까지 퍼진다.

소리를 켜면 각 금빛 점멸 시작에70ms의 짧은 금속음을 재생한다. 음소거에서도 동일한 시각 정보가 남는다. 연출 줄이기에서도 타이밍 원 한 겹은 유지하고 번짐·잔향·입자·흔들림을 제거한다. 일시정지는 전투 시계와 함께 모든 시각 상태를 멈춘다.

## 쳐내기와 입력

- 상단은 공격 버튼/Space로 제자리 올려 베기. 숙이기 버튼과 S/아래 입력은 제거한다. 점프·후퇴·전진은 기존 방향키/WAD를 유지한다.
- 일반 방어 T−160~T, 완벽 T−60~T. Unity는 정확한 T의 중앙 접촉 프레임을 먼저 보여주고 그 프레임의 입력을 받은 후 피격을 해결한다. 추가 늦은 입력 유예는 없다.
- 공격 입력 우선순위는 유효한 상단 쳐내기 → 완벽 반격 → 일반 공격. 한 입력은 한 동작이다. 쳐내기와 회피는260ms 재사용을 공유한다.
- 일반 공격500ms 쿨타임과 쳐내기는 독립이다. 쳐내기로 명중 전 공격을 끊으면 예약 피해만 취소하고 원래 쿨타임은 유지한다. 이미 명중한 피해는 되돌리지 않는다.
- 쳐내기는 해당 위협1회만 막고 적 HP를 자동으로 깎지 않는다. 일반/완벽은 기존20/40 공명 및 유물/기절 면역 규칙을 따른다. 완벽 쳐내기는 청록 파동과500ms 반격 기회를 준다. 반격을 수락하면 원점으로 즉시 복귀한 후 명중200ms의 공격을1회 수행한다.
- 세 가지 이동 회피는 상단 영역 안에 남으므로 상단을 막지 못한다. 실제로 영역 밖에 있는 몸에 방향 검사만으로 피해를 주지는 않는다. 적 기절·사망 외에는 다음 연타가 계속된다.

## 선택한 미리보기 모션 적용

회피는50ms 이내 cubic ease-out 진입, 타격 후100ms 유지,130ms 복귀. 타격까지50ms 미만이면 진입을 압축해 정확한 접촉 입력도 수용한다. 너무 이른 회피는160ms 안에 복귀해 판정 창을 늘리지 않는다. Core 몸통과 표시 위치가 같은 이동량을 사용한다.

일반 공격/반격은 원점375→540으로165px 접근120ms, 명중200ms,230~500ms 귀환. 접근 중 달리기 대신 베기 준비 포즈를 사용한다. 전장 사이 이동의 승인 달리기8자세·400ms 주기·1,920px/2초는 유지한다.

## 적용과 검증 범위

원본은 GameData/mvp-catalog.json(mvp-1.4.0), 생성본은 exporter로만 갱신한다. requiredDodge 필드는 기존 스키마 이름을 유지하며 상단 응답값을parry로 명시한다. 저장의 Down enum은 과거 저장 호환용으로 남지만 현재 입력으로 수락하지 않는다.

저장된 GameView 프리팹에 CombatRhythmGraphic을 추가하고 Mvp 씬에 연결했다. 새 마이그레이션은 관련 UI와 음향 참조만 변경한다. 실제 테스트/빌드 결과는 [검증 기록](../Evidence/Combat-v59/verification.json)이 기준이다. 미리보기의 직접 입력은 방향 자동 대응을 사용하며 피해·공격 쿨타임·저장 전체를 시뮬레이션하지 않는다. Android APK는 이번 범위에서 재빌드하지 않는다.

## 화면 밖 두 원점에서 생성되는 원형 파동

화면 너비W,높이H. 원점은 `(-0.125W,0.5H)`와 `(1.125W,0.5H)`에 고정하며 실제 게임에서 점이나 추가 종으로 표시하지 않는다. `r(t)=0.625W*clamp((clock−start)/(T−start))`. 모든 원은 가로·세로 반경이 같은 화면 픽셀 원이며, 화면 경계에서 잘라 그린다. 반지름만 선형으로 증가한다. 월드·캐릭터·카메라 흔들림과 무관하다.

960×540에서 원점(-120,270)/(1080,270), 접촉 반경600px. 반경0에서 시작해 원이 화면 안으로 들어오고 위아래 화면 높이를 가로지른다. T에 두 원의 주선이(480,270)에서 최초로 맞닿는다. 첫 파동은 T−600ms 생성, T−480ms 화면 진입. 연타는 이전 타격에 새 원을 생성하고360/320ms 뒤 다음 T에 접촉한다. 후속 파동이 화면에 보이는 시간은288/256ms다.

주선 색#C7DAFA, 기준4px. 번짐18px/alpha0.09, 주선alpha0.86. 주선 뒤28px에는2px/alpha0.18의 약한 잔향 한 겹만 둔다. 밝은 주선이 타이밍 기준이며 잔향으로 별도 타격을 암시하지 않는다. 연출 줄이기는 주선 한 겹만 남긴다. 원 내부를 색으로 채우지 않는다.

T에서 접촉한 두 원은 같은 반경으로45ms 동안 빠르게 흐려지는 잔광을 남긴다. 렌더 프레임이 T를 건너뛰어도 접촉 모습을 확인하기 위한 것이며 타격 후 입력 유예를 추가하지 않는다. 일반160ms·완벽60ms·재사용260ms와 마지막60ms 중앙 목표점 강조를 유지한다. 청록 성공 파동은 확정된 완벽 회피에서만 나오며 다음 예고 시 이전 성공 주선alpha를45%로 낮춘다.

## 금빛 히트박스 노출 단축 비교

미리보기 초기 선택은 단축안이다. ‘히트박스 노출’에서 기존안과 즉시 비교한다. 줄이는 대상은 채움·점멸 구간이며, 공간을 기억할 수 있는 희미한 테두리는 해당 타격까지 남긴다.

| 안 | 기본 점멸 | 빠른 점멸 | 이후 |
| --- | --- | --- | --- |
| 단축 제안 | 540ms/3회.90ms 밝음+90ms 흐림 ×3 | 390ms/3회.65ms 밝음+65ms 흐림 ×3 | 채움0, 테두리alpha0.14 |

각 예고의 시작은 기존 슬롯0/780/1560ms(기본),0/530/1060ms(빠름)를 유지한다. 예고 슬롯의 마지막240/140ms에는 채움 없이 윤곽만 보인다. 연타의 모든3회 점멸을 먼저 끝낸 뒤 기존 순서로 공격한다. 금빛 채움을 발사 때 다시 켜지 않는다(단축안). 기본 채움 노출은 약31%, 빠른안은 약26% 짧아진다.

타격 T는 두 노출안이 동일하다. 단발900/650ms,2연타 기본1680/2040·빠름1180/1500ms,3연타 기본2460/2820/3180·빠름1710/2030/2350ms. 타이밍 안내 형태와 공간 표시 노출을 먼저 비교하므로 공격 템포를 동시에 올리지 않는다. 단축안은 검토용 제안이며 확정 밸런스가 아니다.

## v5.6 · 좌우 수렴 파동과 남은 공격의 종

### 세 가지 시각 정보

- 금빛 사각형: 공격이 닿을 **공간**. 빈 곳으로 회피한다. 기존 색 #E9B85A, 세 번 점멸, 범위 좌표를 유지한다.
- 흰빛 좌우 파동: 회피할 **시간**. 양쪽 파동의 앞끝이 화면 정중앙에서 만나는 순간이 타격 T다.
- 청록 원형 확산: **확정된 완벽 회피 결과**. 중앙 도착만으로 완벽 문구·성공 파동을 재생하지 않는다.

방향 지시 문구·정답 화살표·캐릭터 상단 예지 게이지는 되살리지 않는다. 종의 실루엣 수와 파동의 이동으로 정보를 전달한다.

### 좌우 파동 시간·위치 계약

960×540 기준 좌상단 원점. 수렴점(480,270), 정규화(0.5,0.5). 파동의 앞끝은 (0,270) / (960,270)에서 출발한다. 흰빛 #C7DAFA의 세로로 휜 윤곽선 두 개이며 각 중심선 높이152px, 본선3px, 선택 잔상2줄이다. 채워진 화면 섬광은 없다. 카메라·월드·캐릭터 변위와 독립된 화면 좌표다.

첫 타격의 수렴 시간은600ms. `start=T−600`, `p=clamp((clock−start)/(T−start))`, `leftX=W/2*p`, `rightX=W−leftX`. 가감속 없는 선형 이동으로 정확히 T에 일치한다. 이후 연타의 start는 이전 타격 T이며 기본360ms/빠름320ms 동안 새 한 쌍이 모인다. 예고 큐 전체는 기존대로 먼저 재생한다. 따라서 첫 수렴 파동은 마지막 금빛 예고 중에 시작될 수 있다.

| 패턴 | 기본안 타격 T | 빠른안 타격 T |
| --- | --- | --- |
| 단발 | 900 | 650 |
| 2연타 | 1680 / 2040 | 1180 / 1500 |
| 3연타 | 2460 / 2820 / 3180 | 1710 / 2030 / 2350 |

단위ms. 첫600ms 수렴 구간과 후속360/320ms 구간은 실제 타격 큐에서 계산한다. 기본 일반160ms·완벽60ms·회피 재사용260ms는 유지하는 제안이며 타격 후 유예는 추가하지 않는다. 중앙의 작은 마름모(반경7px)에 T−60~T 동안 모서리 네 개를 켜 완벽 구간을 보조한다. T 이후45ms 접촉 표식은 중립적인 타이밍 표식이며 성공을 뜻하지 않는다.

완벽 파동은 v5.5처럼 화면 정중앙에서 시작해 화면 밖까지 퍼진다. 후속 수렴 안내가 활성화되면 이전 성공 파동의 주선 alpha를45%로 낮춘다. ‘완벽’은 중심 아래34px에 표시해 수렴점을 가리지 않는다. 그리기 순서: 월드/금빛/공격 연출 → 성공 파동 → 수렴·목표점·종 → 기존 HUD/입력.

### 종 개수 = 아직 판정하지 않은 공격 수

종 중심 정규화(0.5,1/3),960×540에서(480,180). 아이콘28×34px, 슬롯44px 간격. 3개 전체 예약 영역126×46px는(417,157)~(543,203)이다. 종은 읽기 전용으로 터치 영역이 없다. 기존 공명 HUD(y83~101), 수렴점(y270), 캐릭터와 입력 버튼에서 떨어뜨린다.

전체 예고 시작부터 큐의 총 공격 수만큼 종을 표시한다. 단발1개,2연타2개,기존 보스3연타3개. 각 T에서 피격/회피 여부와 무관하게 왼쪽부터 하나씩 제거한다. 남은 종은 첫 슬롯 위치를 유지하고 빈 자리를 회색 종으로 남기지 않는다. 수렴 중인 타격의 종에만 크림색 양옆 선을 그린다. 초기에2개였다는 사실과 현재1개가 남았다는 사실을 혼동하지 않도록 **항상 보이는 개수=남은 횟수**로 통일한다.

처치·기절로 공격 큐가 취소되거나 전투가 끝나면 관련 종과 수렴 파동을 즉시 제거한다. 일시정지 시 큐 시각·종·파동 모두 동결, 재개 때 같은 위치에서 계속한다. 연출 줄이기는 타이밍에 필수적인 선형 수렴을 유지하고 잔상·번짐·확산·입자·카메라 흔들림을 제거한다. 소리 없이도 판독 가능해야 한다. 미리보기는 무음이다.

### 검토용 직접 입력

미리보기에서 ‘직접 타이밍 맞추기’를 켜면 자동 회피·자동 반격을 끄고, 예시 방향으로 회피하는 입력 시각만 버튼/Space로 지정한다. 입력 간 재사용260ms, T 이전160ms 내 일반·60ms 내 완벽으로 분리한다. T에서 결과를 확정한다. 무입력·너무 빠른 입력은 성공 파동을 내지 않는다. 0.5/0.25배속은 형태 확인용이며 난도는1배속에서 판단한다. 이는 브라우저 시계의 연습이며 실제 터치 지연·기기 난도 검증을 대신하지 않는다.

## v5.6 · 후퇴 회피와 공격 접근은 기존 미리보기 기준으로 채택

사용자 요청: “뒤로 회피하거나 앞으로 공격하는 모습이 인게임과 다르다. 미리보기가 더 좋은 것 같으니 저대로 수정”. 기준 원본은 `hitbox-preview-v55.js`의 `dodge`, `heroState`, `drawHero`다. 새 v5.6 미리보기의 자동 시연은 해당 동작을 유지한다.

### 완벽 회피 파동과 즉시 복귀 반격

- 확정된 PerfectDodge 순간, **전투 화면 정중앙**(정규화0.5,0.5 /960×540 기준480,270)에서 청록·크림 **원형** 고리 두 겹을 확산한다. 화면 좌표로 그려 캐릭터 위치·카메라 흔들림과 분리한다. 원의 가로·세로 반지름을 동일하게 유지한다.
- 파동420ms, 둘째 고리45ms 지연. 두 고리 모두 최대 반경 `sqrt((화면너비/2)^2+(화면높이/2)^2)+64px`까지 확산해 네 모서리 밖으로 빠져나간다(960×540에서는 약614.7px). 반투명 윤곽선만 사용하며 화면을 색으로 채우지 않는다. ‘완벽’도 화면 중심에 표시하며, ‘완벽’320ms. 일반 회피·피격·입력 직후에는 완벽 파동이 없다. 기존 일반20/완벽40 공명과 면역 중 증가0을 유지한다.

- 기존 공격 쿨타임을 초기화하지 않는다. 입력이 거절되면 강제로 복귀하지 않는다. 성공 기회는 첫 수락 공격에서 소비하며 새 회피·피격·사망·전투 종료 시 폐기한다. 자동 반격은 실제 게임 기능이 아니라 미리보기 예시다.

### 표시와 판정을 맞추는 구현 계약

- Core가 소유한 예고 시작·발사·타격 시각으로 모든 표시를 계산한다. UI의 별도 타이머가 피해를 생성하지 않는다. 창 찌르기는 실제 무기 소켓/몬스터 전면과 플레이어 공격 기준점에서 범위를 만든다.

## 2. 공격 예고 — 위험 위치와 맞는 순간을 함께 읽는다

현재 Unity에는 위험 영역·수축 표식이 있지만, 가시의 여러 접점과 공격별 다른 이동 궤적이 시간을 나눠 보여 준다. 한 곳을 보고 동일한 끝점을 학습하기 어렵다. 상단 종 게이지는 기절 누적이므로 공격 카운트다운으로 재사용하지 않는다.

**채택할 안: 위험 영역 + 적의 준비 자세 + 고정 길이의 타이밍 막대.** 위험 영역은 어디를 피해야 하는지, 막대는 언제 눌러야 하는지를 맡는다. 막대는 플레이어 머리 위 별도 공간(960×540 기준 중심x=플레이어 기준x, y=318)에 144×16으로 배치한다. 플레이어 공격 접근·회피 때마다 따라 뛰지 않고 전투 기준점에 고정한다. 화면 위 기절 게이지와 모양·자리·기능을 구분한다. 640×360은 120×16, y=212를 출발값으로 삼고 캐릭터/보스 HUD와 분리 검토한다.

- 막대는 왼쪽에서 오른쪽의 **고정 타격선**까지 선형으로 찬다. 시작 전에 타격선이 보이며 중간 가감속·되감기·끝점 점멸은 없다. `p=clamp((현재 전투 시각−예고 시작)/(T−예고 시작),0,1)`.
- T−160ms에 막대 끝의 유효 구간으로 진입하고, T−60ms부터 이중 테두리 구간에 들어간다. 색 외에 단일선/이중선/끝의 마름모로 구분한다. 구간 너비는 실제 시간으로 계산: 650ms 예고에서 144px 기준 일반22.15px·완벽13.29px. 900/250ms에서도160/60ms를 고정 백분율로 바꾸지 않는다.
- 준비 초반에는 적의 체중 이동과 무기 준비를 읽게 한다. T−160~T에는 준비 자세의 긴장·접점 수렴을 강화한다. 실제 가시/칼날/찌르기/화살의 접촉은 **T에 한 번**이다. 화살이 T 전 이동해도 플레이어/지면 접점에 먼저 닿지 않는다.
- 단발650ms, 연타 첫900ms, 후속 재강조250ms, 타격 간격 최소450ms를 유지한다. 다음 타격은 빈 위험 실루엣 하나만 보이고 두 번째 타이밍 막대는 표시하지 않는다. 후속250ms가 시작할 때 현재 막대를 새 타격T에 연결한다.
- 일반 `[T−160,T−60)`, 완벽 `[T−60,T]`, 늦은 입력 유예0, 재사용260ms, 방향 검사는 유지한다. 입력을 수락한 순간과 회피 성공 확정 순간을 구분한다. 완료 프레임 입력 처리 계약도 유지하며 UI가 새 판정·유예를 만들지 않는다.
- 일시정지·중단·재개에는 예고와 전투 시계를 함께 멈추고 정상 첫 예고를 보장한다. 무음·색 구분 어려움·감소 모션에서도 끝점과 이중선이 남는다.

훈련에서는 처음에만 “끝선에 맞춰 피해!”를 보여 주고 실제 일반 회피 1회 후 끝낸다. 완벽 회피를 튜토리얼 통과의 필수 조건으로 만들지 않는다. 정답 방향 상시 점등·카운트 숫자·공격 이름은 추가하지 않는다. ‘빠름/늦음’ 진단은 연습/사후 피드백 후보이며, 이미 판정된 피해를 늦은 입력으로 소급 취소하지 않는다.

## 3. 완벽 회피 — 결과를 느끼게 하는 한 묶음

현재 표시 연결은 일반/완벽 회피에 같은 회피 음원의 음량 차이를 주고 있다. **완벽은 고유한 표식·소리·누적 증가를 같은 성공 사건에 묶는다.** 입력 버튼을 누를 때가 아니라 Core의 PerfectDodge가 확정되는 T에 시작한다.

| 수단 | 완벽 회피 제안 | 일반 회피와 구별 |
| --- | --- | --- |
| 글자 | 플레이어 위의 별도 결과 공간에 `완벽`, 960에서22px/640에서18px, 320ms(220ms 유지+100ms 소멸). 최대1개 | 일반은 작은 단일 고리180ms, 글자 없음 |
| 형태 | 청록빛 마름모 + 2겹 종 파문180ms. 캐릭터 전체 백색 피격이나 방패 모양은 쓰지 않음 | 일반 단일 고리와 다른 형태 |
| 소리 | 짧고 맑은 전용 종소리1회, 시작은 결과 사건과 동일. 준비/피격/치명 소리와 음색 구별 | 기존 짧은 회피 소리. 단순 음량 차이만으로 구별하지 않음 |
| 촉각 | 선택 설정을 켰을 때만 약20ms의 짧은 진동1회, 기기 지원 확인 후 결정 | 기본적으로 일반 회피는 진동 없음 |
| 전투 보상 | 기본 기절 누적20→완벽40, 게이지에서 새로 증가한 구간의 이중 밝은 꼬리180ms | 효과가 있으면 실제 적용량을 표시. 가득 차면 즉시 기존 기절 전환 |

시간 정지/슬로모션/카메라 흔들림/추가 피해/무적 연장은 이번 제안에 넣지 않는다. 연타의 다음 박자를 계속 읽을 수 있어야 한다. 완벽 표식보다 **현재 위험·타이밍·HP·입력**이 우선한다. 최소450ms 간격에서320ms 표식은 다음 타격 전에 끝난다. 다음 예고와 일부 겹치는 구간에는 위치를 분리한다. 유물 적용 누적량과 상한100 때문에 항상 정확히40만큼 보이는 것은 아니다. 기절 후 면역 중에는 성공 표식을 내되 잠금 게이지에 가짜 누적을 그리지 않는다. 기존 게이지량80→완벽 성공이면100에서 즉시 기절하며 넘친20을 다음 기절에 저장하지 않는다.

무음·진동 OFF에도 글자와 형태로 완벽이 확인된다. 감소 모션은 파문 확산을 정적인 마름모180ms로 대체하고, 글자·기절 증가·입력 규칙은 유지한다. 일시정지에서는 표시 수명도 멈춘다. 전투를 떠날 때 표시를 정리하고 이전 결과를 재생하지 않는다.

## 4. 강화·골드 경제 재개정 — 매회 복리 상승, 돌파 할증, 스테이지 수입 연동

**사용자 수정 반영(v5.1): 앞선 매 레벨+1G·돌파+5G·고정 구역 보상안은 폐기한다.** 강화할 때마다 비용이 큰 비율로 오르고, 기존 능력치가 크게 뛰는10→11·20→21·30→31·40→41에서는 추가 비용을 받는다. 9→10으로 돌파 시점을 옮기거나 기존 능력치 공식을 변경하지 않는다.

### 4.1 강화 가격

목표 레벨 `L=1..50`, `b=floor((L−1)/10)`일 때 **`C(L)=ceil(10×1.25^(L−1)×2^b)` G**. `C(0)=0`은 구매 아님. 통상 약25%씩 상승하고 돌파 때는 통상1.25배에 추가2배가 포함돼 **약2.5배**다. 반올림 전 원식을 계산해 마지막에 한 번 올림하므로 이미 올림한 이전 가격에1.25를 반복 곱하지 않는다. 실제 청구는 검증한50개 정수 배열을 쓴다. 별도 돌파 비용을 다시 더하지 않는다.

예: 0→1은10G, 1→2는13G, 2→3은16G, 9→10은75G, **10→11은187G**, 11→12는233G. 가격은 스탯 자신의 레벨로 계산하며 다른 스탯·별점 때문에 바뀌지 않는다. 상한50에서는 구매 대신 MAX 표시.

### 4.5 연동된 금액·저장·UI

- 골드 교환도 고정100G를 대체한다. 계정 최고 **완료** 보스가0/10/20/30/40일 때1파편당100/150/2,776/51,700/962,966G.40에서 상한,50에서 추가 급등 없음. 여러 캐릭터와NG+에서 이미 열린 교환 단계를 낮추지 않는다. 미완료 도달 기록으로 교환율을 올리지 않는다. 기존 저장의 완료 기록에서 단계를 복구하고 복구 근거가 없으면0에서 시작한다. 파편 지급1/3·슬롯 비용4/8·현금 상품 구성은 유지한다.
- 필요한 파편은 `ceil(max(0,가격−골드)/현재교환율)`. 확인은 교환만 하고 다시+를 눌러 강화한다. 예:10보스 미완료·교환율100·잔액12·10→11 비용187이면2파편을200G로 교환해212G, 별도 강화 후25G. 교환율·지갑·강화 레벨이 바뀐 견적은 다시 확인한다. 부족한 파편을 상점/결제로 자동 연결하지 않는다.
- MAX 유물 전환은 보스층 기본값의1/2인 `C(S)`:75/1,388/25,850/481,483/8,968,311G. 일반 중복은 유물 레벨만 증가한다. MAX 전환에는 행운을 적용하지 않고 선택 제안 때 확정한 금액을 복구한다.
- 큰 금액을 지원하도록 향후 골드·비용·보상·견적·저장·합산을64비트 정수로 맞춘다. 한 회차는 현재32비트 안이지만 반복 플레이로 넘을 수 있으므로 UI만 확장하면 안 된다. HUD의만/억 축약은 내림 표시하고 실제 구매·교환 확인은 콤마가 있는 정확한 정수를 보여준다. 큰 숫자가+나지갑을 밀지 않는지640화면에서도 검토한다.
- 기존 레벨·골드·파편은 그대로 보존하고 이후 구매와 새 처치부터 적용한다. 소급 청구·과거 보상 재지급 없음. 진행 중 처치/유물 선택은 저장된 기존 금액을 유지하고 새 견적만 갱신한다.

향후 구현 범위는 강화 가격뿐 아니라 **스테이지별 골드표·교환율 단계·MAX 유물 금액·큰 정수 저장/UI**까지 한 번에 일치시키는 것이다. 현재 단계에서는 Planning 문서와 제안 JSON만 바꾼다. 적HP/공격·플레이어 성장 계수·예고/회피 시간은 이번 경제 개정으로 변경하지 않는다.

## 6. 달리기 — 속도보다 접지와 체중 이동을 먼저

현재 선택8장은24fps/약333ms, 이동은1920px/2초다. 직접 본 프레임 시트에서 큰 후드와 짧은 다리 때문에 발의 지지/밀기 차이가 작고, 손과 허리 종이 붙는 자세가 있다. 다리가 몸을 실제로 밀기보다 빠르게 교체되는 인상을 줄 가능성이 있다. 실제 재생을 새로 계측한 결과가 아니라 기존 시트·캡처를 보고 내린 아트 판단이다.

**추천은 ‘무거운 후드를 쓴 종지기의 낮고 단단한 달리기’다.** 기존 정지 그림의 다리만 바꾸거나 전체 이미지를 기울이는 방식은 피한다.

1. 먼저 접지/눌림/통과/밀기 4개 키포즈와 반대발4개, 총8자세를 만든다. 지지발은 지면을 뒤로 밀고, 회수발은 무릎을 접어 몸 아래를 통과한다. 앞·뒤 다리 명도를 나눠 포개져도 읽히게 한다.
2. 몸통 전경20~25도 후보, 머리 수직 변화2~3 원본px, 골반4~6px 후보. 머리만 흔들리지 않고 골반이 접지 때 내려가고 밀기 때 올라간다. 큰 후드·짧은 체형·검은 얼굴·금색 눈을 유지한다.
3. 검은 몸 뒤 낮게 고정하고 손–손잡이–날 길이가 변하지 않게 한다. 자유손이 허리 종을 가리지 않는 실루엣으로 팔꿈치를 벌린다. 옷자락은 골반보다 한 프레임 늦게 따라가되 다리의 통과를 가리지 않는다.
4. 새 키포즈가 읽히면 **400ms와480ms** 두 후보를 현재333ms와 비교한다. 480ms 후보는 접지70/눌림50/통과50/밀기70ms×양발로 구성한다. 프레임 수 증가 자체를 개선으로 삼지 않는다. 기존24fps를 즉시 덮어쓰는 결정은 아니다.
5. 접지한 발과 바닥 표식의 상대 이동을 먼저 맞춘다.1280 기준960px/s를480ms 루프와 결합하면 한 주기460.8px를 이동하므로 짧은 보폭과 맞는지 검증해야 한다. 안 맞으면 발 궤적/루프/근경 스크롤을 함께 비교하고, 거리·속도 변경안을 별도로 표시한다. 시트를 느리게만 재생하지 않는다.
6. 2초 이동의 시작/끝100~140ms에는 출발/감속 자세 후보를 두고 중앙은 정속 반복한다. 마지막 달리기 프레임에서 곧바로 직립하지 않고 착지→정착→전투 대기로 연결한다. 전환 전체3250ms와 전투 입력 재개 시점을 늘리지 않는 배분안으로 비교한다.

승인 기준은 정상속도·실제표시크기에서 양발교대가 읽힘, 발 접지 중 바닥과 어긋남이 화면2px 이내, 후드·검·종의 형태 안정, 반복 경계·공격 접근/복귀 연결에 튐 없음이다. 이 허용치는 검토 목표이며 현재 통과했다는 뜻이 아니다. 정지 시트 검사와 반복 재생 검토를 따로 기록한다.

## SimpleGame 검술사 참고와 새 전체 몸체 달리기

사용자가 지정한 SimpleGame 검술사의 실제 Move를 참고한다. Player.controller의 Move 상태(속도1·속도 파라미터 비활성) → BladeMage.overrideController → BladeMage_Move.anim → sprite fileID → Character.png.meta의 internalID/rect를 추적했다. 실제 선택은 BladeMage_08~15의8장이며 원본64×64·왼방향을 그대로 추출했다. 키 시각은0/62.5/125/187.5/250/312.5/375/437.5ms, m_SampleRate16, m_StopTime0.5, LoopTime1이므로 한 주기는500ms다. [원본 추적·해시·픽셀 검증](PixelLab/v10/reference/source-manifest.json), [8장 비교](PixelLab/v10/reference/contact.png), [참고 GIF](PixelLab/v10/reference/reference.gif)를 보존한다. 원본 파일은 변경하지 않았다.

새 hero-v10-blademage-run은 온의 별도 입력 자세에서 PixelLab MiniMax로 전체 몸체 시퀀스를 생성한 검토 후보다. 작업은929856d9-e432-453f-bec9-379bbfd9166f이며 반환 PNG9장을 확인했다. 입력 반환00과01~07을 선택해8장으로 재생하고, 같은 달리기 위상으로 돌아오는 끝08은 제외한다.00과08이 픽셀까지 같다는 뜻이 아니다. v9처럼 고정 몸통에 관절 자세만 붙이는 제작 방식으로 설명하지 않는다.

이동은1920px/2000ms, 일반 전환3250ms다. 이동 거리960→1920px와 속도480→960px/s를 각각2배로 높이고 이동 시간은 유지한다. 온의 달리기 재생만1.5배로 높이며 공격·회피·피격·보스 카메라 시간은 바꾸지 않는다. 원본 후보의 review 상태는 보존하며, 선택 클립을 Unity에 연결한 사실과 출시 품질 승인을 구분한다. 실제 동작의 연결·원형·접지는 [v10 아트 검토](../Reviews/run-v10-art.md), 참고와 생성 요청은 [v10 제작 기록](../Reviews/run-v10-prompt.md)에 남긴다. 이전 후보는 [v9 고정 보드](index-v9.html)를 포함한 아카이브에 보존한다.

플레이어 화면x500을 고정하고 바닥은1920px를2000ms 동안 왼쪽으로 이동한다. 이동 속도는960px/s이며 이전보다 속도·거리가 각각2배다. 다음 적의 world anchor도2820→900으로 같은 거리만큼 이동한다. 하늘·원경·중경·가까운 기둥은 바닥 대비0.02/0.08/0.22/0.48배로 움직인다. 전진 슬라이더 최대값은1920px이며 각 레이어의 최대 이동량은 하늘38.4px·원경153.6px·중경422.4px·가까운 기둥921.6px·바닥1920px다. 다음 적은 체급에 따라 자연스럽게 화면 안으로 들어오며, 마지막150ms에 갑자기 표시를 켜거나 별도 속도로 밀어 넣지 않는다.

## Stage 배너 뒤 보스 등장

보스 등장 장면에는 Stage500ms가 앞에 포함된다.280ms 조립→120ms 유지→100ms 소멸 뒤 카메라 연출을 시작한다.

포효는 확대 유지 중 얼굴 원형 파동과 표시용 공격1회를 사용하며 피해·투사체·예고를 만들지 않는다. 마지막 정착200ms에 보스HP를 실제값으로 공개하고 HUD는 월드와 함께 확대하지 않는다. 줌아웃·배너 종료 뒤에만 첫 전체 예고를 시작한다.

전환·Stage·포효 중 전투 시계와 입력은 잠그고 그동안 받은 입력은 폐기한다. 다음 조우는 준비된 공격·회피와 온전한 첫 예고를 보장한다. 일시정지는 표시 시계도 멈추며 앱 복원은 기존 층·HP·보상을 바꾸지 않는 안전 재개 계약을 따른다. 감소 모션은 움직임을 줄이되 배너 종료→첫 예고 순서를 유지한다.

## 10단위 보스 처치 뒤 진실 대화

메인 기획 상단의 [스토리 전체 보기](../index.html#story)와 [서사 데이터](../story.json)를 내용 원본으로 삼는다.10·20·30·40·50층은 처치·기본 보상·고정 유물 후보/선택권을 먼저 저장하고, 보스 쓰러짐·분해 → 하단 대사 → 유물3택1 → 선택·체크포인트·회복 저장 → 자동 다음 층 순서로 진행한다.5·15·25·35·45층 중간 보스는 기본 골드·종 파편1개만 지급한다. 유물후보·선택권과 대사는 생성하지 않으며 분해 후 자동 전진한다. 유물은10·20·30·40·50층 보스에서만3개 중1개를 선택하므로 한 회차 선택 기회는5회다.50층은 대사와 유물 선택 뒤 해당 캐릭터 최초 완주에만6초 엔딩 → 로비로 잇고, 같은 캐릭터의 이후 완주는 정산 뒤 로비로 돌아간다. 완주 캐릭터만 다음 회차1층을 시작한다.

자동 대사는 캐릭터별 해당 보스 첫 처치에 한 번만 표시하고 NG+에서는 반복하지 않는다. 계정 보관함의 다시보기는 공유한다. 대사는3박자이며 한 번에 한 줄을 표시하고 자동으로 넘기지 않는다. 처치 때 누른 입력을 폐기한 뒤 새 탭으로 다음 줄을 읽거나 해당 장면을 건너뛴다. 건너뛰어도 유물을 자동 선택하거나 생략하지 않는다. 대사 완료/스킵을 저장하며 앱 복원 시 storyPending의 미완료 줄을 유물 선택 대기보다 먼저 처리한다. 대사 UI는 전투 입력·공격 예고·보스 등장 카메라와 동시에 재생하지 않으며 보상이나 처치 판정을 만들지 않는다. story-50-stage-2는 종전 계정 최초 엔딩만 자동 재생하던 기준을 캐릭터별 최초로 명시적으로 대체한다. storySeen은 characterId+storyBossId, endingSeen은 characterId로 저장하고 다시보기 해금은 계정이 공유한다. 유물 선택 전 체크포인트를 확정하지 않으며50층은 선택 저장 뒤 endingPending을 복구한다. 구체 대사·퇴장 연출 길이는 서사 원본의 최신 합의안을 따른다.

## v4 네 방향 회피 복원

현재 선택은 전체 교체 전 hero-dodge-up/down/front/back이다. v5 회피 재제작본을 현재 선택으로 표시하지 않는다. 네 원본은 입력 참고1셀+생성16셀을 보존하고 down/back의 기존 선별 순서도 유지한다.

## 예고 종료 순간의 회피

예고 게이지가 끝나는 시각과 타격 시각은 같은T다. 입력 시각D가 올바른 방향이며 회피 재사용이 준비된 상태일 때, **T−160≤D<T−60은 일반 회피, T−60≤D≤T는 완벽 회피**다. −60ms와 정확한0ms는 완벽에 포함한다. T 이후 늦은 입력 유예를 추가하지 않으며 잘못된 방향은 실패다. 단발650ms·연타 첫900ms·후속250ms와 최소450ms 연타 간격은 유지한다.

동일한 논리 시각에는 입력 수집·회피 시작 → 적 타격 판정 → 살아 있는 플레이어의 예약 공격 순으로 처리한다. 예고 표시와 D·T는 세션의 단일 전투 시계를 따른다. 이미 `Tick(T)`로 피해가 확정된 뒤의 입력을 소급해 성공시키는 계약이 아니다.260ms 회피 재사용 제한·잠금 상태·입력 폐기 정책도 유지한다.

사용자가 본 화면은 Unity 실행 화면으로 확인했다. 변경 전 Core는 정확T를 포함하는 판정식이었지만 `Tick(T)`에서 즉시 피해를 확정해 게이지100% 화면을 보고 입력할 기회를 보장하지 못했다. 수정 후 실제 프레임은 입력 수집 → Presenter `LateUpdate`의 `TickInputFrame` → Render 순서다. 처음T에 도달하면 시계를T에 두고 타격을 미확정으로 보존해 Progress1을 표시한다. 다음 프레임에서 올바른 회피를 누르면D=T로 평가하고, 그 뒤 타격을 확정한다. 미입력·방향 오류·260ms 재사용 제한은 실패 조건을 유지한다.

완료 프레임 대기는160/60ms 판정창이나 고정 ms 유예를 늘리는 변경이 아니다. 남은 delta를 보존하고 각 타격의 완료 표시를 보장하며450/250ms 연타 일정을 유지한다. 대기 중 일시정지 후에는 완료 화면을 다시 한 번 제공한다. 저장 복원은 대기 상태를 재사용하지 않고 기존 새 예고·일시정지 정책으로 돌아간다. 기존 `Tick`은 즉시 시간 시뮬레이션용으로 남기며 실전 프레임에서 `TickInputFrame`과 중복 호출하지 않는다.

기획 보드의 `dodgeOffset = D−T` −220~+100ms 검토는 이 논리 경계를 설명하는 별도 도구다. 변경 전 진단과 변경 후 구현·Core52개 검사 결과는 [예고 종료 타이밍 검토](../Reviews/telegraph-end-timing.md)에 구분해 기록한다. Unity View의 Progress1 상태·PointerDown 연결을 포함한 PlayMode5/5와 EditMode58/58 검사는 통과했다. `-batchmode -nographics` 자동검사이므로 실제 화면의 시각 품질·사람의 터치·실기기 체감 검증 완료로 표시하지 않는다.

## 기존 베기·접근·복귀 유지

v6 올려베기·내려베기는 각 생성24장을 보존하고 접점 프레임을 선별한다. 올려베기07, 내려베기04를200ms 명중에 맞춘다. 효과 시작은 내려베기 준비01의 칼끝[66,17], 올려베기07의 검손[91,82]다. 은색 검·정면 후드·큰 내장 원호는 후속 아트 정리 대상이다.

접근0~120ms →준비120~200ms →명중200ms 한 번 →회수300ms까지 →복귀460ms →재공격500ms다. x500에서 일반3종 앞x780, 수문장x690, 기사x680으로 접근한다. 공격 이동은 처치 후 화면x500 고정 질주와 별개이며 피해량·사거리·무적을 추가하지 않는다. 플레이어HP는 표시 몸 아래를 따른다.

상향·하향과 각 기준각−7°/0°/+7°를 결합한6조합 중 공격 시작에 직전과 다른 조합을 시각용 난수로 한 번 고른다. 스크럽·일시정지·대상 선택·치명 토글은 결과를 유지하며 치명·보상 난수를 소비하지 않는다. 내장 검흔과 외부 참격은 같은 한 번의 공격이다. 참격175~425ms, 접촉·파편·숫자200ms, 치명타 흔들림80ms를 유지한다. 타격 전 유효 회피는 예약 명중·선행 궤적을 취소하고 타격 후 회피는 확정된 피해를 유지한다. 공격 간격은 환급하지 않는다.

## 막타 흔들림과 오래 남는 피해 숫자

1280×720 기획 시안은 적 처치 막타에서 월드만120ms·최대5px, 치명타는80ms·최대3px를 사용한다. Unity 실행본은 기존X0.035/Y0.02 월드 진폭에 막타5/3배를 적용한다. 카메라 orthographic size3.1·960×540에서 막타는 약X5px/Y3px이며 기획1280의5px와 정확히 같은 스케일이 아니다. 같은 타격의 치명타·막타는 막타 흔들림1회가 우선하며 더하지 않는다. 사망·처치·보상 사건을 연출에서 다시 생성하지 않는다. HUD·위험 표시·입력 위치는 고정하고 감소 모션에서는 흔들림을0으로 둔다.

피해 숫자는 실제 명중 위치에서650ms 동안 우측96px·위72px로 이동한다(1280×720 기획 Canvas 좌표 변화는+96/−72). Unity의960기준 UI는 위가 양수이므로 대응 이동량은+72/+54다. 처음400ms는 보이고 마지막250ms에 사라진다. 기존350~450ms보다 오래 남으며 일반·치명 숫자 크기 차이는 그대로다. 기존960×540 기준 일반35px·치명50px,640×360에서는25px·35px를 유지한다.0 피해는 표시하지 않고 위험 예고·HP·조작을 가리지 않게 배치한다. 감소 모션에서는 숫자 위치 이동만0으로 두고650ms 수명과 소멸은 유지한다.

플레이어 공격 기획은200ms에 한 번 명중하고500ms에 다시 공격할 수 있다. 숫자의650ms 수명 때문에 공격 간격을 늘리지 않는다. 명중200ms부터 끝850ms까지 숫자를 확인하도록 **공격 기획 미리보기만0~850ms로 확장**한다. 이어지는 공격의 숫자는 각 명중 사건별 수명을 가지며 기존 최대6개 표시 제한과 예고 우선순위를 유지한다. 이번 Unity 변경은 기존 실행본의 공격 시점을 바꾸지 않는다.

Unity Presenter·BattleEffects에는 일반 적의 즉시StageStarted에서도 막타 효과를 지우지 않고, 보스 막타를 보상 화면 전650ms 동안 보여주는 연결을 적용한다. 피해·처치·보상 확정 사건은 재생성하지 않으며 이 대기는 숫자를 보여주는 표시 계층의 처리다. 숫자·흔들림의 상태·좌표·종료와 보상 화면 전환은 Unity PlayMode 자동검사를 통과했다. Windows 빌드·새 실행 파일smoke도 통과했고 실제GPU 치명타 팝업 캡처 한 시점을 확인했다. 시간적 흔들림과 사람의 터치 검수는 별도다. 이는 계획된 적 분해·달리기·보스 서사 전체를 Unity에 구현했다는 뜻이 아니다.

## 캐릭터 전체 백색 피격

확인된 피해 사건에서 캐릭터 현재 프레임의 불투명 픽셀만 흰색으로 바꾼다.0~45ms 완전 흰색,45~120ms 원색 복귀 후 종료한다. 투명 alpha·크기·피벗은 보존한다. 배경·HUD·사각 프레임·별도 효과에는 적용하지 않는다. 한 피해 사건에 한 번 시작하며 회피 성공에는 시작하지 않는다.

플레이어와 적5종이 같은 효과를 쓴다. 적 피격 자세는 기존 v6 clean 후보의 생성16장 중9개 재생 셀을180ms에 표시한다. 공격 기준 백색 효과는200~320ms, 피격 자세는200~380ms다. 경직·기절·추가 피해·무적을 만들지 않는다. 중요한 공격 준비·발동 중에는 원래 자세에 색만 적용해 예고를 숨기지 않는다. 사망은 피격 복귀보다 우선한다.

원본 alpha를 흰 시트로 캐시하고 현재 셀의 RGB만 섞는 hit-flash-v7.js를 사용한다. [비교 이미지](../Evidence/Presentation-v7/hit-flash-proof.png)와 [연결 계약·검증 한계](../Reviews/hit-flash-v7-flow.md)를 따른다. 도우미가 피해·보상 사건을 생성하지 않는다.
