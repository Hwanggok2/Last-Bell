# 마지막 종지기 · 전투 연출 기획 02

2026-10-21 KST · 기획 수정. Unity 코드·프리팹·카탈로그·빌드는 이번 작업 범위가 아니다.

## 시안과 수치의 기준

사용자 첨부 이미지의 작은 종지기와 거대한 적 대비를 채택한다. 보스의 큰 줌과 정지 포효, 준비 자세에서 시작하는 공격 예고와 실체 VFX, 플레이어 검흔, 이동 배경의 깊이, 사용 조건을 확인한 음원을 기획한다.

`index.html`은 비교·재생 보드, `proposal.json`은 연출 수치 원본, `audio-sources-v2.json`은 음원 후보와 라이선스 기록이다. 게임 데이터 원본 `GameData/mvp-catalog.json`을 대체하지 않는다. v1은 `index-v1.html`과 `design-spec-v1.md`로 보존한다.

보드의 Canvas는 기존 스프라이트를 재배치한 기획 모형이다. 준비·포효·달리기 새 프레임은 아직 없으며, 기존 공격/대기 포즈를 자리표시자로 사용한다. 도형 배경은 층별 이동량을 보여주는 모형이다. 현재 Unity 화면이나 완성 애니메이션으로 취급하지 않는다.

높이는 모자·후광·무기를 포함한 대기 스프라이트 전체 bounds 기준이다. 주인공 발(500,590), 적 발(900,590), 바닥선 y600을 유지한다. 대기 그림에서 정한 배율을 모든 포즈에 공통 적용하여 공격 그림이 커졌다는 이유로 몸통을 다시 줄이지 않는다. 확대만으로 피해량·판정 범위는 바꾸지 않는다.

플레이어 HP는(447,608,106,10), 일반 적 HP는(847,608,106,10). 보스·중간 보스 HP는 기존 긴 상단 바를 사용하고, 종 게이지는(326,88,627,18)로 올린다. 전투 구도에서 머리·후광과 HUD가 겹치지 않아야 한다. 등장 클로즈업에서는 다리와 온 일부의 크롭을 허용하되 얼굴·핵·후광은 살린다.

## 2. 큰 줌 → 고정 포효 → 줌아웃 → 전투

|구분|줌인|큰 줌 유지·포효|줌아웃|정착|최대 줌|
|---|---|---|---|---|---|
|중간 보스|0–0.40s|0.40–1.15s|1.15–1.60s|1.60–1.80s|1.45배|
|보스|0–0.50s|0.50–1.50s|1.50–2.00s|2.00–2.20s|1.60배|

포효가 시작되기 전에 줌인이 끝난다. 포효 동안 카메라 배율과 중심을 고정한다. 포효가 끝난 후 줌아웃하고, 원래 구도에서 0.20초 정착한 뒤 첫 예고를 시작한다. 포효의 꼬리 잔향은 줌아웃에 남을 수 있으나 첫 예고를 가리지 않도록 줄인다.

중간 보스는 월드(900,330)를 화면(820,350)에, 보스는 월드(880,270)를 화면(800,350)에 맞춘다. 기본 직교 크기3.1에서 `orthographicSize = 3.1 / zoom`으로 작아지는 크기와 구도 이동을 함께 설계한다. HUD는 화면 기준을 유지한다. 상단 HP는 마지막 정착0.20초에 실제 체력을 페이드인하며 가짜 체력 채우기를 하지 않는다.

재조우도 같은 최대 줌을 쓴다. 중간 보스1.00초(0.20/0.35/0.25/0.20), 보스1.20초(0.25/0.45/0.30/0.20)로 나눈다. 같은 캐릭터·회차·보스ID의 첫 연출을 끝낸 뒤에만 재조우 완료를 기록한다. 첫 등장 중 앱이 종료되었다고 완료 처리하지 않는다.

수문장은 낮은 문·종·숨소리, 종기사는 깨진 종·금속 호흡의 괴성을 새로 제작한다. 무음에서는 가슴 핵과 각진 두 잔향이 포효를 보여준다. 과도한 전체 화면 흰색 점멸은 사용하지 않는다.

## 3. 준비 자세와 연결되는 네 방향 공격

준비 자세 진입과 첫 환경 신호를 같은 시점에 시작한다. 기본 예고650ms, 연타 첫900ms, 연타 후속250ms를 유지한다. 실제 판정시각을 T라고 한다. 몸의 준비→환경 신호→실체 타격→회수가 이어져야 하며 상단 설명문은 띄우지 않는다.

|패턴 / 회피|준비 자세|T 이전 환경 신호|T의 실체 공격|
|---|---|---|---|
|아래 / ▲|무기 끝 또는 손을 지면에 대고 힘을 모음|발밑 균열·황동빛 접점이 수축|3~5개 큰 가시, 최대80px|
|위 / ▼|무기를 어깨 위에서 수평으로 당김|머리 높이에 얇은 칼날 길과 끝빛|머리 높이를 쓸어가는 넓은 칼날|
|정면 / ◀|상체를 뒤로 당기고 창끝을 모음|정면 수평 경로와 다가오는 접점|정면에서 수평 창찌르기|
|뒤 / ▶|무기를 세우거나 팔을 들어 하늘을 부름|등 뒤 하늘에 검·창·화살3발과 착지점|세 발이 동시에 등 뒤에 꽂힘|

후방 무기는 x404/450/496에 도착한다. 마지막120ms에 가속해 떨어지고 T에 착지한다. T 이전의 낙하·궤적은 예고이며 피해를 주지 않는다. 세 무기와 여러 가시는 한 패턴 스텝의 한 번 타격이다. 장식 개수로 피해 이벤트를 늘리지 않는다. 실제 연타는 기존 패턴의 각 스텝별 예고와 판정을 사용한다.

하단 가시는 T에서 올라와 T+40ms에 정점, T+140ms 안에 잔해까지 퇴장한다. 성공한 위 회피는 판정 순간 발이 바닥보다100px 높게 보이도록 보정하고(최소96px), T+140ms까지 유지한 뒤 T+220ms에 착지한다. 기존 무적160ms·완벽60ms를 늘리지 않는다. 경계 입력의 급격한 자세 변화는 짧은 도트 잔상으로 연결하되 실제 경계 프레임 검수가 필요하다. 실패 시는 지면에서 피격하고 회피 성공 장면처럼 띄우지 않는다.

색 외에 지면/머리/앞/뒤 위치와 물체 실루엣으로 구별한다. 밝은 크림색 접점과 어두운 외곽을 사용한다. 현재 신호는 채워진 재료와 수축 접점, 다음 신호는 작은 빈 실루엣만 사용한다. 다음 신호가 현재의 큰 가시·무기와 같은 강도로 켜져서는 안 된다. 동시 신호 배치와 같은 방향 연타는 후속 제작 검증 항목이다.

## 4. 플레이어 공격과 타격감

입력 후100ms 명중 사건에 검흔·적 접점·피해 숫자·명중음을 동기화한다. 온은80px 정도 전진하고, 초승 검흔 끝에서 적의 몸통·갑옷 접점까지 황동빛 종의 잔향을 잇는다. 파수병 시안의 접점은(866,505)이며, 내민 도끼가 아니라 갑옷에서 불꽃과 파편이 발생한다. 적마다 실제 몸통 기준 접점을 따로 지정한다. 기존 칼 그림과 큰 적 사이에 빈 공간만 남은 채 적이 맞는 것처럼 보이지 않게 한다. 이는 사거리 판정 변경이 아니다.

본베기는100–180ms(80ms), 잔흔 페이드는180–220ms로 나누고 자세 회수는280ms에 끝낸다. 다음 공격 가능500ms는 유지한다. 일반 피해 숫자의 도트 셀6px, 치명타9px(1.5배)로 그린 시안을 사용한다. 샘플64/128은 연출 비교용 숫자로 게임 피해 공식이 아니다. 치명타는 접점 불꽃·사각 파편을 키우고 기존80ms 화면 흔들림을 연결한다. 보드에는 검흔과 팝업을 보여주며 실제 카메라 흔들림은 구현 검증 대상이다.

적의 현재 예고가 플레이어 검흔보다 읽기 우선이다. 장식은 그리기 순서·밝기·밀도를 낮춰 억제하며, 검흔이 또 다른 위험 영역처럼 보이지 않아야 한다. VFX 자체가 피해를 계산하거나 중복 명중 이벤트를 발생시키지 않는다.

## 5. 처치 후 이동과 5겹 배경

일반 적 처치 전환은1.40초: 분해0–0.55, 전진0.55–1.20, 정착1.20–1.40. 이동 동안 온은 화면의 중심 구간을 지키며 달리고, 다음 적이 오른쪽에서 다가온다. 한 이동의 바닥 진행량은160px/650ms 초깃값이다.

|레이어|속도 비율|160px 이동 시 왼쪽 이동|정렬 순서|
|---|---:|---:|---:|
|달·하늘|0.02|3.2px|-50|
|먼 성벽·첨탑|0.08|12.8px|-40|
|중경 아치·성문|0.22|35.2px|-30|
|가까운 기둥|0.48|76.8px|-20|
|바닥·접지면|1.00|160px|-10|

직교 카메라에서는 깊이 z만 다르게 두어도 자동 원근 차가 생기지 않는다. 현재 MVP는 직교2D를 유지하고 `offset = -cumulativeTravel × factor`로 층별 이동량을 계산한다. z/Sorting Order는 겹침 관리에 사용한다. 원근2.5D는 실제 카메라 이동과 거리 차로 패럴랙스를 얻을 수 있지만 픽셀 밀도·크기·입력 구도를 다시 검증해야 하므로 이번 권고안으로 선택하지 않았다. [Unity Learn 카메라와 자동 패럴랙스](https://learn.unity.com/tutorial/working-with-unity-cameras-questions?version=2019.4), [Unity6000.3 카메라 문서](https://docs.unity.com/en-us/engine/6000.3/manual/cameras/overview).

각 스테이지 전환에서 누적 이동을0으로 되돌리지 않는다. 보이지 않는 이음매에서만 타일을 순환한다. 논리 이동은 소수로 보존하고 화면에 그릴 때만 픽셀 격자로 반올림한다. 매 프레임 소수 이동을 버려 원경이 영원히 움직이지 않는 문제를 피한다. 전투·보스 포효·사망 로비에서는 가로 배경 이동을 멈춘다. 비전투 줌의 비정수 배율은 허용하되 선명도·떨림은 기기에서 검수한다.

현재 한 장으로 합쳐진 배경을 완성된 다층 자산이라고 간주하지 않는다. 달/하늘, 원경, 중경, 기둥, 이음매 없는 바닥을 분리 제작하고 가려졌던 부분도 복원한다. 적·HP·버튼과 겹치는 전경 물체를 두지 않는다.

## 6. 사망·보상·전환 계약 유지

사망은 온 분해0–0.55초, 암전0.25–0.70, 어둠 유지0.70–0.85, 등불/로비 공개0.85–1.60, 정착1.60–1.80초다. 등불 중심(520,130). 로비는 암전 아래 준비하고 전체가 읽힌 뒤 새 입력만 받는다. 사망 당시 누르고 있던 입력이 출전이나 강화로 넘어가지 않게 비운다.

보스 처치 순서는 처치확정·보상원장 저장 → 분해 → 같은 유물3후보 중 선택 → 선택 결과 저장 → 전진 → 다음 적 등장 → 온전한 첫 예고다. 10층마다 로비로 돌려보내거나 계속 확인창을 띄우지 않는다. 체크포인트는10층 단위이며5층은 만들지 않는다. 9층 실패→Stage1, 11층 실패→Stage11을 유지한다. 보스 보상·최대HP 반영·회복은 기존 세션 계약에 따른다.

세션이 전투·보상·영구 진행을 소유한다. Presenter는 표시만 맡고 독립적으로 다음 층이나 로비를 결정하지 않는다. 연출 동안 전투시계를 멈추고, pause/비활성 때 연출시계도 함께 멈춘다. 과정 재개는 같은 시점·구도로 복귀한다. 프로세스 재시작은 저장된 목적상태(다음 적 대기/미선택 동일3후보/선택완료 후 다음 적/사망 로비)로 복구하고 보상·괴성 콜백을 중복 발행하지 않는다. 저장 오류에서는 기존 복구 UI를 우선한다.

동시 사망 우선순위는 기존 세션 판정에 따른다. 새 전투시작 전 기존 눌림을 비우고 첫650/900ms 예고를 온전히 제공한다. 모션 줄이기는 카메라 줌·흔들림·배경 스크롤과 장식 잔해를 줄이되 가시/무기 낙하의 필수 공격 궤적을 없애지 않는다. 총 길이와 조작 복귀시점은 동일하다.

CC0 팩의 상업 사용 조건은 [Kenney 공식 설명](https://kenney.nl/support), 음악은 [제작자 라이선스](https://incompetech.com/music/royalty-free/licenses/)와 [CC BY4.0 원문](https://creativecommons.org/licenses/by/4.0/)을 따른다. 최종 파일을 받을 때 원본 라이선스 사본·파일명·출처·해시를 기록한다. 실제 사용 곡만 접근 가능한 게임 크레딧에 올리고, 편집했을 때만 해당 수정 내용을 적는다. 조건부 허용을 저작권이 없다는 표현으로 바꾸지 않는다.

괴성2종, 짧은 종 울림, 가시 예고음, 등불 점화는 직접 녹음·합성이 필요한 항목이다. 기존 팩이 완성 포효를 포함한다고 가정하지 않는다. 자체 녹음의 제작자 동의와 출처도 기록한다.

큐시트13개: 휘두름, 명중, 치명, 가시, 후방 무기 출발/착지, 중간 보스/보스 포효, 달리기 발소리, 등불, 전투/보스/로비 BGM. 예고와 실제 명중은 서로 다른 소리다. 회피 성공에 명중음을 붙이지 않는다. 장식 무기3발은 핵심 착지음 한 묶음과 낮은 잔향으로 믹스한다.

Master/Music/SFX를 나누고 포효 때 BGM -6dB를 초기 청음값으로 삼는다. 수치는 실측 완료가 아니다. 스테이지마다 전투 곡을 다시 시작하지 않으며 BPM으로 판정을 구동하지 않는다. 죽음·기절·일시정지·연출취소 시 예약된 후속 소리를 정리한다.

## 8. 다음 제작의 자산과 검증

MVP 5종 적의 실제 사용 방향은19개 조합이다. 방향별 준비2프레임씩38개와 발동19개를 우선 예산으로 잡는다. 회수는 기존 대기/공격에서 재사용 가능 여부를 검토한다. 보스2종의 준비·포효·회수3포즈씩6개, 온 달리기 최소4프레임, 네 위험 VFX, 플레이어 검흔/접점, 배경5층, 오디오 선별·자체 제작을 별도 관리한다. 확정 공수나 전체50종 신규 프레임 수로 오인하지 않는다. 기존 원형과 구역별 재질 변형을 활용하되 예고 의미는 고정한다.

- 체급 비교와 클로즈업에서 얼굴·핵·후광, 전투 복귀 후 양측 발/HP를 확인한다.
- 포효 구간의 배율·중심이 고정되고, 포효 종료→줌아웃→정착→첫 예고 순서를 로그로 검증한다.
- 650/900/250ms, 네 방향, 같은 방향 연타, 무음·흑백·모션 줄이기에서 현재 신호가 먼저 읽히는지 확인한다.
- 위 회피 입력 경계 -160/-60/0ms 근처의 성공/실패 모습과 가시 접촉이 모순되지 않아야 한다. 보정은 무적 시간을 늘리지 않는다.
- 파편·무기 개수와 무관하게 스텝당 피해1회. 장식과 실제 연타를 구분한다.
- 10회 연속 이동에 원경 누적·바닥 이음매·발 접지·적 조우가 튀지 않으며 전투 중 정지한다.
- 보상/사망/등장 중 중단·재시작에 보상, 후보, 체크포인트, 오디오 중복이 없어야 한다.
- 최소640×360 및 안전영역, 실기기 픽셀 떨림과 오디오 청음을 후속 제작에서 확인한다.

이번 검증은 오프라인 Canvas 렌더와 페이지 핸들러·정적 링크 검사다. 브라우저 CSS/터치, 실제 오디오, Unity 실행 검증을 대체하지 않는다. 역할별 검토는 `../Reviews/presentation-v2-art.md`, `presentation-v2-flow.md`, `presentation-v2-research.md`에 기록한다.
