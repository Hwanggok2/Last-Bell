# 마지막 종지기 · 전투 연출 기획 01

2026-10-21 KST · 기획 초안. Unity 코드·프리팹·카탈로그·빌드는 변경하지 않는다.

## 결정과 시각 자료의 권위

사용자 요청은 ①세 번째 적 확대 ②공격 예고 리디자인 ③적 처치 후 분해·전진 및 플레이어 사망 후 분해·암전·등불 로비 ④중간 보스·보스의 줌·괴성 등장이다. 기획 보드 `index.html`은 비교·재생용, `proposal.json`은 이 제안의 수치 원본이다. 게임 데이터 원본인 `GameData/mvp-catalog.json`을 대체하지 않는다.

생성 분위기 보드는 장면의 방향만 설명한다. 실제 인물 비율·HUD·위험 위치는 기존 스프라이트와 메타데이터를 쓰는 canvas 배치가 기준이다. 이는 Unity 캡처가 아니며, 달리기·분해·포효의 완성 애니메이션도 아니다. 입력·시계·저장 동작은 아래 구현 계약이며 현재 동작으로 표시하지 않는다.

## 1. 재의 불씨 확대

대상은 현재 MVP Stage 3·7의 `ash_wisp`, 표시명 재의 불씨. 50종 제작 명단의 세 번째 몬스터와 혼동하지 않는다. `MvpArtCatalog.asset`의 height가1.0이며 `ActorView.ApplyArt`가 대기 스프라이트의 전체 bounds 높이로 정규화한다. 투명 여백 문제보다 의도적으로 작은 height가 직접 원인이다.

전체 높이1.0→1.5, 주인공1.1 대비0.91→1.36배. 정면 폭도 같은비율로 확대한다. 중간 보스1.8·보스2.1의 위계를 유지한다. 현재 카메라의1280×720 환산에서 약116→174px, 대기폭약69→104px다. 단순한 정수픽셀 배율처럼 보장하지 않으며 최종 Pixel Perfect 정책에서 재확인한다.

향후 적용은 저장된 ArtCatalog의 해당 항목에 한정한다. `MvpArtImporter`의 기본값도 별도 변경 대상이지만 임포터 재실행으로 기존 카탈로그 전체를 덮어쓰지 않는다. 대기/공격/기절 공통 scale, 발 pivot, 부유 높이, HP 위치를 함께 확인한다. 판정거리·전투HP·예고시간 변경은 이 제안에 없다.

## 2. 공격 예고: 금 간 종의 잔향

선택안 A는 금이 간 황동 잔향이다. B는 종틀 각인으로 장식비중이 크고, C는 적 무기 잔상으로 몬스터마다 다른 가독성 문제가 있어 주 예고로 채택하지 않는다. A의 네 위치·형태는 `proposal.json`을 따른다. 위/아래는 수평 열린 띠, 정면은 짧은 세로균열, 후면은 오른쪽으로 열린 C형. 삼각 화살촉은 조작 버튼에만 남긴다.

밝은 핵12×12px·암청 외곽16×16px, 현재띠10px·암청받침14px를 기준으로 한다. 12px 형태슬롯에서 접점외곽은 양쪽2px 돌출하므로 최대영역을 함께 검수한다. 다음예고는4px점·16px간격이며 슬롯은 바깥16px이다. 하단슬롯은 y560, 플레이어HP 상단은y601, 다음점선의외곽하단은약y586이므로15px 여유다. 등불/광원중심은(520,130)으로 캐릭터미리보기상단빈공간에 두고스탯패널을가리지않는다.

위험과 대응의 의미를 구분한다. 머리 위 위험→▼, 발밑 위험→▲, 정면(오른쪽) 위험→◀, 후면(왼쪽) 위험→▶. 현재 공격은 연결된 분절·밝은 사각 접점, 다음 공격은 바깥16px에 놓인 점유율25%·밝기55% 점선·접점없음. 동일 방향의 연속타격도 두 띠가 겹치지 않는다. 640×360에서 접점6px·띠5px, 현재/다음 구분과 HP 이격을 확인한다.

기존650/900/250ms와 실제 `EnemyIntent.Progress`가 원본이다. 별도의 UI 애니메이션 타이머로 타격시점을 정하지 않는다. 장식은 예고 시작부터 위험위치를 보여야 하며250ms 후속 예고에는 등장 지연이 없다. 소리와 색을 제거해도 위치·형태·점선·접점으로 읽힌다. 빠른 점멸은 사용하지 않는다.

현행 Canvas 기준960×540와 보드1280×720의 환산은4/3이다. 보드 좌표 원점은 좌상단이며 Safe Area 인셋0이다. 실제 기기에서는 안전 영역 안에 배치하고 좁은 화면에서 입력과 세계영역을 함께 검토한다. 포즈별 캐릭터 머리를 추적하지 않고 기본 발 좌표에 예고를 고정한다.

게임 문구를 늘리지 않는다. 튜토리얼에만 기존 단일 행동 문구를 유지하고, 전투 중 위/뒤/기절/보스등장 설명을 붙이지 않는다. 보드의 설명과 시간표는 게임에 들어가지 않는다.

## 3. 승리와 이동

일반 적 0.00–0.55초: 처치 확정 후 실루엣에서8~12개 구역이 빠지고 각 구역의 사각 도트가 중력 방향으로 떨어진다. 전체 alpha만 줄이는 사망은 목표가 아니다. 0.55–1.20초: 온의4~6프레임 달리기와 원경/중경/바닥의 왼쪽 이동으로 전진한다. 1.20–1.40초: 발 위치와 카메라 정착. 다음 적의 이름/스테이지는 새 조우가 성립한 정착 구간에 바뀐다.

중간 보스 분해0.70초, 보스 분해0.85초 후 유물3택1. 선택 전에는 이동하지 않는다. 선택 확정 후 획득반응0.20초 + 전진0.65초 + 정착0.20초 =1.05초. 사용자 선택 시간은 제한하지 않으며 연출총시간에 포함하지 않는다. 10층 보상 후에도 같은 흐름으로11층으로 이어진다. 11층 경계 표본 종료와 미래50층 엔딩은 기존 별도 경로를 유지하며, 없는12층/51층으로 자동생성하지 않는다.

처치 확정 순간 게임 세션이 보상 원장·적처치·다음 진행을 한 번 기록한다. VFX 종료 이벤트는 보상 권한을 갖지 않는다. 일반 처치 후 현재런의HP는 유지하고, 다음 전투 시작에는 공격·회피를 준비 상태로 명시적으로 초기화하는 안을 제안한다. 현행 BeginStage가 재사용 시각을 초기화하지 않는 점과 다른 변경이며 구현 시 테스트해야 한다. 연출 중에는 전투 시계·재사용·기절타이머가 흐르지 않는다. 처치된 적의 기절/예고는 제거한다. 중복 OnComplete·재진입·두 번 선택에도 보상이 중복되지 않아야 한다.

## 4. 사망과 등불 로비

0.00–0.55초 플레이어 분해, 0.25–0.70초 겹쳐서 암전, 0.70–0.85초 짧은 어둠, 0.85–1.60초 불씨→점등→계단형 빛 확장, 1.60–1.80초 로비 정착. 검은 화면을 오래 유지하지 않는다. 온의 금빛 파편은 기존 피격보다 느리게 아래로 떨어지고, 보상처럼 지갑으로 흡수되지 않는다.

로비 패널은 암전 아래 준비한다. 좌측1/4 캐릭터 목록, 우측 idle·스탯, 우상단재화, Stage출전 표기는 기존대로 유지한다. 등불은 장식이며 클릭대상이 아니다. 전체 화면이 읽히고0.20초 안정된 뒤 강화·유물·출전 버튼 입력을 연다. 사망 당시 눌러 둔 포인터/키를 새 로비 버튼으로 전달하지 않는다.

## 5. 중간 보스·보스 등장

|구분|줌인|괴성|줌아웃|정착|최대 줌|재조우|
|---|---|---|---|---|---|---|
|중간 보스|0–0.35s|0.35–0.80s|0.80–1.20s|1.20–1.40s|1.12×|0.80s|
|보스|0–0.45s|0.45–1.10s|1.10–1.60s|1.60–1.80s|1.18×|1.00s|

재조우 분할은 중간보스0.18/0.24/0.18/0.20초, 보스0.22/0.33/0.25/0.20초다. 같은 캐릭터·회차·보스ID의 등장 완료를 기록한다. 앱 중단으로 첫 연출을 끝내지 못했다면 완료로 마킹하지 않는다. 최초 등장 전체를 기본으로 하고 반복에서는 짧은 줌·괴성을 유지한다.

카메라는 보스의 상체와 무기를 보여주되 플레이어 위치와 발을 완전히 지우지 않는다. UI는 줌 대상에서 제외한다. 등장 중 예고와 종게이지를 숨기고 상단 보스 HP는 마지막0.20초에 실제값 그대로 페이드인한다. 가짜HP 채우기 애니메이션은 쓰지 않는다. 줌아웃 완료·정착 후에야 전투시계를 시작하여 온전한 첫650/900ms를 보장한다.

괴성 음원은 현재 미제작. 수문장은 문 경첩·낮은 종·숨소리, 종기사는 깨진 종·금속 호흡의 방향. 단순 볼륨 상승보다 음색과 길이로 차별화한다. 무음에서도 가슴의 밝은 핵·각진 두 잔향으로 같은 구간을 표현한다. 화면 전체의 흰색 점멸은 금지한다.

## 6. 시계·중단·재개

게임 세션이 전투·보상·영구진행을 소유한다. 작은 명시적 전환상태와 완료/취소 계약을 추가하는 것이 향후 구현안이다. Presenter는 연출표시만 하고 독립적으로 다음층이나로비를 결정하지 않는다. 연출시계는 전투시계와 분리하되 일시정지·앱비활성에서 둘 다 멈춘다.

현재 프로세스의 일시정지는 연출시점/카메라를 그대로 유지하여 재개한다. 재시작은 연출프레임을 영구저장하지 않고 원자적으로 기록된 목적상태에 복구한다: 일반처치면 다음 적 대기, 미선택 보스보상이면 같은3후보, 선택완료면 다음 적 대기, 사망이면 로비. 저장오류가 있으면 기존 복구 UI를 우선하며 다음상태로 밀어붙이지 않는다. 복귀 후 사용자의 계속 입력으로 전투를 재개하고 첫예고를 온전히 보장한다. 괴성·보상콜백은 다시 발행하지 않는다.

양쪽이 같은 틱에 죽는 경우는 기존 세션의 판정우선순위를 그대로 사용한다. 연출이 임의로 승리를 선택하거나 보상을 더하지 않는다. 전환 동안 입력을 버리고, 첫전투시점에서 눌림상태를 비워 새로운 눌림만 받는다.

모션 줄이기에서는 줌·흔들림·횡스크롤을 제거하고 입자를 절반으로 낮추며 짧은 자리 교차 전환으로 이동을 표현한다. 길이와 조작복귀 시점은 바꾸지 않는다. 재조우 단축과 접근성 감소모션은 별도 옵션이다. 무음·진동꺼짐에서도 예고·기절·보스등장이 읽혀야 한다.

## 7. 다음 구현의 검증 기준

- Stage3의 대기/공격/기절이50% 확대되고 HP·위험예고·피해숫자와 충돌하지 않음.
- 네 위험방향·동일방향연타·흑백에서 현재/다음 예고를 구분. 640×360·최소Safe Area에서 하단 다음예고와HP 사이1280기준15px(640기준약7.5px) 여유 재확인.
- 처치10회 연속에서 입력잠금1.40초, 이음매·적 순간교체·전투판정 혼입 없음. 실제 플레이 후 반복 지연 평가.
- 보스 등장 전/중/후 입력연타와 키홀드에 숨은피격/선공없음. 정착 이후 첫650/900ms를 로그로 확인.
- 사망·보상선택·일반처치·보스등장 각각에서 pause/앱중단/프로세스재시작. 보상/후보/체크포인트 중복이나손실없음.
- 괴성off,모션감소on,저프레임 조건에서 첫예고/HP/입력시점동일. 최대파편수와드로콜은기기측정후결정.
- 체크포인트는10층기준,9층실패→Stage1·11층실패→Stage11;5층처치는체크포인트를만들지않음.

브라우저 모형이 이 계약을 자동으로 검증한 것은 아니다. 계획 검토·오프라인 시각 검사·향후 Unity 테스트를 각각 구분해 기록한다.
