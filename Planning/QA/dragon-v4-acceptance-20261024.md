# Dragon-v4 · v0.9.3 완료 기준과 최소 QA 설계

2026-10-24 KST · **QA_COMPLETE_WITH_RECORDED_LIMITS · 최종 candidate03 4프로세스/1,037 checks PASS, Console0**

최신 상태: DQA4-001/002 QA 진단기 수정, DQA4-003 제품 Stage11 전진 수정 모두 재검증·종결했다. 최종 scope는1280 Stage11 표적/1280 resume/640 fresh/resume이며 이미 통과한1280 기능·대사는 반복하지 않았다. [종합 결과](dragon-v4-result-20261024.md)와 개별 결함 기록을 따른다. 실입력/모바일 DEFERRED, 직접 청음 NOT_RUN, 정확한 동시 voice NOT_CERTIFIED는 유지한다. 아래 준비 기록은 최초 인계 시점의 이력이다.

총괄의 v0.9.3 요청과 후속 허가에 따라 검증안·V4 전용 probe/runner/analysis를 작성했다. 기존 entry에 V4 분기만 추가했고 V3 본체는 유지했다. 별도 허가된 Player defines 독립 소스 컴파일1회와 구문 검사만 수행했다. **QA 실행, Unity, 빌드, 이전 candidate 재실행은 하지 않았다.** 새 후보·실행권을 인계받은 뒤 한 차례 batch QA를 수행하고, 발견한 결함은 수정 범위와 직접 인접한 경계만 재검증한다. 실행 방법과 한계는 [V4 도구 설명](../../Tools/QA/Dragon-v4/README.md)을 따른다.

사용자의 **“실입력 검사는 나중에 진행”** 지시는 계속 유효하다. 모바일 터치 UI 구현 요청을 OS 마우스·키보드나 실기기 입력 검사 재허가로 해석하지 않는다. 아래 터치 경로 검사는 향후 허용된 관측 probe의 합성 UI 이벤트를 뜻하며 물리 입력·멀티터치 사용성 검증과 구분한다. 사용자 기본 저장은 `NOT_ACCESSED`, 새 격리 프로필과 합성 구 저장만 사용한다.

## 기준과 변경 경계

- 목표 앱 버전은 **0.9.3**이다. 최종 데이터 버전·저장 namespace·실행 경로·스킬 세부 효과는 통합 인계에서 고정한다. v0.9.2 값으로 추정하지 않는다.
- [v3 결과](dragon-v3-result-20261024.md)는 기존 범위의 회귀 참고 자료다. 새 기능의 합격 근거로 재사용하지 않는다. 승인된 변경 외 적 예고/접촉 시각, 기본 조작, 경제·보상·체크포인트는 보존한다.
- 이전 [전용 스킬 기획](../Story/Dragon-v1/character-skills-v1.md)의 **3칸 충전·다음 평타 발동·다렌/미엘 잠금**은 이번 완료 기준이 아니다. 새 요청인 **3명 선택 가능·각 전용 스킬 버튼·20초 쿨타임**이 우선한다. 이전 피해 배율·보호막·기절 수치를 QA가 확정값으로 가져오지 않는다.
- 캐릭터 stable ID는 `on=루카`, `dam=다렌`, `rin=미엘`을 대조한다. NPC 리나(`rina`)와 미엘을 혼동하지 않는다. 만남 대사 보완이 Stage21~50 구현을 자동으로 뜻하지 않는다.

원본의 `speaker='player'`, `portraitId='player'`는 Core가 현재 선택 캐릭터 `on/dam/rin`에 맞게 해석한다. 렌더 기대값은 **`session.Story.Text / Speaker / PortraitId`**다. 원본 `scene.lines[i].text/speaker`를 렌더와 직접 비교하지 않는다. 세 캐릭터 각각에서 Core 해석이 인계된 이름·초상화·문구 정책과 맞는지 먼저 확인하고, 이후 UI가 해석 결과를 그대로 표시하는지 대조한다. 이 두 검증을 분리해 Core와 UI가 같은 잘못된 값으로 일치하는 경우도 놓치지 않는다.

후속 지시에 따라 기존 `V3StoryTwenty`는 변경하지 않고 새 V4 시나리오에 해석된 대사·초상화 비교를 구현했다.20층6페이지와10층3페이지를 구분하며 전체 장면은2층6·7층5·10층3·15층5·20층6페이지다. `???` 초상화는2층 첫 줄 unknown,7층 첫 줄 rina,15층 첫 줄 barun,20층 둘째 줄 doto이며 일괄 실루엣으로 검사하지 않는다.

## 통합 후 한 차례 batch QA

한 batch는 한 동결 후보에 대한 캠페인이다. 파일 복원과 native 재시작을 구분하기 위해 **1280 관측→같은 격리 저장 재시작,640 관측→같은 격리 저장 재시작의 총4프로세스**를 기본안으로 한다. 실제 프로세스 수는 최종 실행 인계에 명시한다. 기존 후보 실행기는 재사용 호출하지 않고 v0.9.3용 경로·모드·저장 정책을 확인한 뒤 실행한다.

| 순서 | 최소 범위 | 남길 근거 |
| --- | --- | --- |
| 0 · 소스/데이터 동결 | 최종 후보·허용 변경·새 스킬/대사/오디오/아트 명세 확인, 변경 관련 Core 계약 한 묶음. 이미 같은 소스로 수행한 신뢰 가능한 결과는 근거와 함께 채택 | 소스/빌드/manifest 해시, 검사 버전·정확한 필터·결과. 광범위한 기존 모션/전수 suite 반복 금지 |
| 1 · 1280 관측 | 세 캐릭터 선택·출전·각 스킬 사용, 예고/기절바 상태, Stage11 실제 콤보와 마지막 회복, 새 대사 모든 페이지·소개 전후·복원, 대표 audio 트리거 | 필요한 정지 PNG, Stage11와 각 스킬 발동의 짧은 연속 구간, UI 이벤트·효과·쿨·재생 로그. 20초 전체 프레임을 저장하지 않고 Core 경계와 준비 직전/직후 렌더 결합 |
| 2 · 1280 재시작 | 중간 쿨·선택 인물·소개 후 대화 위치를 저장한 동일 경로 재기동 | 종료코드, 파일 해시, 복원 직후 실제 렌더 후 버튼·화자·초상화·쿨 비교 |
| 3 · 640 관측·재시작 | 같은 변경 UI·모션·대화 범위를 작은 화면에서 검토하고 동일 저장 재시작 | 1280과 같은 종류의 근거. 화면 축소로 가독성·터치 영역이 줄거나 겹치는지 별도 판정 |
| 4 · 분석·종결 | 이벤트·쿨/좌표·PNG 해시 대조, 대표 연속 프레임 직접 검토·오디오 청취, 설정 복구 | 항목별 PASS/FAIL/NOT_RUN, 실패 원본 보존, scoped 설정 원복·합성 구 저장 일치, OS 입력/실기기 미실시 명시 |

실제 입력 경로는 버튼 delegate 직접 호출만으로 합격시키지 않는다. 허용된 합성 pointer/click→UI 핸들러→세션 명령 경로를 관측하고 동일 입력의 중복 처리를 검사한다. 이는 OS 입력 또는 모바일 터치 성공의 증거가 아니다. 대화 파일 복원은 `Bind` 뒤 실제 렌더를 기다린 후 검사한다. stage 이름이나 시나리오 라벨 대신 **실제 motion·clip·phase**를 읽으며, 강제 Attack 프레임 샘플을 실제 전투 회복 증거로 사용하지 않는다.

프레임 기록은 기존 연속 수집 구조를 활용할 수 있으나, 마지막 타격 이후 복귀까지 충분히 포함한다. 발 피벗 Y 오차와 수평 루트 이동을 따로 계산하고 카메라 흔들림을 제외한다. readback 비용이 있는 관측을60fps 성능·정상속도 체감 인증으로 부르지 않는다. audio 로그는 실제 출력·청취의 대체 근거가 아니다.
