## 측정과 증거 수집

- 전투 경계는 결정적 논리 검사로, 화면 타이밍은 정상속도 GPU 실행으로 나누어 측정한다. 기존 smoke는 가속 진행·직접 UI 호출·이펙트 정리를 포함할 수 있으므로 정상속도 품질/실입력 증거로 사용하지 않는다.
- 로그의 최소 열: candidate, scenario, frame, realtime, combatTime, presentationTime, phase, stage, input(direction/time), HP, damage/reward/save 횟수, variant/clip/frame, playerX, cameraZoom. 실제 제공되는 관측 지점과 수집 방법을 기록한다. 로그가 없으면 영상·자동검사 근거를 결합하며 측정 불가를 통과로 바꾸지 않는다.
- 24fps 달리기는 원본 8자세와 표시 반복 수를 구분한다. 60fps 영상에서 한 자세가2~3프레임 보일 수 있다. GIF의 표시 프레임 수를 런타임 원본 장수로 세지 않는다.
- 시간표마다 기대/실측/차이/프레임 간격을 남긴다. 일시정지 시간을 제외하며 배경 거리는 누적 offset·wrap 전 거리로 계산한다. 실제 픽셀과 기획1280 좌표 변환도 함께 기록한다.
- 포인터 검사는 실제 OS 입력과 Unity PointerDown 자동 주입을 구분한다. 키보드는 WASD/방향키·Space·Esc를 사용한다. 실제 터치 장치가 없으면 모바일 터치·물리 지연 검증은 미실행으로 명시한다.
- 각 필수 항목에 `소스/데이터`, `자동`, `GPU 렌더`, `실입력/청음` 중 필요한 증거를 붙인다. 에디터 테스트 로그에 새 오류가 있으면 테스트 개수만 보고 통과시키지 않는다.

- 명중/치명/막타 숫자와 흔들림은 가능한 같은 진행에서 수집한다. 드문 사건을 무작정 기다리지 말고 결정적 테스트·별도 테스트 프로필 표본으로 보완하고 방법을 명시한다.

### Q03 — 전투·완료 프레임 경계 (AC-03~08, 16)

전체 주행을 되풀이하지 않고 테스트 fixture 또는 같은 후보의 전투 표본을 사용한다. 내부 fixture 검증은 실제 입력 경로 검사와 분리한다.

| 분기 | 입력/상태 | 기대 |
| --- | --- | --- |
| 일반/완벽 창 | D−T = −161, −160, −61, −60, −1, 0, +1ms | 실패, 일반, 일반, 완벽, 완벽, 완벽, 실패 |
| 실패 원인 | 정확T에서 오방향·미입력·재사용 미충족 | 피해가1회 확정; flash/HP가 일치 |
| 재사용 | 직전 회피 후259ms/260ms | 미준비/준비; 추가 유예 없음 |
| 완료 프레임 | 100% 최초 렌더→다음 Update의 올바른 PointerDown | D=T로 피해보다 먼저 처리 |
| 완료 화면 pause | 100%에서 pause→resume | 완료 화면 재제공, 입력 우선 유지 |
| 저프레임·연타 | 보통 delta와 경계를 넘는 큰 delta | 잔여 시간 보존, 타격마다 완료 화면,450/250ms 계약 유지 |
| 공격 취소 | 200ms 직전·명중 뒤 회피 | 앞은 예약 피해0, 뒤는 피해1 유지,500ms 쿨 유지 |
| 공격 연타 | 499ms/500ms와 누른 채 입력 | 조기 추가 공격 없음, 준비 후 정상 공격 |
| 변형 난수 | 6조합 매핑·직전 제외·pause/redraw·동일 전투 seed | 시각 선택 고정, 치명/보상 결과 불변 |

−161ms 표본은 입력 자체가 금지된다는 뜻이 아니라 **타격 시점의 회피 유효창 밖이어서 그 타격을 피하지 못함**을 뜻한다. 순수 `Tick(T)` 후 소급 입력 성공을 요구하지 않는다. 실제 Presenter의 입력→`TickInputFrame`→Render 경로도 반드시 확인한다.

### Q04 — 사망·로비·체크포인트 (AC-12, 16~18, 21)

기본 주행에서 만든 테스트 분기를 사용해9층 사망→1800ms 등불 귀환→로비 정비→1층 재출전과 10층 선택 완료 뒤11층 사망→11층 재출전을 확인한다. 부활 비용·자동 재공격·사망 보상 중복이 없는지 본다. 강화·유물 장착·부족분 교환의 확인/취소 및 교환 후 별도 강화 명령은 기존 동작을 유지한다. 선택 전 체크포인트가 확정되는지 여부는 Q05에서 함께 검사한다.

### Q05 — 10층 서사·보상·저장 분기 (AC-13~17)

Q02에서 만든 유효한 테스트 저장 또는 명시된 테스트 fixture의 복사본을 사용한다. 각 분기는 독립된 프로필 이름과 시작 해시를 가진다.

| 중단/입력 지점 | 확인할 결과 |
| --- | --- |
| 처치 입력을 계속 누름 | 붕괴 후 첫 대사가 자동으로 넘어가지 않음; 모두 뗀 뒤 새 탭만 유효 |
| 대사1/2 표시 뒤 종료·재실행 | 보스 재처치 없이 미완료 줄부터, storyPending이 relicPending보다 우선 |
| 대사 전부 읽기 | 정확한 3대사 뒤 유물3택1, 읽는 동안 시간/HP 불변 |
| 대사 건너뛰기 | 현재 장면 seen 저장, 유물은 선택 대기; 자동 선택/생략 없음 |
| 대사 완료/스킵 저장 후 재실행 | 대사 반복 없이 같은 유물 후보ID·선택권 복구 |
| 유물 선택 전 재실행 | 보상·후보 고정, 체크포인트 선확정 없음 |
| 선택 저장 후 재실행 | 선택·레벨/골드·회복·체크포인트 한 번,11층 안전 재개; 중단 없는 선택 후 전환은2000+700ms |

원본 저장 손상/백업·양쪽 손상·지원하지 않는 버전 검사는 복사된 테스트 프로필에서 수행한다. 실제 파일 쓰기 실패를 검증한 경우와 mock 실패를 구분한다. 진행 중인 공유 폴더의 권한이나 사용자 저장을 변경해 실패를 유도하지 않는다.

### Q06 — 일시정지·앱 복귀·재조우 (AC-06, 09~12, 15~17)

전투 예고/100%대기, 분해, 이동, Stage, 줌인/확대 유지/줌아웃, 사망 암전, 대사, 유물 선택에서 pause/resume 표본을 한 번씩 모은다. 일시정지 전후 combatTime/presentationTime·HP·층·후보/보상을 비교한다. 전환 입력 연타는 폐기되어야 한다.

앱 포커스 이탈/복귀와 정상 종료 후 별도 프로세스 복원은 다른 검사로 기록한다. 전환·사망 중 저장 복원은 인계된 안전 재개 정책을 대조하고, 같은 HP/층/보상 및 다음 온전한 예고를 보장하는지 확인한다. 저장에 남은 완료 프레임을 재활용해 이미 확정한 타격을 되돌리지 않는다.

재조우 상태의 전용 테스트 복사본에서 중간1500ms·보스1700ms와 포효 공격1회·실제 피해0을 확인한다. 정상 게임플레이로 아직 도달할 수 없는 상태는 fixture임을 명시하고 실제 재조우 플레이 완료로 확대하지 않는다.

### Q07 — 해상도·Safe Area·실입력 (AC-18, 21)

전체 주행을 해상도마다 반복하지 않고 같은 후보의 주요 화면 상태를 사용한다.

| 렌더 크기 | Safe Area 표본 | 확인 화면 |
| --- | --- | --- |
| 960×540 | 전체 화면 | 전투·포효/Stage·pause·대사·유물·로비·강화/교환 |
| 640×360 | 전체 화면 및 비대칭 inset | 전투 네 버튼·대사/skip·유물·로비·강화/교환 |
| 1280×540 | 전체 화면 및 가로 inset | 위 주요 화면, 배경 끝/타일, 화면 밖 UI·입력 오프셋 |

Safe Area 시험 사각형은 테스트 환경에만 적용하고 실제 `(x,y,width,height)`를 기록한다. 좌우 어느 쪽 노치도 검사하며 상하 inset을 한 표본에 포함한다. 시뮬레이터/테스트 주입과 실제 기기를 구분한다. 최종 빌드 자체의 Safe Area 적용 코드를 우회해 화면을 수동으로 옮기지 않는다.

실제 OS 포인터와 키보드로 튜토리얼 입력, 네 회피·공격·pause/resume, 대사/skip, 유물 선택, 로비 조작을 확인한다. 눌림 유지·연타·줌 복귀 후 버튼 위치도 확인한다. 모바일 실기기나 오디오 출력이 없으면 해당 한계를 결과에 남긴다.

### Q08 — 음향·감소 모션 (AC-19, 20)

최종 `audio-provenance.json`의 Kenney CC0 4개+직접 합성8개를 실제 사용하는 파일·생성 절차·출처·크레딧과 대조하고 실제 출력으로 전투/명중/포효/귀환을 확인한다. 합성 원본 경로는 `Client/Tools/build_presentation_audio.py`다. 켜기→mute→pause/복원→재실행 순서에서 설정과 무음이 유지되는지 본다. 소리 없는 얼굴 포효/공격1회도 확인한다. 미사용 후보 음원을 내려받는 작업은 QA 범위가 아니다.

감소 모션은 일반 전환·보스 등장·공격/피해 숫자 표본만 비교한다. 줌/스크롤/흔들림 제거와 필수 궤적·배너·타이밍·판정 보존을 대조한다. 이 설정 때문에 전체 주행을 새로 시작하지 않는다.

### Q09 — 결과 묶음과 인계 (AC-01~21)

각 AC에 현재 후보의 근거를 연결하고 `PASS/FAIL/BLOCKED/NOT_RUN`을 결정한다. 빌드·자동검사·정상속도 화면·OS 입력·청음·모바일 실기기 여부를 각각 명시한다. 결함은 아래 양식으로 묶고 총괄이 `wait_threads`로 확인할 수 있도록 이 문서와 최종 답변에 결과를 남긴다. 다른 담당 파일을 QA가 직접 수정하지 않는다.
