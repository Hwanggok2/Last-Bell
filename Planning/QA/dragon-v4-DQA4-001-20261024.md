# DQA4-001 · 저장 복원 시간의 exact double 비교

**CLOSED · candidate02에서 다렌 파일 복원 경계 재검증 PASS.** `restoredDurations`의 다렌 cooldown/shield 차이0, 미엘 파일 복원2건과 세 캐릭터×5장면 story cooldown15건도 허용오차1e-6ms 안에서 통과했다. 정수 방패·같은 인스턴스 freeze는 정확 비교를 유지했다. candidate02 전체 실행의 단일 Console 실패는 별개 QA 문제 DQA4-002다. 아래는 발견 당시 이력이다.

**QA 단언 문제 / probe 수정 동결 / 새 관측 빌드·재검사 대기.** candidate01은 첫1280×720 fresh에서65 PASS /1 FAIL, native exit1로 중단했다. Console 오류0, timeout 없음.1280 resume·640 fresh/resume은 시작하지 않았다. 이후 총괄 승인으로 QA의 저장 시간 비교만 수정하고 `v4-tail` continuation을 준비했다. 제품 변경·재실행은 하지 않았다.

실패 위치는 `DragonThemeSmokeProbe.V4.cs`의 다렌 스킬 파일 복원 검사다. 쿨타임을 JSON 저장 전후 `==`로 비교했다.

| 보호막 양milli |1981000 |1981000 |

쿨타임 차이는 **−3.637978807091713×10⁻¹²ms, −1 ULP**다. 관측된 이 차이만으로 현재 exact 비교가 실패한다. 저장 payload checksum은 일치한다. 보호막 시간·양과 선택 인물은 일치하며 복원된 실제 PNG에도 방패 표식과20초 표시가 남아 있다. `recoveredBackup` bool은 별도 기록하지 않았으므로 이 보고서에서 직접 관측했다고 주장하지 않는다.

연속 프레임79장의 해시 불일치는0이다. 두 원본 PNG를 직접 열었다. pause 화면과 복원 뒤 화면의 패널 차이는 fixture가 재바인딩하면서 pause를 해제한 결과다. 게임·Editor scoped PlayerPrefs 원복과 합성 구 저장 sentinel은 일치했다. 실제 사용자 기본 프로필은 `NOT_ACCESSED`, 실입력·모바일은 보류다. 오디오 시나리오에는 도달하지 않았다.

승인된 수정은 JSON 파일/프로세스 복원을 가로지르는 duration 비교에만 **절대 허용오차0.000001ms**를 적용하고 expected/actual/delta를 기록한다. 동일 인스턴스의 pause·대화 동결, 캐릭터 ID·보호막 정수량·지갑 비교는 정확 비교를 유지한다. 대화 복원·native resume에도 같은 한정 규칙을 적용했다. 제품 저장·시간 정책은 변경하지 않았다. [2차 소스 동결](../Evidence/Dragon-v4/source-fix-20261024-02/verification.json).

후속은 새 QA 관측 빌드 인계 뒤 다렌 복원/방패와 아직 실행되지 않은1280 나머지 구간을 먼저 확인하고, 미실행 native resume 및640을 진행하는 범위로 제안한다. 이미 통과한 루카·선택 검사를 포함한 전체 fresh 재실행은 하지 않는다. 이후 기능은 아직 `NOT_RUN`이며 전체 QA 합격을 선언하지 않는다.
