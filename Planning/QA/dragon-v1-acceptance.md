# Dragon v1 — 완료 기준·측정·격리 저장 계약

작성: 2026-10-24 KST. 현재 상태: **요청된 자동·대표 시각 QA 완료**. 실제 합격 범위와 미검증 항목은 [최종 결과](dragon-v1-result-20261024.md)를 따른다. 아래는 준비 시점의 계약/작업 기록이며 NOT_RUN·미실행 표기는 현재 결과를 대체하지 않는다. 모든 해상도·OS 입력·모바일·최종 일반 빌드까지 포괄하는 무조건 합격 선언은 아니다.

이번 작업은 완료 기준과 명시적 CLI 관측 도구 준비다. QA 채팅에서 테스트·빌드·Unity/MCP 접근·게임 실행·실입력·사용자 저장 접근을 하지 않았다. 총괄은 2026-10-24 후속 통보에서 probe가 Unity 컴파일/Apply에 함께 통과했다고 확인했다. 소스 관찰과 컴파일은 동작 검증이나 제품 합격을 뜻하지 않는다. 기존 dirty 파일은 공동 작업이며 되돌리지 않는다. 승인된 QA 소유 범위는 이 문서, `DragonThemeSmokeProbe.cs`, `Tools/QA/Dragon-v1/`, 향후 `Planning/Evidence/Dragon-v1/`다. probe 소스는 관측 빌드를 위해 동결했다.

## 1. 범위와 기준 우선순위

이번 대상은 기존 MVP의 **Stage 1~10에 새 온·슬라임/뿔토끼/멧돼지·바람들판·밝은 도트 UI·서사/재화 표시를 적용**하는 것이다. 기존 판정·성장·유물·저장 보존이 전제다. 플레이어는 온 한 명이며 토리는 10보스 뒤 안내 역할이다. 신규 동료 전투·직업 해금·50층/브라크 엔딩·11~50 새 아트·공개 배포·엔진 업그레이드는 이번 완료 조건에 넣지 않는다. 기존 11~20 콘텐츠와 구 저장은 범위 밖이라는 이유로 삭제하거나 초기화하지 않는다. 10→11 및 11이상 구 저장은 연결/보존 경계만 확인한다.

기준 순서는 이번 사용자/총괄의 명시 지시 → 제작 완료 인계에서 확정한 변경 계약 → 새 시안의 해당 외형/문구 → 보존하기로 한 v8.6 실제 규칙이다. 새 JSON의 `미적용` 상태는 작성 당시 기록으로 읽으며 제작 승인 취소로 해석하지 않는다. 반대로 승인된 정적 시안을 완성된 Unity 스프라이트/모션으로 간주하지 않는다.

## 3. 보존할 기준값과 상태

아래는 읽은 v8.6 카탈로그/소스의 기준이다. 인계 시 고정한 기준본과 변경본을 대조하고 허용된 외형·표시 이름·적 아트 매핑 이외의 차이를 분리한다.

- 판정: 회피 유효240ms,회복120ms,완벽90ms. 일반 공격 명중200ms/간격500ms. 예고900ms,연속 타격 간격750ms,완벽 반격 기회1200ms. 기절 중 공격 속도1.2배 등의 기존 예외도 보존한다. 정확 접촉 프레임 입력 우선,오방향/미입력/쿨타임 실패,사후 소급 성공 금지와 미처리 delta 보존을 검사한다.
- 기절: 일반/완벽 누적20/40,문턱100. 100은 준비 상태이며 다음 살아 있는 적에 대한 명중에서 발동한다. 발동 타격은 일반 피해,충전만으로 연타 취소 없음,치사/동시 사망 추가 기절 없음. 기존 배율·지속/연장·면역 규칙 유지.
- 전환: 처치550ms,이동2000ms,도착700ms,사망1800ms; 중간/보스 첫 등장1800/2200ms,재등장1000/1200ms. 이 수치는 각 상태 시간이며 Stage를 별도 중복 가산하지 않는다. 10보스의 서사 진입 특례와 보스 퇴장 상태순서는 현행을 보존한다. 정적 시안의 패배 묘사를 이유로 새 대기/상태를 삽입하지 않는다.
- 성장: 네 스탯과 +1/MAX **견적→강화 실행** 유지. MAX는 실제 순차 비용·돌파 구간을 반영한다. 교환은 지갑 변경만 수행하며 추가 강화 입력이 필요하다. 골드/보석 표시 이름 변경이 비용·지급·확률을 바꾸면 안 된다.
- 유물: 보유 전체 자동 적용,출전 시 능력치 스냅샷,중복Lv.5까지,기본3종/최대10종,확장 비용4/8/12/18/26/36/48. 명시적 확장+획득/다른 후보/골드 대체,자동 지출 없음. 수동 장착 슬롯을 되살리지 않는다.
- 진행: 9까지 깨고10에서 패배하면Stage1,10처치 체크포인트는11. 보스 회복은 생존 상태에서만 적용하고 동시 사망을 되살리지 않는다. 처치 보상·고정 후보·확정·재시작 콜백은 중복 지급하지 않는다.

## 5. 좌표·도트·시간 측정 방법

### 방향키의 최우선 좌표

레퍼런스 프레임1200×540에서 실제 게임 영역 x44..1128만 잘라 얻은 **1084×540,좌상단 원점**이다. 이미 잘린 좌표에44를 다시 더하지 않는다.

| 버튼 위치 |1084×540 중심|960×540 기대 중심|640×360 기대 중심|
| --- | --- | --- | --- |
|첫째/위|(122,380)|(108.04,380.00)|(72.03,253.33)|
|둘째/왼쪽|(60,460)|(53.14,460.00)|(35.42,306.67)|

Safe Area의 좌상단 screen 위치를 `(Sx,Sy)`,크기를 `(Sw,Sh)`라 할 때 기대 중심은 `Sx + Sw*refX/1084`, `Sy + Sh*refY/540`이다. Unity `Screen.safeArea`는 아래 원점이므로 `Sy = Screen.height - safeArea.yMax`로 변환한다. 레터박스/카메라 viewport가 있으면 실제 SafeRoot와의 변환도 함께 기록한다. whole screenshot 크기를 SafeRoot 크기로 대신 쓰지 않는다.

실제 RectTransform의 투영 네 모서리로 중심과 hit 영역을 계산하고 그림/버튼/명령 이벤트를 함께 대조한다. 중심 허용 오차는 렌더 양자화 **1출력 픽셀 이내**로 기록하며 임의 배치 여유로 확대하지 않는다. 기준 v8.6 버튼78×84 논리 크기와 공격 중심(983,440),112×120은 비교용이다. 변경 시 확정 hitbox를 인계해야 하며 아이콘만 작아졌다고 클릭 영역을 축소하지 않는다.

`ui-pixel-v4.json`의 jump/back/forward 중심(148,528)/(64,652)/(268,652)은 이번 게임 조작 위치의 합격값이 아니다. 해당 파일의 뒤로 영역x12와 설계 safe x16 충돌도 새 게임에 그대로 이식하지 않고 실제 hit 영역 기준으로 판정한다.

### 아트와 UI

native 소스 크기,투명 여백/몸 bounds,PPU,pivot,scale,필터를 따로 적는다. 같은 logical pixel 단위를 유지하며 해상도 큰 생성 이미지를 실제 저해상도 sprite라고 오인하지 않는다. v4의4px 셀과 NeoDunggeunmoPro 16px 기반 정수 확대는 시안 논리 규칙이다. 모든 기기에서4물리 px로 고정하라는 뜻이 아니며,최종 Canvas/카메라 배율에서 흐림·찌그러짐·불균일 가장자리를 실제 렌더로 판단한다. 글꼴/이미지 라이선스와 최종 사용 파일 출처도 전달 manifest에 연결한다.

HP 검사는 `N=innerWidth/logicalCellWidth`, `filledCells=HP>0 ? clamp(ceil(N*HP/maxHP),1,N) : 0`에 해당하는 표시와 실제 HP를 대조한다. 셀 반올림을 HP/피해 계산에 되먹이지 않는다. HP 중심/보스 바 너비는 인계된 world→UI 대응표와 함께 확인한다.

### 시간과 증거 강도

Core 논리 시각은 경계 앞/정확/뒤에서 검사한다. 화면은 실제 timestamp/delta로 명중·상태 시작/종료 첫 표시 프레임을 기록한다. 정상60fps 기준1프레임 약16.67ms,30fps는33.33ms이며 실제 delta와 함께 해석한다. 캡처 부하가 큰 프레임을 이유로 논리 판정 허용창을 늘리지 않는다.

가속 smoke/fixture 저장/직접 PointerCommand/실제 OS 입력을 증거에 구분한다. 정적 시안·한 장 캡처·빌드 성공을 정상속도 연결/실입력 통과로 대신 쓰지 않는다.

**실입력 보류의 정확한 출처:** 2026-10-21 이 QA 채팅에서 assistant가 “실제 게임 포인터 검사 중 컴퓨터 사용 도구가 다른 사용자 입력을 감지해 동작을 중단했습니다. 약 1분간 마우스·키보드를 비워 둘 수 있는 시점을 알려 주세요.”라고 질문했고, 사용자가 `request_user_input_async` 응답으로 **“실입력 검사는 나중에 진행”**이라고 직접 답했다. 질문 call ID는 `call_7ba11f8797f443ecb9ebca8f6eb1c144`,질문 항목0이다. 같은 지시는 [2026-10-21 결과 보고서](result-20261021.md)에도 기록돼 있다. 스킬에서 추론한 승인 조건이나 도구 충돌 자체가 지속 제한의 근거인 것은 아니다.

적용 범위는 **OS 마우스·키보드를 직접 보내는 실입력 검사**다. 격리 저장·자동 테스트·직접 이벤트 기반 검사·정상속도 관측·일반 빌드/복원 검증은 이번 제작 요청에 포함돼 있어 사용자 재승인을 요구하지 않는다. 최신 제작 요청의 격리 저장/빌드 승인과 이전 실입력 보류를 구분해 적용한다. 사용자가 실입력 재개를 지시하거나 총괄이 그 최신 지시를 인계하면 별도 확인을 다시 요구하지 않는다. 현재 준비 단계에서는 총괄의 QA 시작 금지 지시도 그대로 유지한다.

2026-10-24 총괄은 위10월21일 근거를 확인하고 **이번에도 OS 실입력 보류 유지,자동 격리 검증으로 확인 가능한 범위 수행**을 명시했다. 자동 검사 결과와 보류된 실입력 범위를 분리 보고한다.

## 6. 격리 저장·후보 계약

다음은 제작 완료 인계 이후 실행할 계약이며 지금 디렉터리 생성·백업·복사·실행을 하지 않는다.

1. 인계에 소스 revision/dirty 포함 파일 목록·hash,승인 자산/프레임 manifest,씬/프리팹,생성 카탈로그,변경 스크립트,C1~C6 결정을 포함한다. 현재 제작 중 파일을 임의 시점에 섞어 테스트하지 않는다. 읽기 전용 기준본과 별도 QA 복사본을 구분하고 기존 dirty를 clean/reset하지 않는다.

4. fresh/legacy/combat/boss-pending/full-storage/corrupt-primary/corrupt-both/write-failure/resume는 프로필을 나눈다. 구 저장은 이전 QA synthetic fixture나 별도 생성 표본의 사본으로 준비하고 원본 fixture hash를 보존한다. 실제 사용자 저장을 자동 채취하지 않는다. 재실행은 해당 프로필의 사본을 사용하며 이전 결과를 덮어쓰지 않는다.
5. 바꾸기 전 설정 범위만 백업하고 종료 후 복구/대조한다. native PlayerPrefs의 실제 company/product 하위 `LastBell.*`,화면/모니터 관련 값과 Editor 대응 범위를 확인한다. 다른 앱/전체 registry를 삭제하거나 Unity 전역 설정을 덮지 않는다. 이름 변경으로 저장 위치를 새로 만드는 방식의 “초기화”는 금지한다.
6. 원본 `.json/.bak` 손상·쓰기 실패는 **격리 표본**에서만 만든다. 실패 시 저장/약속된 보상을 보존하고 정상 재시도/중복 방지를 확인한다. 알 수 없는 버전은 자동 초기화하지 않는다. 엔진 native 종료와 정상 저장 결과를 각각 기록한다.
