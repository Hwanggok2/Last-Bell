# Player-v2·HP 변경 검사 계획

최신 실행 결과는 [Dragon-v2 최종 QA 보고서](dragon-v2-result-20261024.md)를 따른다. 후보01 모션/표적11테스트와 후보02 HP30상태 검사로 요청 범위를 종료했고 DQA2-001은 해결됐다. 아래 준비/동결 문구는 계획 작성 당시 기록이다.

2026-10-24 KST. **QA 소스 동결 인계 / 실행 금지 유지 / 모든 신규 검사 NOT_RUN.** 최초에는 계획만 작성했다. 이후 총괄의 QA 소스 수정 허용에 따라 probe·launcher·관련 기존 테스트를 준비했다. 제품 Runtime·씬·프리팹·아트는 수정하지 않았으며, 컴파일·Unity/MCP·게임·테스트·빌드를 실행하지 않았다. 준비 소스는 동결하고 총괄의 최종 후보·실행 인계를 기다린다.

## 대상과 보존 계약

플레이어는 갈색 머리·붉은 스카프·초록 튜닉·작은 여행 가방·한손검의 새 모험가로 바꾼다. **기존 Last Bell 승인 모션의 포즈와 타이밍을 새 외형에 입히는 변경**이다. 총괄의 최종 원형 기준은 **32×32 캔버스, 불투명 몸높이22px,8색, recommendedIntegerScale7 → 기준 화면154px**다. 기존18~20px 목표와 앞선26px 요청 대신 이 확정값을 적용한다. 투명 캔버스 높이와 불투명 몸높이를 구분하며 최종 아트/통합 인계 전 합격으로 판정하지 않는다.

HP는 더 굵은 픽셀 테두리와 블록 채움으로 바뀐다. 위·뒤 회피, 아래 쳐내기, Space 공격과 판정·이동·저장·경제·몬스터는 유지한다. 기존 Dragon-v1 합격 기록을 새 플레이어/HP의 합격으로 재사용하지 않는다. 실제 OS 마우스·키보드 검사는 사용자의 기존 보류 지시를 유지한다.

완료 인계 후 바뀐 플레이어 모션·HP와 직접 접점만 **한 검사 묶음**으로 수행한다. 전체1~10 캠페인·전체 Core suite·정산/카드/스토리·모든 몬스터 모션을 다시 실행하지 않는다. 실패가 있으면 수정된 항목과 바로 인접한 경계만 재검사한다.

### 실제 프레임 시퀀스

- **Idle:** 진입 후2주기. 선택/강화에서 같은 아트를 쓰면 한 표본을 함께 남겨 다른 외형이나 구 후드가 나오지 않는지 확인한다.
- **Run:** 기존 처치→이동→도착의 한 전환. 이동 안에서 최소2주기와 시작/끝 Idle 연결을 포함한다. 실제 선택 actor의 Run으로 승인된400ms 주기와 실제 발 접지·몸통/가방·칼 위치를 확인한다. 이동 중 플레이어 root의 수평 X가 고정되고 프레임별 Body offset/scale 변화가 별도 흔들림을 만들지 않아야 한다. 기존 배경을 유지하며 원경/지면 진행이 멈추거나 되감기지 않는지 본다.
- **Attack:** pre-roll Idle→수락→0~120ms 첫 자세→120~200ms 준비→200ms 명중→200~500ms 후속→Idle. 기존 관련 테스트에119/120/160/200/380ms 경계를 넣었다. 실제 선택되는 승인 베기 변형이 여러 개면 각 변형을 포함한다. 작은 슬라임과 큰 보스의 두 체형에서 명중 지점이 몸에 대응하는지 확인한다. 명중1회당 피해1회, 칼이 먼저/늦게 닿는 모습, 검이 손에서 분리되는 프레임을 점검한다.
- **Up/Back:** 입력 직전→진입→접지/체공·유지→복귀→Idle을 포함한다. 최종 clip 길이와 contactFrame을 읽어 hold·후속 프레임을 확인하며 고정8프레임/hold3 가정을 쓰지 않는다. 실제 session에서 수락된 위험 방향에 맞춰 입력하고 성공 이벤트/HP와 함께 확인한다. 단순 자세 호출을 성공 회피 검사로 쓰지 않는다. 유효240ms/회복120ms/완벽90ms는 유지한다.
- **Down:** 아래 쳐내기 수락→접촉→회복→Idle. 기존 완벽 쳐내기/HP 보존/홈 좌표를 확인하고 앞 회피로 바뀌지 않았는지 본다.

**정상속도**는 렌더 프레임의 실제 delta로 session이 한 번씩 진행하는 구간이다. 이전 full의6×50ms 가속 경로, `Time.captureFramerate`로 고정한 가상 시간, 반복 manual Tick 결과를 정상속도라고 부르지 않는다. 실제 수집률·frame delta·누락을 기록하며 미달/누락은 그대로 표시한다.

렌더 프레임이 표시하지 못한 원본 포즈는 승인 source frame 접촉표로 별도 확인할 수 있다. 이 표와 원본 clip 재생은 **아트 검사**라고 표시하고 실제 게임 프레임을 대신하지 않는다. 신규 v2 수집은 짧은 구간의 CPU 이미지를 모은 후 구간 종료 때 PNG를 저장하도록 준비했다. 구간당 raw768MiB 상한을 넘으면 조용히 생략하지 않고 실패한다. 렌더 부하와 실제 프레임 간격은 여전히 측정/검토해야 한다. Idle만 전투 시계를 고정하고 실제 visual delta로2주기를 기록하며 이를 별도 clockMode로 표시한다.

### 직접 볼 시각 기준

갈색 머리·붉은 스카프·초록 튜닉·여행 가방이 프레임마다 같은 캐릭터로 유지돼야 한다. 가방/말린 담요가 생기거나 사라지지 않고, 검은 한 자루이며 손·손잡이·칼날이 연결돼야 한다. 팔/다리가 갑자기 늘거나 복제되지 않고, 앞뒤 팔 순서와 발 접지가 자연스러워야 한다. 피벗·reference height 때문에 몸 크기가 펄떡이거나 지면 아래로 내려가면 실패로 기록한다. 의도된 포즈 변화/스카프 흔들림과 복장 누락을 구분한다.

큰 색면·거친 정사각 픽셀·계단 외곽선이1280과640에서 유지돼야 한다. 확정된32×32 캔버스·불투명 몸높이22px·8색·정수7배/기준 화면154px를 최종 원본/manifest/실제 화면과 대조하고, 몬스터와의 도트 크기 차가 줄었는지 실제 나란한 화면에서 본다. 640은 기준 화면의 절반이며 정수7배는720p 기준임을 구분한다. 흐림, 불필요한 미세 점묘, 다른 크기의 도트가 섞이는 장면을 원본/실제 게임 양쪽에서 확인한다. **8프레임·고유 해시가 모두 존재하는 것만으로 시각 품질을 합격시키지 않는다.** 한 장의 멋진 정지화면으로 모션 합격을 대신하지 않는다.

### HP 표본과 판정

각 해상도에서 player·일반 적·boss 폭에 대해0, tiny(`0.000001`),25%,50%,100%를 확인한다. 총30개의 바 상태를 한정된 화면 묶음으로 남긴다. 확정 용량 `C=26/31/50`에 대해 기대 채움은0→0, tiny→1,25%→7/8/13,50%→13/16/25,100%→26/31/50이며 실제 테두리·칸 간격·끝 블록 상한을 함께 본다.

0HP 바의 모양 검사는 실제 사망 세션의 UI가 숨겨지는 동작과 구분한다. **표시용 fixture**에서는 저장된 HealthBarGraphic을 정지 상태로 직접 표본화하고, session HP를0으로 바꿔 생존/보상 규칙을 우회하지 않는다. 실제 공격/피격 구간은 presenter가 읽는 session HP와 표시값 일치를 별도로 확인한다. 새 디자인의 굵기·블록·외곽선이640에서도 식별되고, 발/이름/선반/조작 영역을 침범하지 않아야 한다.

## 증거·격리·종료 계약

- 신규 `Planning/Evidence/Dragon-v2/<candidate>`와 그 하위 save만 사용한다. 기존 Dragon-v1/candidate-01~03 기록·실제 사용자 저장·0.9.0 빌드/ZIP을 재사용하거나 덮어쓰지 않는다.
- 파일명은 candidate/해상도/scenario/clip/segment/전역 capture 번호로 구별한다. 각 캡처의 파일 경로·SHA256·frameCount·realtime·delta·session ClockMs·motion·frame index·actor 좌표·HP를 index에 연결한다. 저장 경로 중복은 오류로 처리한다.
- 캡처 전후와 구간 사이 누락/중복, 마지막 프레임 쓰기 완료, PNG 수/index 수를 대조한다. 번호가 고유하다는 이유만으로 중간 프레임 누락까지 없다고 추정하지 않는다.
- 정상속도 재생물은 기록한 시간 차이를 사용한다. frame-by-frame 검토용 원본 PNG·index도 보존하며 보간 프레임을 실제 증거에 섞지 않는다.
- PlayerPrefs는 기존 게임·화면 범위만 백업/복구/대조한다. JSON pass와 native exit를 각각 기록한다. OS 입력은 보내지 않는다.
- 최종 표에는 자동 규칙 PASS, 실제 시각 검토 PASS/FAIL, 누락/미검증, 일반 빌드 패키징/별도 실행 여부를 분리한다. 이번 단계에서는 어느 항목도 PASS가 아니다.

## 준비 결과

총괄의 후속 QA 소스 수정 허용에 따라 기존 probe의 `v2` 모드/전용 partial·launcher `-V2Only`·설정 helper의 v2 증거 경로·기존 관련 테스트 최소 수정·표적 필터를 준비했다. **컴파일·Unity/MCP·게임·테스트·빌드는 모두 NOT_RUN**이며 제품 Runtime은 수정하지 않았다. [소스 동결 인계서](dragon-player-v2-qa-source-handoff-20261024.md)와 해시를 남겼다. 총괄의 최종 아트/HP 통합·관측 후보·실행 인계 후 위 범위만 진행한다. 실제 OS 입력은 사용자의 보류 지시가 해제될 때까지 수행하지 않는다.
